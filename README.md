# 📝 [iUnoT] 통합 요구사항

> 본 문서는 서비스 범위와 주요 기능 정의를 목적으로 하며, 세부 구현 방식 및 기술 설계는 별도 문서에서 관리합니다.

---

# 1. 서비스 개요

## 1.1 서비스 목적

- 의약품 보관 환경과 재고 정보를 통합 관리하여 의약품 관리 업무의 효율성을 높이고, 환경 변화로 인한 의약품 품질 저하 및 재고 손실 위험을 줄이는 의약품 관리 서비스를 제공합니다.
- 센서 기반 환경 데이터와 의약품 재고 정보를 연계하여 보관 상태를 분석하고, 관리자가 필요한 조치를 수행할 수 있도록 지원합니다.

---

# 2. 서비스 요구사항

## 2.1 의약품 관리 요구사항

- 의약품별 재고 현황을 관리할 수 있어야 합니다.
- 의약품의 제조번호, 유통기한, 보관 위치 등의 정보를 관리할 수 있어야 합니다.
- 의약품의 입고, 출고, 폐기 등 재고 변동 이력을 추적할 수 있어야 합니다.
- 유통기한 임박 또는 재고 부족 상태를 확인할 수 있어야 합니다.
- 폐기 대상 의약품을 식별하고 관리할 수 있어야 합니다.
- 의약품별 관리 이력을 조회할 수 있어야 합니다.

---

## 2.2 환경 관리 요구사항

- 보관 공간별 환경 상태를 확인할 수 있어야 합니다.
- 온도, 습도, 문 열림 등의 환경 데이터를 수집하고 관리할 수 있어야 합니다.
- 환경 기준값을 설정하고 기준 초과 여부를 판단할 수 있어야 합니다.
- 환경 이상 발생 시 관리자가 확인할 수 있도록 알림을 제공해야 합니다.
- 환경 변화 이력을 조회할 수 있어야 합니다.
- 센서 데이터 미수신 등 환경 관리 상태 이상을 확인할 수 있어야 합니다.

---

## 2.3 IoT 데이터 관리 요구사항

- 센서를 통해 수집된 환경 데이터를 저장하고 관리할 수 있어야 합니다.
- 센서별 연결 상태 및 데이터 수집 상태를 확인할 수 있어야 합니다.
- 수집된 데이터를 기반으로 보관 환경 상태를 판단할 수 있어야 합니다.
- 데이터 수집 오류 또는 센서 장애 발생 시 이를 확인할 수 있어야 합니다.
- 환경 데이터와 저장소 및 보관 위치 정보를 연계하여 관리할 수 있어야 합니다.

---

## 2.4 환경 데이터 기반 재고 관리 요구사항

- 환경 이상 발생 정보와 의약품 보관 정보를 연계할 수 있어야 합니다.
- 환경 이상 발생 시 영향을 받을 수 있는 의약품을 식별할 수 있어야 합니다.
- 영향 가능성이 있는 의약품을 별도 관리 대상으로 분류할 수 있어야 합니다.
- 관리자의 판단에 따라 정상 복구 또는 폐기 처리할 수 있어야 합니다.
- 환경 이상과 의약품 처리 이력을 추적할 수 있어야 합니다.

---

## 2.5 사용자 및 조직 관리 요구사항

- 사용자는 조직 단위로 서비스를 이용할 수 있어야 합니다.
- 사용자는 인증 절차를 통해 서비스를 이용할 수 있어야 합니다.
- 조직 생성자는 Owner 권한을 가지며 조직을 관리할 수 있어야 합니다.
- 조직 구성원은 초대 방식으로 조직에 참여할 수 있어야 합니다.
- 조직 구성원의 업무 역할에 따라 접근 가능한 기능을 구분해야 합니다.
- 환경 관리, 재고 관리, 운영 관리 등 업무 권한을 관리할 수 있어야 합니다.
- 사용자는 자신이 속한 조직의 데이터만 조회할 수 있어야 합니다.

---

# 3. 시스템 요구사항

## 3.1 아키텍처 요구사항

- 서비스는 MSA 구조로 구성해야 합니다.
- API Gateway를 통해 외부 요청을 통합 관리해야 합니다.
- 서비스 검색을 위해 Eureka Service Discovery를 사용할 수 있어야 합니다.
- 서비스 간 독립적인 배포가 가능해야 합니다.
- 특정 서비스의 변경 및 배포가 다른 서비스에 영향을 주지 않아야 합니다.
- 외부에서는 Gateway만 접근 가능하도록 구성해야 합니다.
- 내부 서비스는 직접 외부에 노출되지 않아야 합니다.

---

## 3.2 배포 및 운영 요구사항

- 서비스는 무중단 배포가 가능해야 합니다.
- 배포 과정에서도 최소 하나 이상의 서비스 인스턴스가 정상 동작해야 합니다.
- 서비스별 독립적인 CI/CD 환경을 구성해야 합니다.
- `main` 브랜치 기준으로 자동 배포 환경을 구성해야 합니다.
- 배포 인증 정보는 안전하게 관리해야 합니다.
- 서비스 장애 발생 시 원인을 확인할 수 있도록 로그를 관리해야 합니다.
- 로그 용량 제한 및 로테이션 정책을 적용해야 합니다.

---

## 3.3 인프라 요구사항

- 서버에 설치된 공용 nginx 환경을 사용해야 합니다.
- nginx 설정은 `~/nginx/site.conf`에서 관리해야 합니다.
- nginx 설정 변경 후 직접 reload 하지 않아야 합니다.
- SSL/TLS 인증서는 Cloudflare를 통해 관리해야 합니다.
- 외부 서비스 접근은 HTTPS 환경을 제공해야 합니다.
- 서비스 포트는 할당된 범위(`10400~10419`) 내에서 사용해야 합니다.
- 서버 계정 및 지정된 로그 경로 규칙을 준수해야 합니다.

---

## 3.4 네트워크 요구사항

- 서비스 도메인은 `iunot.cloud`를 사용해야 합니다.
- 외부 요청 진입점은 nginx로 통합해야 합니다.
- Gateway를 통해 내부 서비스로 요청을 전달해야 합니다.
- 외부 접근이 필요하지 않은 서비스는 내부 네트워크에서만 접근 가능해야 합니다.
- 컨테이너 및 네트워크 이름은 `team1-` 접두어를 사용해야 합니다.

---

## 3.5 보안 요구사항

- 인증되지 않은 사용자의 서비스 접근을 제한해야 합니다.
- 사용자 권한에 따라 접근 가능한 기능을 제한해야 합니다.
- 조직 간 데이터 접근을 차단해야 합니다.
- 사용자 정보 및 서비스 데이터는 안전하게 관리해야 합니다.
- 중요 인증 정보 및 배포 키는 외부에 노출되지 않도록 관리해야 합니다.
