# 📝 2.1 조직 생성

## 기능 목적

> 사용자가 새로운 조직을 생성하고 조직의 소유자(`OWNER`)로 등록한다.

## 사용자 및 권한

- `ACTIVE` 상태의 회원

## 사전 조건

- 로그인한 사용자여야 한다.
- 회원 상태가 `ACTIVE`여야 한다.
- 현재 다른 조직에 소속되어 있지 않아야 한다.
- 진행 중(`PENDING`)인 조직 가입 요청이 없어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 조직명 | String | O | 2~30자, 중복 불가 |
| 조직 설명 | String | X | 조직에 대한 설명 |

## 처리 절차

1. 사용자 로그인 및 회원 상태를 확인한다.
2. 조직 소속 여부를 확인한다.
3. 진행 중인 가입 요청 여부를 확인한다.
4. 조직명 중복 여부를 확인한다.
5. 조직 정보를 저장한다.
6. 생성자를 `OWNER` 권한으로 등록한다.
7. 조직 상태를 `ACTIVE`로 설정한다.

## 업무 규칙

- 조직명은 필수 입력값이다.
- 조직명은 시스템 내에서 중복될 수 없다.
- 조직명은 2~30자까지 입력할 수 있다.
- 허용되지 않은 특수문자는 사용할 수 없다.
- 조직 생성자는 `OWNER` 권한을 가진다.
- 조직 생성 시 상태는 `ACTIVE`이다.

## 처리 결과

- 새로운 조직이 생성된다.
- 생성자는 `OWNER` 권한을 가진다.
- 조직 상태는 `ACTIVE`로 저장된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 로그인하지 않은 사용자 | 조직 생성을 거부한다. |
| 회원 상태가 `ACTIVE`가 아님 | 조직 생성을 거부한다. |
| 이미 조직에 소속되어 있음 | 조직 생성을 거부한다. |
| 진행 중인 가입 요청이 존재함 | 조직 생성을 거부한다. |
| 조직명이 중복됨 | 조직 생성을 거부한다. |

# 📝 2.2 조직 조회

## 기능 목적

조직 목록 및 조직 정보를 조회한다.

## 사용자 및 권한

- 로그인한 회원

## 사전 조건

- 로그인한 사용자여야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 조직 ID | Long | X | 조직 상세 조회 시 사용 |
| 조직명 | String | X | 조직 검색 시 사용 |

## 처리 절차

1. 로그인 여부를 확인한다.
2. 요청 유형(목록/상세)을 확인한다.
3. 조직 정보를 조회한다.
4. 조회 결과를 반환한다.

## 업무 규칙

- 로그인한 회원은 본인 소속 조직을 조회할 수 있다.
- 조직 가입 신청 시 `ACTIVE` 상태의 조직만 조회할 수 있다.
- `CLOSED` 상태의 조직은 가입 가능한 조직 목록에서 제외한다.
- `OWNER`는 조직 관리에 필요한 상세 정보를 조회할 수 있다.

## 처리 결과

- 조직 목록 또는 조직 상세 정보를 반환한다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 로그인하지 않은 사용자 | 조회를 거부한다. |
| 존재하지 않는 조직 | 조회를 거부한다. |

# 📝 2.4 조직 비활성화

## 기능 목적

조직 운영을 일시 중지한다.

## 사용자 및 권한

- `OWNER`

## 사전 조건

- 조직 상태가 `ACTIVE`여야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 조직 ID | Long | O | 비활성화할 조직 |

## 처리 절차

1. 사용자 권한을 확인한다.
2. 조직 상태를 확인한다.
3. 조직 상태를 `INACTIVE`로 변경한다.

## 업무 규칙

- `OWNER`만 수행할 수 있다.
- 조직 상태를 `INACTIVE`로 변경한다.
- 비활성화된 조직은 신규 가입 요청을 받을 수 없다.

## 처리 결과

- 조직 상태가 `INACTIVE`로 변경된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| `OWNER` 권한이 아님 | 수행을 거부한다. |
| 이미 `INACTIVE` 상태 | 상태를 변경하지 않는다. |

# 📝 2.6 조직 폐쇄

## 기능 목적

조직 운영을 종료한다.

## 사용자 및 권한

- `OWNER`

## 사전 조건

- 조직이 존재해야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 조직 ID | Long | O | 폐쇄할 조직 |

## 처리 절차

1. 사용자 권한을 확인한다.
2. 조직 상태를 `CLOSED`로 변경한다.
3. 모든 조직원의 소속 상태를 `REMOVED`로 변경한다.

## 업무 규칙

- `OWNER`만 수행할 수 있다.
- 조직 상태를 `CLOSED`로 변경한다.
- 모든 조직원의 소속 상태를 `REMOVED`로 변경한다.
- `CLOSED` 상태의 조직은 복구할 수 없다.

## 처리 결과

- 조직이 폐쇄된다.
- 모든 조직원이 조직에서 제외된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| `OWNER` 권한이 아님 | 수행을 거부한다. |
| 이미 `CLOSED` 상태 | 상태를 변경하지 않는다. |
