# 📝 2.1.1 조직 생성 초대 (Admin)

## 기능 목적

> 서비스 관리자가 계약된 기관의 담당자에게 조직 생성 링크를 발급한다.

## 권한
- Account Role : `ADMIN`

## 사전 조건
- 계약이 완료된 기관이어야 한다.
- 조직 생성 이력이 없는 기관이어야 한다.

## 입력값
| 항목      | 형식     |  필수 | 설명                  |
|---------|--------| :-: |---------------------|
| 담당자 이메일 | String |  O  | 조직 담당자 이메일          |
| 조직명     | String |  O  | 계약된 조직명             |
| 사업자번호   | String |  O  | 계약된 조직 사업자번호 (10자리) |


## 처리 절차

1. 계약 기관 정보를 확인한다.
2. 조직 생성용 초대 토큰(UUID)를 생성한다.
3. 초대 토큰의 만료 시간을 설정한다.
4. 초대 정보를 저장한다.
5. 조직 생성 링크를 생성한다.
6. 담당자 이메일로 조직 생성 링크를 발송한다.

## 업무 규칙

- `ADMIN`만 발급할 수 있다.
- 조직 생성 링크는 1회만 사용할 수 있다.
- 만료 시간이 지나면 사용할 수 없다.
- 조직 생성 링크는 `ORG_OWNER` 가입 전용이다.
- 하나의 조직은 최초 한 번만 생성할 수 있다.


## 처리 결과

- [ ] 조직 생성 초대 링크가 발급된다.
- [ ] 담당자에게 이메일이 발송된다.

## 예외처리
| 예외 조건         | 처리                 |
| ------------- | ------------------ |
| 이미 조직이 생성된 기관 | 조직 생성 초대를 거부한다.    |
| 이메일 발송 실패     | 발송 실패를 기록하고 재시도한다. |

# 📝 2.1.2 조직 생성

## 기능 목적

> 조직 담당자가 조직 생성 링크를 통해 회원가입과 조직 생성을 완료한다.

## 사전 조건

- 유효한 조직 생성 초대 토큰이어야 한다.
- 초대 토큰이 만료되지 않아야 한다.
- 초대 토큰이 사용되지 않은 상태여야 한다.

## 입력값

| 항목 | 형식 | 필수 | 설명                   |
|------|------|:---:|----------------------|
| 주소 | String | O | 도로명 주소, 우편 번호, 상세 주소 |
| 기관 설명 | String | X | 기관 설명                |
> 기관명은 Admin이 계약 시 등록한 정보를 사용한다.

## 처리 절차

1. 사용자가 조직 생성 초대 링크로 접속한다.
2. 시스템은 초대 토큰의 유효성을 검증한다.
3. Account를 생성한다. (Account)
4. Organization을 생성한다.
5. OrganizationMember를 생성하고 Role을 `ORG_OWNER`로 설정한다. 
6. 초대 토큰을 사용 완료 상태로 변경한다.

## 업무 규칙

- 조직 생성은 조직 생성 초대 링크를 통해서만 가능하다.
- 최초 생성자는 조직 역할(Role)이 `ORG_OWNER`로 설정된다.
- 조직명은 수정할 수 없다.
- 초대 토큰은 한 번만 사용할 수 있다.

## 처리 결과

- [ ] 새로운 Organization이 생성된다.
- [ ] 생성자는 `ORG_OWNER` 역할을 가진 OrganizationMember가 된다.
- [ ] 초대 토큰이 사용 완료 상태로 변경된다.

## 예외 처리

| 예외 조건     | 처리                 |
| --------- | ------------------ |
| 토큰 만료     | 사용할 수 없는 링크를 반환한다. |
| 이미 사용한 토큰 | 사용할 수 없는 링크를 반환한다. |
| 이메일 중복    | 이미 가입된 이메일을 반환한다.  |

# 📝 2.1.4 조직 수정

## 기능 목적

> 조직 정보를 수정한다.

## 사용자 및 권한

- Organization Role : `ORG_OWNER`

## 입력값

| 항목       | 형식      | 필수 여부 | 설명            |
|----------|---------|:-----:|---------------|
| 주소       | String  |   O   | (도로명 주소, 우편 번호) |
| 조직 설명    | String  |   X   | 조직에 대한 설명     |
> 조직명은 수정할 수 없다.

## 처리 절차

1. `ORG_OWNER` 권한을 확인한다.
2. 조직 상태를 확인한다. (ACTIVE)
3. 입력값을 검증한다.
4. 조직 정보를 수정한다.

## 업무 규칙

- `ORG_OWNER`만 수행할 수 있다.
- 조직 상태가 `ACTIVE`여야 한다.
- 주소와 설명만 수정할 수 있다.
- 수정 시 수정 일시를 갱신한다.

## 처리 결과

- [ ] 조직 정보가 수정된다.

## 예외 처리

| 예외 조건               | 처리                      |
|---------------------|-------------------------|
| `ORG_OWNER`가 아님     | 수정 권한이 없음을 반환한다.        |
| 조직 상태가 `ACTIVE`가 아님 | 수정을 거부한다.               |

# 📝 2.1.5 조직 상태 변경

## 기능 목적

> 조직의 운영 상태를 변경한다.

## 사용자 및 권한

- Organization Role : `ORG_OWNER`

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 조직 상태 | Enum | O | `ACTIVE` 또는 `INACTIVE` |

## 처리 절차

1. Owner 권한을 확인한다.
2. 조직 상태를 확인한다.
3. 요청한 상태로 변경한다.

## 업무 규칙

- `ORG_OWNER`만 수행할 수 있다.
- `ACTIVE` <-> `INACTIVE`만 변경 가능하다.
- `SUSPENDED` 상태의 조직은 상태를 변경할 수 없다.

## 처리 결과

- [ ] 조직 상태가 요청한 상태(`ACTIVE` 또는 `INACTIVE`)로 변경된다.

## 예외 처리

| 예외 조건               | 처리               |
|---------------------|------------------|
| `ORG_OWNER`가 아님     | 권한 없음을 반환한다.     |
| 조직 상태가 `CLOSED`인 경우 | 상태 변경을 거부한다.     |

# 📝 2.1.6 조직 폐쇄

## 기능 목적

> 조직 운영을 종료한다.

## 사용자 및 권한

- Organization Role : `ORG_OWNER`

## 사전 조건

- 조직이 존재해야 한다.

## 처리 절차

1. Owner 권한을 확인한다.
2. 조직 상태를 `SUSPENDED`로 변경한다. 
3. 모든 OrganizationMember 상태를 REMOVED로 변경한다.
4. 사용 가능한 초대 링크를 모두 EXPIRED로 변경한다.

## 업무 규칙

- `ORG_OWNER`만 수행할 수 있다.
- 폐쇠된 조직은 복구할 수 없다.
- 조직 데이터는 감사 및 이력 관리를 위해 보존한다. (초대 내역은 삭제해도 된다.)

## 처리 결과

- [ ] 조직 상태가 `CLOSED`로 바뀐다.
- [ ] 조직원들의 상태가 `REMOVED` 바뀐다.
- [ ] 모든 초대 링크가 만료된다.

## 예외 처리

| 예외 조건           | 처리             |
|-----------------|----------------|
| `ORG_OWNER`가 아님 | 권한 없음을 반환한다.   |
| 이미 `CLOSED` 상태  | 폐쇄된 조직임을 반환한다. |
