# 📝 2.3.1 조직 탈퇴

## 기능 목적

> 조직원이 현재 소속된 조직에서 탈퇴한다.

## 사전 조건

- 로그인한 사용자여야 한다.
- 조직에 소속되어 있어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 조직 ID | Long | O | 탈퇴할 조직 |

## 처리 절차

1. 로그인 여부를 확인한다.
2. 조직 소속 여부를 확인한다.
3. 사용자 Role을 확인한다.
4. 조직 소속 상태를 `LEFT`로 변경한다.

## 업무 규칙

- `MEMBER`는 직접 탈퇴할 수 있다.
- `OWNER`는 다른 `OWNER`가 존재하는 경우에만 탈퇴할 수 있다.
- 조직에는 항상 1명 이상의 `OWNER`가 존재해야 한다.
- 탈퇴 시 조직 소속 상태를 `LEFT`로 변경한다.

## 처리 결과

- [ ] 멤버가 조직에서 탈퇴된다.
- [ ] 조직 소속 상태가 `LEFT`로 변경된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 조직에 소속되어 있지 않음 | 탈퇴를 거부한다. |
| 마지막 `OWNER`가 탈퇴를 요청함 | 탈퇴를 거부한다. |

# 📝 2.3.2 조직원 강제 제외

## 기능 목적

> 조직 관리자가 조직원을 강제로 제외한다.

## 사용자 및 권한

- `OWNER`

## 사전 조건

- 대상 사용자가 조직에 소속되어 있어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 조직원 ID | Long | O | 제외할 조직원 |

## 처리 절차

1. 사용자 Role을 확인한다.
2. 대상 조직원을 조회한다.
3. 조직 소속 상태를 `REMOVED`로 변경한다.

## 업무 규칙

- `OWNER`만 수행할 수 있다.
- 마지막 `OWNER`는 조직에서 제외할 수 없다.
- 조직에는 항상 1명 이상의 `OWNER`가 존재해야 한다.
- 조직 소속 상태를 `REMOVED`로 변경한다.

## 처리 결과

- [ ] 조직원이 조직에서 제외된다.
- [ ] 조직원의 조직 소속 상태가 `REMOVED`로 변경된다.

## 예외 처리

| 예외 조건 | 처리                  |
| --- |---------------------|
| `OWNER` 권한이 아님 | 권한 없음을 반환한다.        |
| 대상 사용자가 조직원이 아님 | 조직원을 찾을 수 없음을 반환한다. |
| 조직에 `OWNER`가 존재하지 않게 되는 경우 | 제외를 거부한다. |

# 📝 2.3.3 역할 관리

## 기능 목적

> 조직원의 역할(Role)을 관리한다.

## 사전 조건
- 대상 사용자가 조직원이어야 한다.

## 입력값

| 항목       | 형식   | 필수 여부 | 설명                |
| -------- | ---- | :---: | ----------------- |
| 조직원 ID   | Long |   O   | 역할을 변경할 조직원       |
| 역할(Role) | Enum |   O   | `OWNER`, `MEMBER` |


## 처리 절차

1. 사용자 Role을 확인한다.
2. 대상 조직원을 조회한다.
3. 역할 변경 가능 여부를 확인한다.
4. 역할을 변경한다.

## 업무 규칙

- 조직 생성 시 생성자는 `OWNER` 역할을 가진다. 
- 가입 승인 시 가입자는 `MEMBER` 역할을 가진다. 
- `OWNER`는 다른 조직원을 `OWNER` 또는 `MEMBER`로 변경할 수 있다. 
- 하나의 조직에는 여러 명의 `OWNER`가 존재할 수 있다. 
- 하나의 조직에는 최소 1명의 `OWNER`가 존재해야 한다. 
- 마지막 OWNER는 MEMBER로 변경하거나 조직에서 제외할 수 없다.

## 처리 결과

- [ ] 조직원의 역할이 변경된다.

## 예외 처리

| 예외 조건                 | 처리                  |
| --------------------- | ------------------- |
| `OWNER` 권한이 아님        | 권한 없음을 반환한다.        |
| 대상 사용자가 조직원이 아님       | 조직원을 찾을 수 없음을 반환한다. |
| 마지막 `OWNER`를 변경하려는 경우 | 역할 변경을 거부한다.        |

# 📝 2.3.4 업무 권한 관리

## 기능 목적

> 조직원의 업무 권한을 관리한다.

## 사용자 및 권한

- `OWNER`

## 사전 조건

- 대상 사용자가 조직원이어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명                                         |
| --- | --- | :---: |--------------------------------------------|
| 조직원 ID | Long | O | 권한을 변경할 조직원                                |
| 업무 권한 | Enum | O | `INVENTORY_MANAGE`, `ENVIRONMENT_MANAGE`, `OPERATION_MANAGE` |

## 처리 절차

1. 사용자 권한을 확인한다.
2. 대상 조직원을 조회한다.
3. 업무 권한을 부여하거나 회수한다.

## 업무 규칙

- `OWNER`만 수행할 수 있다.
- `MEMBER`에게만 업무 권한을 부여할 수 있다.
- 업무 권한은 부여 및 회수할 수 있다.

## 처리 결과

- [ ] 조직원의 업무 권한이 변경된다.

## 예외 처리

| 예외 조건 | 처리                  |
| --- |---------------------|
| `OWNER` 권한이 아님 | 권한이 없음을 반환한다.       |
| 대상 사용자가 조직원이 아님 | 조직원을 찾을 수 없음을 반환한다. |
