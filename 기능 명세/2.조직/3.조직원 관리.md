# 📝 2.3.1 권한/부서 대기 조직원 조회

## 기능 목적

> 회원가입을 완료했지만 아직 Department, Permission이 부여되지 않은 조직원을 조회한다.

## 사용자 및 권한

- Organization Role : `ORG_OWNER`

## 처리 절차

1. 승인 여부가 `False`인 조직원을 조회한다.
2. 조회 결과를 반환한다.

## 업무 규칙

- `ORG_OWNER`만 조회할 수 있다.
- 자신의 조직에 소속된 조직원만 조회할 수 있다.
- 승인 여부가 `False`인 조직원만 조회한다.
- 조직원의 이름, 이메일, 가입일을 조회할 수 있다.

## 처리 결과

- [ ] 권한/부서 대기 조직원 목록을 반환한다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| `ORG_OWNER` 권한이 아님 | 권한 없음을 반환한다. |

# 📝 2.3.2 조직원 승인

## 기능 목적

> 가입을 완료한 조직원에게 Role, Department, Permission을 부여하여 조직 활동을 시작할 수 있도록 한다.

## 사용자 및 권한

- Organization Role : `ORG_OWNER`

## 사전 조건

- 대상 사용자가 조직에 소속되어 있어야 한다.
- 대상 조직원의 승인 상태가 `False` 여야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 조직원 ID | Long | O | 등록할 조직원 |
| 역할(Role) | Enum | O | `OWNER`, `MEMBER` |
| 부서(Department) | Long | O | 소속 부서 |
| 업무 권한(Permission) | Enum | O | `INVENTORY_MANAGE`, `ENVIRONMENT_MANAGE`, `OPERATION_MANAGE` |

## 처리 절차

1. 사용자 Role을 확인한다.
2. 대상 조직원을 조회한다.
3. 역할(Role)을 부여한다. (default : `ORG_MEMBER`)
4. 부서(Department)를 지정한다.
5. 업무 권한(Permission)을 부여한다.
6. 조직원 승인 여부를 `FALSE`로 변경한다.

# 📝 2.3.3 멤버 조회

## 기능 목적

> 조직에서 활동 중인 조직원을 조회하고 관리한다.

## 사용자 및 권한

- Organization Role : `ORG_OWNER`

## 처리 절차

1. 로그인 여부를 확인한다.
2. 사용자 Role을 확인한다.
3. 조직 소속 여부를 확인한다.
4. 승인 상태가 `True`인 조직원을 조회한다.
5. 조회 결과를 반환한다.

## 업무 규칙

- `ORG_OWNER`만 조회할 수 있다.
- 자신의 조직원만 조회할 수 있다.
- 승인 상태가 `True`인 조직원만 조회한다.
- 조직원의 이름, 이메일, 역할, 부서, 업무 권한 조회할 수 있다.

## 처리 결과

- [ ] 조직원 목록 또는 상세 정보를 반환한다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| `ORG_OWNER` 권한이 아님 | 권한 없음을 반환한다. |
| 조직에 소속되어 있지 않음 | 조회를 거부한다. |

# 📝 2.3.4 조직 탈퇴

## 기능 목적

> 조직원이 현재 소속된 조직에서 탈퇴한다.

## 사전 조건

- 조직에 소속되어 있어야 한다.
- 조직원 승인 여부가 `True` 여야 한다.

## 처리 절차

1. 로그인 여부를 확인한다.
2. 조직 소속 여부를 확인한다.
3. 사용자 Role을 확인한다.
4. 조직원 정보를 삭제한다.

## 업무 규칙

- `MEMBER`는 직접 탈퇴할 수 있다.
- `OWNER`는 다른 `OWNER`가 존재하는 경우에만 탈퇴할 수 있다.
- 조직에는 항상 1명 이상의 `OWNER`가 존재해야 한다.
- 탈퇴 시 조직원의 정보를 삭제한다.

## 처리 결과

- [ ] 멤버가 조직에서 탈퇴된다.
- [ ] 조직원의 정보가 삭제되었다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 조직에 소속되어 있지 않음 | 탈퇴를 거부한다. |
| 마지막 `OWNER`가 탈퇴를 요청함 | 탈퇴 불가를 반환한다. |

# 📝 2.3.5 조직원 강제 제외

## 기능 목적

> 조직 관리자가 조직원을 강제로 제외한다.

## 사용자 및 권한

- Organization Role : `ORG_OWNER`

## 사전 조건

- 대상 사용자가 조직에 소속되어 있어야 한다.
- 대상 조직원의 승인 상태가 `Thrue`여야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 조직원 ID | Long | O | 제외할 조직원 |

## 처리 절차

1. 사용자 Role을 확인한다.
2. 대상 조직원을 조회한다.
3. 조직 소속 상태를 `REMOVED`로 변경한다.

## 업무 규칙

- `ORG_OWNER`만 수행할 수 있다.
- 마지막 `OWNER`는 조직에서 제외할 수 없다.
- 조직에는 항상 1명 이상의 `OWNER`가 존재해야 한다.

## 처리 결과

- [ ] 조직원이 조직에서 제외된다.
- [ ] 조직원 정보가 삭제된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| `ORG_OWNER` 권한이 아님 | 권한 없음을 반환한다. |
| 대상 사용자가 조직원이 아님 | 조직원을 찾을 수 없음을 반환한다. |
| 조직에 `OWNER`가 존재하지 않게 되는 경우 | 제외 불가를 반환한다. |

# 📝 2.3.6 역할 관리

## 기능 목적

> 활동 중인 조직원의 역할(Role)을 변경한다.

## 사용자 및 권한

- Organization Role : `ORG_OWNER`

## 사전 조건

- 대상 사용자가 조직원이어야 한다.
- 대상 조직원의 승인 여부가 `True`여야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명                        |
| --- | --- | :---: |---------------------------|
| 조직원 ID | Long | O | 역할을 변경할 조직원               |
| 역할(Role) | Enum | O | `ORG_OWNER`, `ORG_MEMBER` |

## 처리 절차

1. 사용자 Role을 확인한다.
2. 대상 조직원을 조회한다.
3. 역할 변경 가능 여부를 확인한다.
4. 역할을 변경한다.

## 업무 규칙

- `ORG_OWNER`만 수행할 수 있다.
- `OWNER`는 다른 조직원을 `OWNER` 또는 `MEMBER`로 변경할 수 있다.
- 하나의 조직에는 여러 명의 `OWNER`가 존재할 수 있다.
- 하나의 조직에는 최소 1명의 `OWNER`가 존재해야 한다.
- 마지막 `OWNER`는 `MEMBER`로 변경할 수 없다.

## 처리 결과

- [ ] 조직원의 Role이 변경된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| `ORG_OWNER` 권한이 아님 | 권한 없음을 반환한다. |
| 대상 사용자가 조직원이 아님 | 조직원을 찾을 수 없음을 반환한다. |
| 마지막 `OWNER`를 변경하려는 경우 | 마지막 `OWNER`임을 반환한다. |
| 같은 역할로 변경 | 동일한 역할임을 반환한다. |
