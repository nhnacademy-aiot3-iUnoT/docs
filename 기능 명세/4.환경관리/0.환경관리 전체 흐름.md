# 📝 4.0 환경관리 전체 흐름

## 전체 구조

![환경관리 룰엔진 Flow](./flowEngine.png)

환경관리 룰엔진은 실제 센서 발행 Flow, 가상 센서 발행 Flow, 구역별 환경 처리 Flow로 구성한다.

| Flow | 생성 기준 | 주요 Node | 책임 |
| --- | --- | --- | --- |
| `ExternalSensorFlow` | 시스템 전체 1개 | `ExternalMqttSubscriberNode` → `SensorTransformNode` → `InternalMqttPublisherNode` | 외부 MQTT 구독, 실제 센서 데이터 변환, 내부 MQTT 발행 |
| `VirtualSensorFlow-{sectionId}` | 가상 센서가 활성화된 구역별 1개 | `VirtualSensorGeneratorNode` → `InternalMqttPublisherNode` | 구역별 가상 센서 데이터 생성, 내부 MQTT 발행 |
| `SectionEnvironmentFlow-{sectionId}` | 활성 구역별 1개 | `InternalMqttSubscriberNode` → `SensorPayloadValidationNode` → `InfluxDbSaveNode` → `RuleEvaluationNode` → `StateDecisionNode` → `EventCreationNode` → `AlarmNode` | 구역별 센서 데이터 구독, 검증, 저장, 룰 검사, 상태 판단, 이벤트 및 알림 처리 |

## 처리 흐름

1. `ExternalSensorFlow`가 외부 MQTT에서 실제 센서 데이터를 수신한다.
2. `SensorTransformNode`가 수신한 데이터를 센서 종류별 `SensorPayloadDto`로 변환한다.
3. `VirtualSensorFlow-{sectionId}`는 설정된 주기와 정책에 따라 표준 가상 센서 데이터를 생성한다.
4. 실제 센서와 가상 센서 데이터를 동일한 토픽 규칙으로 내부 MQTT Broker에 발행한다.
5. `SectionEnvironmentFlow-{sectionId}`가 `iot/+/+/{sectionId}/#` 토픽을 구독해 해당 구역의 데이터만 수신한다.
6. 수신한 데이터를 검증하고 InfluxDB에 저장한다.
7. 구역별 룰을 검사하고 `NORMAL → PENDING → ALERT` 상태를 판단한다.
8. `ALERT` 상태면 이상 이벤트를 생성하고 메신저 알림을 전송한다.

## 공통 원칙

- `LocationResolveNode`는 사용하지 않는다.
- 실제 센서와 가상 센서는 동일한 `SensorPayloadDto`와 내부 MQTT 토픽 규칙을 사용한다.
- `sectionId`는 구역별 Flow ID, MQTT 토픽, InfluxDB Tag, 룰 및 이상 상태 관리의 기준이다.
- `SectionEnvironmentFlow-{sectionId}`는 자신의 `sectionId`에 해당하는 데이터만 처리한다.
- 한 구역 Flow의 오류가 다른 구역 Flow의 처리를 중단시키지 않는다.
