# 📝 4.4 환경 이벤트 및 알림 관리

## 기능 목적

> 환경 룰 판단 결과에 따라 이상·상태 변경·복구 이벤트를 생성하고 메신저 알림 시스템에 전달한다.


## 사용자 및 권한

- 환경관리 룰엔진 시스템
- 환경 알림 수신 대상으로 등록된 조직 관리자 및 조직원
- 메신저 알림 시스템


## 사전 조건

- 환경 룰 판단 결과가 확정되어 있어야 한다.
- 위치별 룰의 알림 활성화 여부가 설정되어 있어야 한다.
- 알림 대상과 메신저 연동 정보가 등록되어 있어야 한다.


## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 이벤트 유형 | String | O | 임계값 이상, 복구, 문열림, 문닫힘, 미수신, 통신 복구 등 |
| 병원명 | String | O | 이벤트 발생 병원 |
| 위치 ID 및 위치명 | Long, String | O | 이벤트 발생 위치 |
| 센서·장치 정보 | Object | O | 센서 종류, 장치명 및 장치 식별자 |
| 이전·현재 상태 | String | O | 상태 변화 내용 |
| 발생 시간 | DateTime | O | 상태가 발생하거나 변경된 시각 |
| 실제·가상 여부 | Boolean | O | 가상 센서 데이터 여부 |

## 처리 절차

1. 룰 판단 결과가 새로운 상태 변화인지 확인한다.
2. 이벤트 유형과 위치, 센서, 장치 및 상태 정보를 조합해 환경 이벤트를 생성한다.
3. 동일 상태의 기존 이벤트와 마지막 알림 시간을 확인한다.
4. 알림 활성화 여부와 재알림 간격을 적용한다.
5. 발행 가능한 이벤트를 메신저 알림 시스템으로 전달한다.
6. 이벤트 및 알림 발행 결과를 기록한다.

## 업무 규칙

- 임계값 이상이 지속시간을 충족했을 때만 이상 이벤트를 생성해야 한다.
- 이상 상태에서 정상으로 돌아오면 정상 복구 이벤트를 생성해야 한다.
- 문 상태가 `CLOSED → OPEN`이면 `DOOR_OPENED`, `OPEN → CLOSED`이면 `DOOR_CLOSED` 이벤트를 생성해야 한다.
- 센서 미수신 상태가 최초 확정되면 미수신 이벤트를 생성해야 한다.
- 미수신 이후 데이터가 다시 들어오면 통신 복구 이벤트를 생성해야 한다.
- 동일 상태에 대한 중복 이벤트를 생성하지 않아야 한다.
- 재알림이 설정된 경우 지정 간격이 지난 뒤에만 알림을 다시 발행해야 한다.
- 룰이 비활성화되거나 알림이 비활성화된 경우 메신저 알림을 발행하지 않아야 한다.
- 이벤트에는 병원명, 위치, 장치, 센서, 상태, 발생 시간 및 가상 센서 여부가 포함되어야 한다.


## 처리 결과

- 환경 이상 및 정상 복구 이력이 이벤트로 생성된다.
- 알림 조건을 충족한 이벤트가 메신저 알림 시스템으로 전달된다.
- 중복 이벤트와 불필요한 반복 알림이 방지된다.


## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 필수 이벤트 정보가 누락됨 | 이벤트를 발행하지 않고 오류 로그를 남긴다. |
| 동일 상태 이벤트가 이미 처리됨 | 중복 이벤트와 알림을 생성하지 않는다. |
| 알림이 비활성화됨 | 이벤트 상태만 관리하고 메신저 알림은 발행하지 않는다. |
| 메신저 이벤트 발행 실패 | 이벤트와 실패 원인을 기록하며 위치별 Flow는 계속 처리한다. |
