# 📝 4.5 환경 이벤트 및 알림 관리

## 기능 목적

> `SectionEnvironmentFlow-{sectionId}`의 `EventCreationNode`가 `ALERT` 상태의 이상 이벤트를 생성하고, `AlarmNode`가 이를 메신저 알림으로 전송한다.

## 사용자 및 권한

- 환경관리 룰엔진 시스템
- 환경 알림 수신 대상으로 등록된 조직 관리자 및 조직원
- 메신저 알림 시스템

## 사전 조건

- `StateDecisionNode`가 해당 센서 상태를 `ALERT`로 판단했어야 한다.
- 해당 `SectionEnvironmentFlow-{sectionId}`의 구독, 검증, 저장, 룰 검사, 판단 단계가 정상 완료되어야 한다.
- 알림 활성화 여부와 수신 대상이 설정되어 있어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 알림 대상 데이터 | Object | O | `StateDecisionNode`가 전달한 `ALERT` 데이터 |
| 구역·센서·장치 정보 | Object | O | `organizationId`, `storageId`, `sectionId`, 센서 종류, `deviceEui` |
| 측정값·임계값·지속 시간 | Object | O | 발생한 측정값, 적용 임계값, 이탈 지속 시간 |
| 발생 시각 | DateTime | O | 임계값 이탈 시작 또는 알림 확정 시각 |
| 알림 설정 | Object | O | 알림 활성화 여부, 수신 대상, 재알림 간격 |

## 처리 절차

1. `EventCreationNode`가 `ALERT` 데이터로 구역·센서·장치·임계값 정보를 포함한 이상 이벤트를 생성한다.
2. 생성된 이벤트를 같은 Flow의 `AlarmNode`로 전달한다.
3. `AlarmNode`가 알림 활성화 여부와 수신 대상을 확인한다.
4. 동일한 이탈 상태의 중복 알림과 재알림 간격을 확인한다.
5. 전송 조건을 충족한 알림을 메신저 알림 시스템에 전송한다.
6. 이벤트 및 알림 전송 결과를 기록한다.

## 업무 규칙

- `EventCreationNode`와 `AlarmNode`는 해당 `SectionEnvironmentFlow-{sectionId}` 내부에 위치해야 한다.
- `PENDING`은 이벤트와 알림을 생성하지 않는다.
- 동일한 이탈 상태에 대한 알림은 중복 전송하지 않아야 한다.
- 재알림은 지정된 간격이 지난 후에만 전송한다.
- 알림이 비활성화된 경우 메신저 알림을 전송하지 않는다.

## 처리 결과

- [ ] `ALERT` 상태가 구역별 이상 이벤트로 생성된다.
- [ ] 알림 설정과 중복 정책을 충족한 알림만 메신저 시스템에 전송된다.
- [ ] 하나의 구역 알림 실패가 다른 구역 Flow에 영향을 주지 않는다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 이벤트 필수 데이터 누락 | 이벤트와 알림을 생성하지 않고 누락 항목을 기록한다. |
| 알림이 비활성화됨 | 메신저 알림을 전송하지 않고 처리 결과를 기록한다. |
| 메신저 알림 전송 실패 | `sectionId`와 실패 원인을 기록하고 다른 구역 Flow의 처리는 계속한다. |
