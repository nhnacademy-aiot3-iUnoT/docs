# 📝 4.2 내부 센서 데이터 수신 및 위치별 분배

## 기능 목적

> 내부 MQTT에 발행된 표준 센서 데이터를 한 번만 수신·검증하고, `locationId`를 기준으로 해당 위치의 `LocationRuleFlow`에 분배한다.

## 사용자 및 권한

- 환경관리 룰엔진 시스템
- 내부 MQTT 브로커
- 실제 센서 데이터 발행 Flow
- 가상 센서 데이터 발행 Flow

## 사전 조건

- `InternalMqttSubscriberFlow`가 실행 중이어야 한다.
- 내부 MQTT의 `iot/#` 토픽을 구독할 수 있어야 한다.
- 활성 위치별 `LocationRuleFlow-{locationId}`가 생성되어 있어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `applicationName` | String | O | 병원 또는 캠퍼스명 |
| `locationId` | Long | O | 위치별 Flow 분배 기준 |
| `location` | String | O | 센서 설치 위치명 |
| `deviceName`, `deviceEui` | String | O | 장치 이름과 고유 식별자 |
| `sensorType`, `value`, `unit` | String, Number, String | O | 표준 센서 종류, 측정값, 단위 |
| `time` | String | O | ISO 8601 형식의 측정 시각 |

## 처리 절차

1. `InternalMqttSubscriberFlow`가 내부 MQTT의 `iot/#` 토픽을 구독한다.
2. 수신한 JSON 메시지를 `SensorPayloadDto`로 변환한다.
3. `SensorPayloadValidationNode`가 위치, 장치, 센서 종류, 측정값, 단위, 측정 시각 등 필수 항목을 검증한다.
4. `LocationRouterNode`가 `locationId`를 추출한다.
5. `locationId`에 일치하는 `LocationRuleFlow-{locationId}`로 메시지를 전달한다.

## 업무 규칙

- 내부 MQTT 구독 Flow는 시스템 전체에 하나만 실행해야 한다.
- 위치별로 MQTT Subscriber를 별도 생성하지 않아야 한다.
- `LocationRouterNode`는 데이터 저장, 룰 판단, 이벤트 생성을 수행하지 않아야 한다.
- 모든 표준 센서 데이터는 동일한 검증·분배 절차를 거쳐야 한다.
- 분배 대상 Flow가 없으면 데이터를 저장하거나 다음 단계로 전달하지 않아야 한다.

## 처리 결과

- [ ] 표준 센서 데이터가 하나의 공통 Subscriber Flow에서 수신된다.
- [ ] 유효한 표준 센서 데이터가 위치별 `LocationRuleFlow`에만 전달된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| JSON 변환 실패 | 메시지를 제외하고 토픽과 실패 원인을 기록한다. |
| 필수 데이터 누락 | 메시지를 제외하고 누락 항목을 기록한다. |
| `locationId`가 없음 | 분배하지 않고 장치 정보와 실패 사유를 기록한다. |
| 분배 대상 Flow가 없음 | 저장·룰 판단으로 전달하지 않고 `locationId`를 기록한다. |
