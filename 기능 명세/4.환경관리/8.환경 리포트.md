# 📝 4.8 환경 리포트 (하루 요약)

## 기능 목적

> 원본 센서 데이터의 보관 기간이 짧으므로, 매일 자정 직후에 어제치 환경 요약을 계산해 별도 요약 버킷에 적재하고 기간 단위로 조회할 수 있게 한다.

숫자는 InfluxDB와 이 계층에서 전부 확정한다. 평균·이탈 비율 같은 계산을 뒤쪽(AI 설명 등)에 맡기면 그럴듯한 오답이 나오므로, 요약은 그 자체로 완결된 결과물이어야 한다.

## 구성 요소

| 클래스 | 역할 |
| --- | --- |
| `DailyThresholdStatNode` | 룰 판단 시점에 임계값 이탈 여부를 Redis로 하루 단위 집계 (4.3 참고) |
| `SensorDailyStatRedisRepository` | `rule-engine:sensor-daily-stat:{zoneId}:{date}` Hash 읽기·쓰기, TTL 3일 |
| `ZoneDailySummaryService` | 구역 하나의 하루 요약 계산 |
| `StorageDailySummaryArchiveService` | 저장소 단위 적재·조회 |
| `DailySummaryInfluxRepository` | 요약 버킷 저장·조회 |
| `DailySummaryRollupScheduler` | 매일 배치 실행 |
| `EnvironmentReportController` | 조회·수동 적재 API |

## 하루의 경계

하루 경계는 `Asia/Seoul`(`ZoneDailySummary.REPORT_ZONE`) 기준이다. 계산할 때와 저장·조회할 때의 경계가 어긋나면 하루가 통째로 밀리므로 기준을 한 곳에 모아 두었다.

## 요약 데이터

### 구역 요약 (`ZoneDailySummary`)

| 항목 | 설명 |
| --- | --- |
| `zoneId` | 구역 ID |
| `sensorStats` | 센서 타입별 통계 목록 |
| `door` | 문 개폐 통계. 문 센서가 없거나 기록이 없으면 `null` |

`door`를 0회로 채우지 않는 이유는 "문이 안 열렸다"와 "문 센서가 없다"를 구분하기 위해서다.

### 센서 통계 (`SensorDailyStat`)

| 항목 | 설명 |
| --- | --- |
| `sensorType`, `unit` | 센서 종류와 단위 |
| `avg`, `min`, `max` | 그날 측정값의 평균·최소·최대 |
| `thresholdMin`, `thresholdMax` | 그날 판단에 쓰인 임계값. 없거나 한쪽만 설정되면 `null` |
| `outOfRangeRatio` | 임계 범위를 벗어난 측정 비율(0.0~1.0). 임계값이 없거나 표본이 없으면 `null` |
| `previousDayAvg` | 전일 평균. 전일 데이터가 없으면 `null` |

임계값과 이탈 비율은 **그날 판단 시점에 Redis로 모아 둔 값**에서 온다. 통계가 없는 날은 두 값을 비운다. 지금 임계값을 끌어와 채우면, 그날 알림이 나갔는데도 이탈이 없었던 것처럼 보이는 틀린 요약이 만들어지기 때문이다.

### 문 통계 (`DoorDailyStat`)

| 항목 | 설명 |
| --- | --- |
| `openCount` | 닫힘 → 열림으로 바뀐 횟수 |
| `openMinutes` | 누적 열림 시간(분). 마지막 열림 구간은 그날 끝까지로 계산 |

## 처리 절차

1. `DailySummaryRollupScheduler`가 `rule-engine.daily-rollup.cron`(기본 `0 10 0 * * *`, Asia/Seoul)에 어제 날짜로 실행한다.
2. `StorageDailySummaryArchiveService.rollup(date)`가 그날 데이터가 들어온 모든 저장소 ID를 InfluxDB에서 찾는다.
3. 저장소마다 그날 데이터가 있던 구역 ID를 찾아 `ZoneDailySummaryService.summarize(zoneId, date)`를 호출한다.
4. 구역 요약은 InfluxDB 일별 집계(평균·최소·최대), Redis 임계값 통계, 전일 평균, 문 이력을 합쳐 만든다.
5. 전일 평균은 먼저 저장된 전일 요약에서 찾고, 없으면 원본에서 다시 집계한다. 둘 다 실패하면 비교 없이 요약한다.
6. `DailySummaryInfluxRepository.save()`가 요약 버킷에 지점을 기록한다.
7. 구역 하나가 실패하면 그 구역만 빠지고, 저장소 하나가 실패하면 그 저장소만 건너뛴다. 적재한 구역 수를 로그와 응답으로 남긴다.

## 요약 버킷 저장 구조

| 구분 | 항목 |
| --- | --- |
| Bucket | `influx-db.summary-bucket` (기본 `sensor-daily`) |
| Measurement | `zone_daily_summary` |
| Tag | `storage_id`, `zone_id`, `sensor_type`, `unit` |
| Field(센서) | `avg`, `min`, `max`, `threshold_min`, `threshold_max`, `out_of_range_ratio`, `previous_day_avg` |
| Field(문) | `open_count`, `open_minutes` |
| Timestamp | 대상 날짜의 `Asia/Seoul` 자정 |

같은 태그·시각의 지점을 덮어쓰므로 적재는 멱등하다. 그래서 배치에 인스턴스 간 Lock을 두지 않았다(4.7 참고).

## API

인벤토리가 환경 리포트를 만들 때 호출하는 서버 간 경로라 사용자 인증을 요구하지 않는다.

| Method | 경로 | 설명 |
| --- | --- | --- |
| GET | `/api/rule-engine/internal/storages/{storage-id}/daily-summaries?from=&to=` | 저장소의 하루 요약을 기간으로 조회. 기본은 어제까지의 최근 7일 |
| POST | `/api/rule-engine/internal/daily-summary-rollups?date=` | 하루 요약 적재 수동 실행. `date` 생략 시 어제 (테스트·복구용) |
| GET | `/api/rule-engine/internal/storages/{storage-id}/sensor-data/latest?organizationId=` | 저장소의 구역별 센서 최신값 (4.2 참고) |

- `from`/`to`는 `yyyy-MM-dd` 형식이다. `to`만 생략하면 어제, `from`만 생략하면 `to` 기준 최근 7일이다.
- 적재되지 않은 날짜는 결과에서 빠지므로 반환 개수가 요청한 일수보다 적을 수 있다.
- `from`이 `to`보다 늦으면 `IllegalArgumentException`으로 거부한다.

## 완료 기준

- [x] 임계값 판단 결과가 판단 시점에 하루 단위로 집계된다.
- [x] 매일 어제치 요약이 요약 버킷에 자동 적재된다.
- [x] 구역별 평균·최소·최대·임계값·이탈 비율·전일 대비 평균을 제공한다.
- [x] 문 개폐 횟수와 누적 열림 시간을 제공한다.
- [x] 저장소 기간 조회 API를 제공한다.
- [x] 수동 적재 API로 실패한 날짜를 원본 보관 기간 안에 복구할 수 있다.
- [x] 적재가 멱등해 인스턴스가 여러 대여도 결과가 같다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 그날 데이터가 있는 저장소 없음 | 경고 로그를 남기고 0건으로 종료한다. |
| 저장소 요약 실패 | 해당 저장소만 건너뛰고 나머지를 적재한다. |
| 구역 요약 계산 실패 | 해당 구역만 빼고 저장소 요약을 만든다. |
| 전일 요약·원본 조회 실패 | 전일 대비 비교 없이 요약한다. |
| 수집된 데이터가 없는 저장소 | 저장하지 않고 로그만 남긴다. |
| 스케줄러 실행 중 예외 | 스케줄러 밖으로 나가면 로그 없이 사라지므로 반드시 잡아서 기록한다. |
| 조회 시작일 > 종료일 | `IllegalArgumentException`으로 거부한다. |
