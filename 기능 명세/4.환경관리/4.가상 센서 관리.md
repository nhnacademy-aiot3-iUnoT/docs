# 📝 4.4 가상 센서 관리

## 기능 목적

> 위치별 설정에 따라 가상 센서 데이터를 생성하고, 표준 형식으로 내부 MQTT에 발행한다.

## 사용자 및 권한

- 가상 센서 관리 권한을 가진 조직 관리자
- 환경관리 룰엔진 시스템

## 사전 조건

- 위치, 장치, 가상 센서 설정이 등록되어 있어야 한다.
- 내부 MQTT 브로커와 단일 `EnvironmentProcessingFlow`가 실행 중이어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 위치 정보 | Object | O | `applicationName`, `locationId`, `location` |
| 가상 장치 정보 | Object | O | `deviceName`, `deviceEui` |
| 생성 주기 | Duration | O | 데이터 생성 간격 |
| 센서 종류 및 값 정책 | Object | O | 온도·습도 범위, 이상값 확률, 문 열림 확률 |
| Flow 활성화 여부 | Boolean | O | 가상 데이터 생성 여부 |

## 처리 절차

1. 가상 센서 설정을 검증한다.
2. 위치별 `VirtualSensorFlow-{locationId}`를 생성하고 시작한다.
3. 설정된 주기와 생성 정책에 따라 센서 종류별 측정값을 생성한다.
4. 위치·장치 정보를 포함한 표준 센서 데이터를 생성한다.
5. `iot/{applicationName}/{location}/{deviceName}/{sensorType}` 토픽으로 내부 MQTT에 발행한다.

## 업무 규칙

- 가상 센서 Flow는 위치당 하나만 운영한다.
- 가상 센서는 InfluxDB 저장, 룰 판단, 이벤트 생성, 알림 전송을 직접 수행하지 않아야 한다.
- 가상 센서 데이터는 반드시 4.2의 단일 `EnvironmentProcessingFlow`가 구독해야 한다.
- 위치의 `locationId`는 Flow 생성 시 주입하고, 매 메시지마다 장소 관리 서비스를 조회하지 않아야 한다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 위치 또는 센서 설정 누락 | Flow를 생성하지 않고 경고 로그를 남긴다. |
| 설정값이 유효하지 않음 | Flow 시작을 거부하고 검증 오류를 반환한다. |
| 내부 MQTT 발행 실패 | 오류를 기록하고 다음 생성 주기의 처리를 계속한다. |
