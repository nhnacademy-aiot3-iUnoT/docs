# 📝 4.4 가상 센서 관리

## 기능 목적

> 구역별 가상 센서 설정과 활성 상태를 Redis에 저장하고, Lock을 획득한 인스턴스가 `VirtualSensorFlow-{sectionId}`를 실행하여 표준 데이터를 생성한다.

## 현재 입력값

| 항목 | 필수 | 설명 |
| --- | :---: | --- |
| `organizationId`, `storageId`, `sectionId` | O | URL 경로의 조직·저장소·구역 ID |
| `deviceEui` | O | 가상 장치 식별자 |
| `measurementIntervalSeconds` | O | 1초 이상의 생성 주기 |
| `temperature.min/max` | O | 온도 생성 범위 |
| `humidity.min/max` | O | 습도 생성 범위 |
| `doorOpenProbability` | O | 0~1 사이 문 열림 확률 |

## 현재 처리 절차

1. 생성 API가 조직·저장소·구역 계층과 설정값을 검증한다.
2. 설정을 Redis에 중복 없이 저장하고 해당 `sectionId`를 활성 목록에 추가한다.
3. `VirtualSensorCoordinator`가 활성 목록을 주기적으로 확인한다.
4. 구역별 Redis Lock을 획득한 인스턴스만 `VirtualSensorFlow-{sectionId}`를 시작한다.
5. `VirtualSensorGeneratorNode`가 온도·습도·문열림 데이터를 모두 생성한다.
6. `RabbitNormalizedPublisherNode`가 데이터를 `iunot.sensor.normalized.queue`에 발행한다.
7. 비활성화되거나 Lock을 잃으면 해당 Flow를 중지한다.

## API

| Method | 경로 | 설명 |
| --- | --- | --- |
| POST | `/api/rule-engine/organizations/{organizationId}/storages/{storageId}/sections/{sectionId}/virtual-sensor` | 가상 센서 설정 생성 및 활성화 |
| PATCH | `/api/rule-engine/organizations/{organizationId}/storages/{storageId}/sections/{sectionId}/status` | `ACTIVE` 또는 `INACTIVE` 변경 |

현재 조회·수정·삭제 API는 구현되어 있지 않다.

## 센서 종류 선택 확장

> **구현 예정** — 센서 목록에서 선택한 종류만 생성·발행하는 기능은 현재 DTO와 Generator에 없다.

- 설정에 `sensorTypes` 목록을 추가한다.
- 지원값은 `temperature`, `humidity`, `door`로 제한한다.
- `VirtualSensorGeneratorNode`는 선택된 센서만 생성한다.
- 선택 목록은 하나 이상이어야 하며, 변경은 해당 `sectionId` Flow에만 반영한다.

- [ ] 가상 센서 설정 조회·수정·삭제 API가 제공된다.

## 현재 제약

- `VirtualSensorGeneratorNode`는 선택 여부와 관계없이 온도·습도·문열림 세 종류를 매 주기 모두 생성한다.
- Redis Repository에는 설정 `update()`가 있으나 이를 호출하는 수정 API와 실행 중 Flow 재적용 절차는 없다.
- 조직·저장소·구역 계층 검증은 현재 형식 검증만 수행하며 장소 관리 API 연동은 TODO다.
