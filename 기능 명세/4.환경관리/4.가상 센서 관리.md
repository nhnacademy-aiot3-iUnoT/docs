# 📝 4.4 가상 센서 관리

## 기능 목적

> `VirtualSensorFlow-{sectionId}`가 구역별 설정에 따라 가상 센서 데이터를 생성하고, 표준 형식으로 내부 MQTT에 발행한다.

## 사용자 및 권한

- 가상 센서 관리 권한을 가진 조직 관리자
- 환경관리 룰엔진 시스템

## 사전 조건

- 조직, 저장소, 구역, 가상 장치, 센서 설정이 등록되어 있어야 한다.
- 내부 MQTT 브로커와 해당 `SectionEnvironmentFlow-{sectionId}`가 실행 중이어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 구역 정보 | Object | O | `organizationId`, `storageId`, `sectionId` |
| 가상 장치 정보 | Object | O | `deviceEui` |
| 생성 주기 | Long | O | 데이터 생성 간격 |
| 센서 종류 및 값 정책 | Object | O | 온도·습도 범위, 이상값 확률, 문 열림 확률 |
| Flow 활성화 여부 | Boolean | O | 가상 데이터 생성 여부 |

## 처리 절차

1. 가상 센서 설정을 검증한다.
2. 활성 구역별 `VirtualSensorFlow-{sectionId}`를 생성하고 시작한다.
3. `VirtualSensorGeneratorNode`가 설정된 주기와 정책에 따라 센서 종류별 측정값을 생성한다.
4. `organizationId`, `storageId`, `sectionId`, 장치 정보를 포함한 `SensorPayloadDto`를 생성한다.
5. `InternalMqttPublisherNode`가 `iot/{organizationId}/{storageId}/{sectionId}/{deviceEui}/{sensorType}` 토픽으로 발행한다.

## 업무 규칙

- `VirtualSensorFlow-{sectionId}`는 활성화된 구역마다 하나만 운영한다.
- `VirtualSensorFlow`는 `VirtualSensorGeneratorNode`와 `InternalMqttPublisherNode`만 포함한다.
- 가상 센서는 InfluxDB 저장, 룰 검사, 상태 판단, 이벤트, 알림을 직접 수행하지 않는다.
- 발행된 가상 센서 데이터는 해당 `SectionEnvironmentFlow-{sectionId}`가 구독한다.
- Flow 생성 시 `sectionId`를 주입하고 메시지마다 구역 정보를 조회하지 않는다.

## 처리 결과

- [ ] 구역별 가상 센서 데이터가 설정된 주기로 생성된다.
- [ ] 가상 센서 데이터가 실제 센서와 동일한 표준 형식과 토픽 규칙을 사용한다.
- [ ] 발행된 데이터를 해당 구역의 환경 처리 Flow가 구독한다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 구역 또는 센서 설정 누락 | Flow를 생성하지 않고 경고 로그를 남긴다. |
| 설정값이 유효하지 않음 | Flow 시작을 거부하고 검증 오류를 반환한다. |
| 내부 MQTT 발행 실패 | 오류를 기록하고 다음 생성 주기의 처리를 계속한다. |
