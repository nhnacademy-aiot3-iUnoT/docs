# 📝 4.2 공통 센서 데이터 구독 및 검증

## 기능 목적

> Subflow 및 가상 센서 Flow가 내부 MQTT에 발행한 표준 센서 데이터를 단일 `EnvironmentProcessingFlow`가 구독·검증하고, 위치별로 분배하지 않은 채 저장 단계로 전달한다.

## 사용자 및 권한

- 환경관리 룰엔진 시스템
- 내부 MQTT 브로커
- 실제 센서 데이터 발행 Flow
- 가상 센서 데이터 발행 Flow

## 사전 조건

- 단일 `EnvironmentProcessingFlow`가 실행 중이어야 한다.
- 내부 MQTT의 `iot/#` 토픽을 구독할 수 있어야 한다.
- InfluxDB와 위치별·센서별 룰 설정을 조회할 수 있어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `applicationName` | String | O | 병원 또는 캠퍼스명 |
| `locationId` | Long | O | 위치별 저장·룰·상태 조회 기준 |
| `location` | String | O | 센서 설치 위치명 |
| `deviceName`, `deviceEui` | String | O | 장치 이름과 고유 식별자 |
| `sensorType`, `value`, `unit` | String, Number, String | O | 표준 센서 종류, 측정값, 단위 |
| `time` | String | O | ISO 8601 형식의 측정 시각 |

## 처리 절차

1. `EnvironmentProcessingFlow`의 `InternalMqttSubscriberNode`가 내부 MQTT의 `iot/#` 토픽을 구독한다.
2. 수신한 JSON 메시지를 `SensorPayloadDto`로 변환한다.
3. `SensorPayloadValidationNode`가 위치, 장치, 센서 종류, 측정값, 단위, 측정 시각 등 필수 항목을 검증한다.
4. 검증을 통과한 메시지를 같은 Flow의 `InfluxDbSaveNode`로 전달한다.

## 업무 규칙

- `EnvironmentProcessingFlow`는 시스템 전체에 하나만 실행해야 한다.
- 위치별로 MQTT Subscriber를 별도 생성하지 않아야 한다.
- `LocationRouterNode`와 위치별 `LocationRuleFlow`를 생성하지 않아야 한다.
- 모든 표준 센서 데이터는 동일한 구독·검증 절차를 거쳐 같은 Flow의 저장 단계로 이동해야 한다.
- `locationId`는 메시지 분기에 사용하지 않고 이후 저장·판단 단계의 조회 키로만 사용한다.

## 처리 결과

- [ ] 표준 센서 데이터가 단일 `EnvironmentProcessingFlow`에서 수신된다.
- [ ] 유효한 표준 센서 데이터가 위치별 분배 없이 같은 Flow의 저장 단계로 전달된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| JSON 변환 실패 | 메시지를 제외하고 토픽과 실패 원인을 기록한다. |
| 필수 데이터 누락 | 메시지를 제외하고 누락 항목을 기록한다. |
| `locationId`가 없음 | 검증 실패로 처리하고 장치 정보와 실패 사유를 기록한다. |
