# 📝 4.2 구역별 센서 데이터 구독 및 검증

## 기능 목적

> `SectionEnvironmentFlow-{sectionId}`가 해당 구역의 내부 MQTT 토픽을 구독하고, 표준 센서 데이터를 변환·검증한 뒤 같은 Flow의 저장 Node로 전달한다.

## 사용자 및 권한

- 환경관리 룰엔진 시스템
- 내부 MQTT 브로커
- `ExternalSensorFlow`
- `VirtualSensorFlow-{sectionId}`

## 사전 조건

- 활성 구역별 `SectionEnvironmentFlow-{sectionId}`가 실행 중이어야 한다.
- 각 Flow는 `iot/+/+/{sectionId}/#` 토픽을 구독할 수 있어야 한다.
- Flow 생성 시 해당 `sectionId`가 주입되어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `organizationId` | Long | O | 조직 식별자 |
| `storageId` | Long | O | 저장소 식별자 |
| `sectionId` | Long | O | Flow 및 구역 식별자 |
| `deviceEui` | String | O | 장치 고유 식별자 |
| `sensorType`, `value`, `unit` | String, Number, String | O | 센서 종류, 측정값, 단위 |
| `time` | String | O | ISO 8601 형식의 측정 시각 |

## 처리 절차

1. `InternalMqttSubscriberNode`가 `iot/+/+/{sectionId}/#` 토픽을 구독한다.
2. 수신한 JSON 메시지를 `SensorPayloadDto`로 변환한다.
3. `SensorPayloadValidationNode`가 조직, 저장소, 구역, 장치, 센서 종류, 측정값, 단위, 측정 시각을 검증한다.
4. Flow의 `sectionId`와 payload의 `sectionId`가 일치하는지 확인한다.
5. 검증을 통과한 메시지를 같은 Flow의 `InfluxDbSaveNode`로 전달한다.

## 업무 규칙

- 구역별 `SectionEnvironmentFlow` 안에 `InternalMqttSubscriberNode`를 하나씩 둔다.
- 각 Flow는 자신의 `sectionId`에 해당하는 토픽만 구독해야 한다.
- 별도의 `LocationRouterNode`나 공통 Subscriber Flow를 생성하지 않는다.
- 검증 실패 메시지는 저장·룰 검사 단계로 전달하지 않는다.

## 처리 결과

- [ ] 구역별 Flow가 해당 `sectionId`의 토픽만 구독한다.
- [ ] 유효한 표준 센서 데이터가 같은 Flow의 저장 Node로 전달된다.
- [ ] 구역별 수신·검증 처리가 독립적으로 실행된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| JSON 변환 실패 | 메시지를 제외하고 토픽과 실패 원인을 기록한다. |
| 필수 데이터 누락 | 메시지를 제외하고 누락 항목을 기록한다. |
| payload의 `sectionId`가 없음 | 검증 실패로 처리하고 장치 정보를 기록한다. |
| Flow와 payload의 `sectionId`가 다름 | 저장·판단을 수행하지 않고 경고 로그를 남긴다. |
