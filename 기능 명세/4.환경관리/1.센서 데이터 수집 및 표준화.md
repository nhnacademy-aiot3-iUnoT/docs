# 📝 4.1 센서 데이터 수집 및 표준화

## 기능 목적

> 외부 MQTT 메시지를 구독해 `deviceEui`로 설치 구역을 해석하고, 측정값을 표준 `SensorPayload`로 변환해 센서 키 기반 파티션 Normalized Queue에 발행한다.

## Flow 구성

`MqttSubscriberNode` → `SensorTransformNode` → `RabbitNormalizedPublisherNode`

## 입력값

외부 payload에서 룰엔진이 사용하는 필드만 `ExternalSensorMessage`로 정리한다.

| 항목 | 원본 위치 | 필수 | 설명 |
| --- | --- | :---: | --- |
| `devEui` | `deviceInfo.devEui` | O | 장치 고유 식별자이자 구역 해석 기준, 누락 시 `unknown` |
| `object` | `object` | O | 센서 측정값 Map |
| `time` | `rxInfo[0].nsTime` | X | 측정 시각, 누락 시 수신 시점의 현재 시각 |
| `applicationName` | `deviceInfo.applicationName` | X | 참고용으로만 담는다 |
| `location` | `deviceInfo.tags.location` | X | 참고용으로만 담는다 |
| `point` | `deviceInfo.tags.point` | X | 참고용으로만 담는다 |

- 위치는 더 이상 `applicationName + location + point` 문자열로 매핑하지 않는다. `devEui` 하나로 Inventory에 물어본다.
- 측정 시각은 payload 최상위 `time` 필드가 아니라 게이트웨이가 기록한 `rxInfo[0].nsTime`을 사용한다. 외부 `time` 값의 오차가 커서 기준을 바꿨다.
- MQTT 수신 토픽과 서버 수신 시각은 각각 `topic`, `mqttReceivedAt`으로 원본 Map에 추가된 뒤 DTO에 담긴다.
- `deviceInfo`, `tags`, `object`가 Map이 아니면 빈 Map으로 처리해 변환 흐름을 끊지 않는다.

## 처리 절차

1. `MqttSubscriberNode`가 `application/+/device/+/event/up` 토픽을 QoS 1로 구독한다.
2. MQTT 연결이 끊기면 자동 재연결하고(`automaticReconnect`) 재연결 완료 시 기존 토픽을 다시 구독한다.
3. 수신 JSON을 Map으로 파싱한 뒤 `ExternalSensorMessage`로 변환해 출력 포트로 보낸다.
4. `SensorTransformNode`가 `SensorTransformService.transform()`을 호출한다.
5. `ZoneResolver.resolveActive(devEui)`가 Inventory에서 `organizationId`, `storageId`, `zoneId`를 조회하고, 운영 중인 구역인지까지 확인한다.
6. 측정값 Map을 순회하며 원본 키를 표준 `SensorCommand` 키로 매핑한 뒤(`magnet_status` → `door`), 하나의 원본 메시지를 센서 종류별 `SensorPayload`로 분리한다.
7. `SensorTransformNode`가 변환 결과 개수만큼 메시지를 나눠 내보낸다.
8. `RabbitNormalizedPublisherNode` → `NormalizedSensorPublisher`가 각 결과를 센서 키(`organizationId:storageId:zoneId:deviceEui:sensorType`) 해시 기반 파티션 Normalized Queue(`iunot.sensor.normalized.queue.0~1`)에 발행한다.

## 센서 변환 규칙

| 원본 측정 키 | 표준 센서 타입 | 값 | 단위 |
| --- | --- | --- | --- |
| `temperature` | `temperature` | 숫자 또는 숫자 문자열 | `C` |
| `humidity` | `humidity` | 숫자 또는 숫자 문자열 | `%` |
| `magnet_status` | `door` | `open` → `1.0`, `close` → `0.0` | 문열림 여부 |
| `illumination` | `illumination` | 숫자 또는 숫자 문자열 | `lux` |

- `magnet_status`는 원본 측정 키이지만 `SensorCommand`는 `door` 키로 등록되어 있어, 변환 전에 `magnet_status`를 `door`로 치환한 뒤 조회한다.
- `open`/`close` 외의 문 상태 값은 변환 예외로 처리된다.

## 구역 해석 규칙

`ZoneResolver`는 `CachedZoneLookup`을 통해 Inventory 내부 API를 호출하고 결과를 Caffeine 캐시에 담는다.

| 조회 | Inventory 경로 | 캐시 이름 | TTL |
| --- | --- | --- | --- |
| 기기 위치 | `GET /api/core/internal/devices/location?device-eui=` | `device-zone` | 조회 성공 30분, 미등록(빈 결과) 2분 |
| 구역 활성 여부 | `GET /api/core/internal/zones/{zoneId}/activation` | `zone-activation` | 30초 |
| 구역 소속 위치 | `GET /api/core/internal/zones/{zoneId}/location` | `zone-location` | 조회 성공 30분, 없는 구역 2분 |

- 구역에 등록되지 않은 기기의 데이터는 갈 곳이 없으므로 버린다. 등록되면 캐시가 만료되는 대로 저절로 다시 흐른다.
- 구역이나 저장소가 비활성이면 데이터를 버린다. 저장소가 꺼져 있으면 구역이 `ACTIVE`여도 `active`는 `false`다.
- Inventory 장애로 활성 여부를 확인하지 못하면 **활성으로 본다**. 조회가 안 된다고 멀쩡한 구역의 수집·알림까지 멈추는 편이 더 위험하기 때문이다. 반면 구역이 정말 없으면 비활성으로 본다.
- 인벤토리에서 구역·저장소 설정이 바뀌면 `iunot.cache_exchange`(Fanout)로 무효화 메시지가 오고, 각 인스턴스의 `CacheInvalidationListener`가 해당 캐시 항목을 즉시 비운다.

## 완료 기준

- [x] 외부 MQTT 메시지가 수집 Flow에서 바로 표준화된다.
- [x] 실제 센서 위치가 `deviceEui` 기준 Inventory 조회로 조직·저장소·구역 ID에 매핑된다.
- [x] 온도·습도·문열림·조도 값이 센서별 `SensorPayload`로 변환된다.
- [x] 한 측정값의 실패가 같은 메시지의 다른 센서값 변환을 중단시키지 않는다.
- [x] 변환 결과가 센서 키 기준으로 파티셔닝되어 Normalized Queue에 발행된다.
- [x] 실제 장치가 보내는 `magnet_status` 키가 `door` 센서로 정상 변환된다.
- [x] 미등록·비활성 구역의 데이터가 수집 단계에서 걸러진다.
- [x] Raw Queue 경유 단계가 제거되어 수집 지연 구간이 줄었다.
- [x] 임시 `SectionCatalog`가 Inventory API 연동으로 교체되었다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| MQTT JSON 파싱 실패 | `rawPayload`만 포함한 Map으로 처리하며, `devEui`가 없어 구역 해석에 실패해 표준 데이터가 생성되지 않는다. |
| MQTT QoS 설정값이 0~2 밖 | 경고 로그를 남기고 기본값 1을 사용한다. |
| 외부 센서 메시지 누락 | 경고 로그를 남기고 변환하지 않는다. |
| 미등록 기기 · 비활성 구역 | 경고 로그를 남기고 표준 데이터를 생성하지 않는다. |
| Inventory 구역 조회 실패 | 경고 로그를 남기고 그 메시지만 버린다(`Optional.empty()`). |
| 미지원 측정 키 | 해당 값만 제외한다. |
| 개별 값 변환 실패 | 실패한 값만 제외하고 나머지 값을 계속 변환한다. |
| 표준 데이터 직렬화 실패 | `IllegalArgumentException`으로 변환해 발행을 중단한다. |
