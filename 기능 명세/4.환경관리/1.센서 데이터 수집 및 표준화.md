# 📝 4.1 센서 데이터 수집 및 표준화

## 기능 목적

> 실제 센서 데이터를 외부 MQTT에서 수신하고, 센서 종류별 표준 형식으로 변환한 뒤 위치를 식별하여 내부 MQTT로 전달한다.

## 사용자 및 권한

- 외부 센서 장치 또는 외부 MQTT 브로커
- 환경관리 룰엔진 시스템
- 장소 관리 서비스 조회 권한을 가진 시스템

## 사전 조건

- 외부 및 내부 MQTT 브로커 접속 정보가 설정되어 있어야 한다.
- 센서가 전송하는 병원명과 위치명이 장소 관리 서비스에 등록되어 있어야 한다.
- 장소 관리 서비스에서 위치 정보를 조회할 수 있어야 한다.
- 지원하는 센서 종류와 단위가 정의되어 있어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `applicationName` | String | O | `deviceInfo.applicationName`에서 추출하는 병원 또는 캠퍼스명 |
| `location` | String | O | `deviceInfo.tags.location`에서 추출하는 위치명 |
| `deviceName` | String | O | `deviceInfo.deviceName`의 센서 장치명 |
| `devEui` | String | O | `deviceInfo.devEui`의 장치 고유 식별자 |
| `measurements` | Map\<String, Object\> | O | `object`에 포함된 센서 종류별 원본 측정값 |
| `time` | String | X | payload의 측정 시간, ISO 8601 형식 |

## 처리 절차

1. `ExternalSensorFlow`(`sensor-processing-flow`)가 외부 MQTT 센서 토픽을 구독한다.
2. `SensorTransformNode`가 메시지에서 병원명, 위치명, 장치 정보, 측정 시간과 센서 종류별 측정값을 추출한다.
3. 하나의 외부 메시지에 여러 센서 측정값이 있으면 센서 종류별 `SensorPayloadDto`로 분리한다.
4. 센서 종류별 변환 정책을 적용해 측정값, 센서 종류와 단위를 표준화한다. 원본 측정 시간이 없거나 변환할 수 없으면 MQTT 수신 시간을 사용한다.
5. `LocationResolveNode`가 `applicationName + location`으로 장소 관리 서비스에서 `locationId`를 조회한다.
6. 조회한 `locationId`를 `SensorPayloadDto`에 설정한다.
7. `MqttPublisherNode`가 표준 센서 데이터를 `iot/{applicationName}/{location}/{deviceName}/{sensorType}` 토픽으로 내부 MQTT에 발행한다.

## 표준 센서 데이터

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `applicationName` | String | O | 병원 또는 캠퍼스명 |
| `deviceName` | String | O | 센서 장치명 |
| `deviceEui` | String | O | 센서 장치 고유 식별자 |
| `location` | String | O | 센서가 설치된 위치명 |
| `locationId` | Long | O | 장소 관리 서비스에서 조회한 위치 식별자 |
| `sensorType` | String | O | `temperature`, `humidity`, `door` 중 하나 |
| `value` | Double | O | 표준화된 측정값 |
| `unit` | String | O | `C`, `%`, `bool` 중 센서 종류에 맞는 단위 |
| `time` | String | O | ISO 8601 형식의 측정 시간 |

## 업무 규칙

- 문서의 병원명과 위치명은 표준 데이터의 `applicationName`과 `location`에 각각 대응한다.
- 위치는 `applicationName + location` 조합으로 식별해야 한다.
- 위치명만으로 위치를 식별하지 않아야 한다.
- 온도와 습도는 숫자로 변환하며 기본 단위는 각각 `C`, `%`로 처리한다.
- 문 열림 값 `open`은 `1.0`, 문 닫힘 값 `close`는 `0.0`으로 변환하고 단위는 `bool`로 처리한다.
- 원본 측정 시간이 유효한 ISO 8601 형식이면 해당 시간을 우선 사용하고, 없거나 유효하지 않으면 MQTT 수신 시간을 사용해야 한다.
- 하나의 외부 메시지에 여러 지원 센서 값이 있으면 센서 종류별로 하나의 표준 데이터를 생성해야 한다.
- 지원하지 않는 센서 종류는 건너뛰되, 같은 메시지의 다른 센서 값 변환은 계속해야 한다.
- 표준 데이터에는 병원명, 장치명, 장치 식별자, 위치 ID, 위치명, 센서 종류, 값, 단위, 측정 시간이 포함되어야 한다.
- `locationId`가 확인된 메시지만 내부 MQTT에 발행해야 한다.
- 실제 센서와 가상 센서는 동일한 내부 토픽 규칙을 사용해야 한다.
- MQTT의 브로커 주소와 QoS는 환경설정으로 관리해야 한다.
- 메시지 한 건의 처리 실패가 전체 Flow를 중단시키지 않아야 한다.
- MQTT 연결이 끊기면 자동 재연결을 시도해야 한다.

## 처리 결과

- [ ] 외부 센서 데이터가 내부 표준 센서 데이터로 변환된다.
- [ ] 위치 식별이 완료된 데이터가 내부 MQTT에 발행된다.
- [ ] 이후 실제 센서와 가상 센서 데이터가 동일한 환경관리 절차로 처리된다.

## 예외 처리

| 예외 조건                 | 처리                                      |
|-----------------------|-----------------------------------------|
| 외부 MQTT payload를 JSON으로 변환할 수 없음 | 메시지를 제외하고 수신 토픽과 변환 실패 원인을 기록한다. |
| `applicationName` 또는 `location`이 없음 | 메시지를 제외하고 식별 가능한 장치 정보와 실패 원인을 로그로 남긴다. |
| 장치 정보가 없음 | 표준 데이터를 발행하지 않고 누락 항목을 기록한다. |
| 측정 시간이 없거나 형식이 잘못됨 | MQTT 수신 시간으로 대체하고 대체 사유를 기록한다. |
| 측정값이 없거나 빈 Map임 | 표준 데이터를 생성하지 않고 디버그 로그를 남긴다. |
| 장소 관리 서비스에서 위치를 찾지 못함 | 내부 MQTT로 발행하지 않고 조회 조건과 실패 원인을 기록한다.    |
| 장소 관리 서비스 호출 또는 응답 오류 | 해당 메시지를 제외하고 오류 로그를 남긴다.                |
| 지원하지 않거나 변환할 수 없는 센서값 | 처리 대상에서 제외하고 경고 로그를 남긴다.                |
| 내부 MQTT 발행 실패         | 오류를 기록하고 외부 MQTT 구독 Flow는 계속 실행한다.      |
| MQTT 연결 해제            | 자동 재연결을 시도하고 연결 상태를 기록한다.               |
