# 📝 4.1 센서 데이터 수집 및 표준화

## 기능 목적

> 실제 센서 데이터를 외부 MQTT에서 수신하고, 위치를 식별한 표준 센서 데이터로 변환하여 내부 MQTT로 전달한다.


## 사용자 및 권한

- 외부 센서 장치 또는 외부 MQTT 브로커
- 환경관리 룰엔진 시스템
- 장소 관리 서비스 조회 권한을 가진 시스템


## 사전 조건

- 외부 및 내부 MQTT 브로커 접속 정보가 설정되어 있어야 한다.
- 센서가 전송하는 병원명과 위치명이 장소 관리 서비스에 등록되어 있어야 한다.
- 장소 관리 서비스에서 위치 정보를 조회할 수 있어야 한다.
- 지원하는 센서 종류와 단위가 정의되어 있어야 한다.


## 입력값

| 항목 | 형식     | 필수 여부 | 설명 |
| --- |--------| :---: | --- |
| 병원명 | String | O | 위치 식별에 사용하는 병원명 |
| 위치명 | String | O | 위치 식별에 사용하는 장소명 |
| 장치명 | String | O | 센서 장치 이름 |
| 장치 식별자 | String | O | 장치를 구분하는 고유 식별자 |
| 센서 종류 | String | O | `temperature`, `humidity`, `door` 등 |
| 측정값 | Number | O | 센서가 측정하거나 전송한 값 |
| 측정 시간 | String | O | ISO 8601 형식의 센서 측정 시간 |


## 처리 절차

1. `external-sensor-flow`가 외부 MQTT 센서 토픽을 구독한다.
2. 메시지에서 병원명, 위치명, 장치 정보, 센서 종류 및 측정값을 추출한다.
3. 센서 종류에 따라 측정값과 단위를 표준 형식으로 변환한다.
4. 병원명과 위치명으로 위치 정보 캐시를 조회한다.
5. 캐시에 정보가 없으면 장소 관리 서비스에서 `locationId`를 조회하고 결과를 캐시한다.
6. 위치 정보와 장치 정보를 포함한 표준 센서 데이터를 생성한다.
7. `iot/{locationId}/{deviceName}/{sensorType}` 토픽으로 내부 MQTT에 발행한다.


## 업무 규칙

- 위치는 `hospitalName + locationName` 조합으로 식별해야 한다.
- 위치명만으로 위치를 식별하지 않아야 한다.
- 온도와 습도는 숫자로 변환하며 기본 단위는 각각 `C`, `%`로 처리한다.
- 문열림 값 `open`, `true`, `1`은 `1.0`, 문닫힘 값 `closed`, `close`, `false`, `0`은 `0.0`으로 변환한다.
- 표준 데이터에는 병원명, 장치명, 장치 식별자, 위치 ID, 위치명, 센서 종류, 값, 단위, 측정 시간 및 가상 센서 여부가 포함되어야 한다.
- `locationId`가 확인된 메시지만 내부 MQTT에 발행해야 한다.
- 실제 센서와 가상 센서는 동일한 내부 토픽 규칙을 사용해야 한다.
- MQTT의 브로커 주소와 QoS는 환경설정으로 관리해야 한다.
- 메시지 한 건의 처리 실패가 전체 Flow를 중단시키지 않아야 한다.
- MQTT 연결이 끊기면 자동 재연결을 시도해야 한다.


## 처리 결과

- 외부 센서 데이터가 내부 표준 센서 데이터로 변환된다.
- 위치 식별이 완료된 데이터가 내부 MQTT에 발행된다.
- 이후 실제 센서와 가상 센서 데이터가 동일한 환경관리 절차로 처리된다.


## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 병원명 또는 위치명이 없음 | 메시지를 제외하고 식별 가능한 장치 정보와 실패 원인을 로그로 남긴다. |
| 장소 관리 서비스에서 위치를 찾지 못함 | 내부 MQTT로 발행하지 않고 조회 조건과 실패 원인을 기록한다. |
| 장소 관리 서비스 호출 또는 응답 오류 | 해당 메시지를 제외하고 오류 로그를 남긴다. |
| 지원하지 않거나 변환할 수 없는 센서값 | 처리 대상에서 제외하고 경고 로그를 남긴다. |
| 내부 MQTT 발행 실패 | 오류를 기록하고 외부 MQTT 구독 Flow는 계속 실행한다. |
| MQTT 연결 해제 | 자동 재연결을 시도하고 연결 상태를 기록한다. |
