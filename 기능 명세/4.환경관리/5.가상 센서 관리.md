# 📝 4.5 가상 센서 관리

## 기능 목적

> 위치별 가상 센서 데이터를 설정에 따라 생성하고 내부 MQTT로 발행하여 실제 센서와 동일한 환경관리 흐름으로 처리한다.


## 사용자 및 권한

- 가상 센서 관리 권한을 가진 조직 관리자
- 환경관리 룰엔진 시스템

## 사전 조건

- 가상 센서를 사용할 위치가 등록되어 있어야 한다.
- 위치의 병원명, 위치 ID 및 위치명을 조회할 수 있어야 한다.
- 내부 MQTT 브로커가 실행 중이어야 한다.
- 위치별 가상 센서 설정이 등록되어 있어야 한다.


## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 병원명 | String | O | 가상 센서 소속 병원 |
| 위치 ID 및 위치명 | Long, String | O | 가상 센서 데이터 발생 위치 |
| 생성 주기 | Duration | O | 가상 데이터 생성 간격 |
| 센서 종류 | List\<String\> | O | 생성할 온도, 습도, 문 센서 종류 |
| 값 생성 범위·확률 | Object | O | 최소·최대값, 이상값 및 문열림 발생 확률 |
| 장치명·가상 장치 식별자 | String | O | 가상 센서를 식별하는 정보 |
| Flow 활성화 여부 | Boolean | O | 데이터 생성 여부 |


## 처리 절차

1. 가상 센서를 사용하는 위치의 설정을 조회한다.
2. 위치별 `virtual-sensor-flow-{locationId}`를 생성하고 시작한다.
3. 설정된 주기와 범위에 따라 온도, 습도 또는 문 상태 값을 생성한다.
4. 위치 및 장치 정보와 `virtual: true`를 포함한 표준 센서 데이터를 만든다.
5. 실제 센서와 동일한 `iot/{locationId}/{deviceName}/{sensorType}` 토픽으로 내부 MQTT에 발행한다.
6. 공통 내부 MQTT 수신 Flow와 위치별 Rule Flow에서 저장 및 룰 판단을 수행한다.

## 업무 규칙

- 가상 센서를 사용하는 위치마다 별도 Flow를 생성해야 한다.
- 동일 위치의 가상 센서 Flow가 중복 생성되지 않아야 한다.
- 위치별 Flow는 독립적으로 시작, 중지 및 제거할 수 있어야 한다.
- Flow 생성 시 전달받은 위치 정보를 사용하며 매 메시지마다 장소 관리 서비스를 조회하지 않아야 한다.
- 위치마다 생성 주기, 센서 종류, 값 범위, 이상값 확률 및 문열림 조건을 다르게 설정할 수 있어야 한다.
- 가상 센서 Flow는 InfluxDB 저장, 임계값 판단, 문 상태 판단 또는 이벤트 발행을 직접 수행하지 않아야 한다.
- 가상 센서 데이터는 반드시 내부 MQTT와 공통 수신 Flow를 거쳐야 한다.

## 처리 결과

- 위치별 가상 센서 데이터가 설정에 따라 생성된다.
- 가상 센서 데이터가 내부 MQTT에 표준 형식으로 발행된다.
- 실제 센서와 동일한 저장, 룰 판단 및 알림 절차가 적용된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 위치 또는 가상 센서 설정이 없음 | Flow를 생성하지 않고 경고 로그를 남긴다. |
| 동일 위치 Flow가 이미 존재함 | 중복 생성하지 않고 기존 Flow를 유지한다. |
| 생성 설정값이 유효하지 않음 | Flow 시작을 거부하고 검증 오류를 반환한다. |
| 내부 MQTT 발행 실패 | 오류를 기록하고 다음 생성 주기의 처리는 계속한다. |
