# 📝 4.3 센서 데이터 저장 및 환경 판단

## 기능 목적

> `SectionEnvironmentFlow-{sectionId}`가 검증된 센서 데이터를 InfluxDB에 저장하고, 해당 구역의 환경 룰을 검사한 뒤 이상 상태를 판단한다.

## 사용자 및 권한

- 환경관리 룰엔진 시스템
- `SectionEnvironmentFlow-{sectionId}`
- InfluxDB

## 사전 조건

- 해당 구역의 `SectionEnvironmentFlow-{sectionId}`가 실행 중이어야 한다.
- InfluxDB와 구역별·센서별 룰 설정을 조회할 수 있어야 한다.
- 센서·장치별 임계값 이탈 시작 시각과 마지막 수신 시각을 관리할 수 있어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `organizationId` | Long | O | 조직 식별자 |
| `storageId` | Long | O | 저장소 식별자 |
| `sectionId` | Long | O | Flow, 저장 Tag, 룰 적용 기준 |
| `deviceEui` | String | O | 장치 고유 식별자 |
| `sensorType`, `value`, `unit`, `time` | String, Number, String, String | O | 센서 종류, 측정값, 단위, 측정 시각 |
| 룰 설정 | Object | O | 최소·최대 임계값, 이상 지속 시간, 미수신 기준 |

## 처리 절차

1. `InfluxDbSaveNode`가 측정 시각을 변환하고, 변환할 수 없으면 서버 수신 시각을 사용한다.
2. 조직·저장소·구역·장치·센서 정보를 Tag으로, 측정값을 Field로 하여 InfluxDB에 저장한다.
3. `RuleEvaluationNode`가 Flow에 주입된 `sectionId`의 센서별 임계값, 이상 지속 시간, 미수신 기준을 검사한다.
4. 측정값이 임계값을 벗어나면 임계값 이탈 시작 시각을 기록한다.
5. `StateDecisionNode`가 이탈 여부와 지속 시간에 따라 `NORMAL`, `PENDING`, `ALERT` 상태를 판단한다.
6. `ALERT`로 판단되면 `EventCreationNode`로 알림 대상 데이터를 전달한다.
7. 측정값이 임계값 범위로 복귀하면 이탈 시작 시각과 상태를 초기화한다.

## 업무 규칙

- 센서 데이터는 룰 검사 전에 InfluxDB에 저장해야 한다.
- 임계값 이탈 상태는 `sectionId + sensorType + deviceEui` 기준으로 관리해야 한다.
- 이상 지속 시간에 도달하지 않은 `PENDING` 상태는 이벤트를 생성하지 않는다.
- 같은 이탈 상태에 대해 이벤트를 중복 생성하지 않아야 한다.
- 한 구역 Flow의 저장 또는 판단 오류가 다른 구역 Flow에 영향을 주지 않아야 한다.

## 처리 결과

- [ ] 검증된 센서 데이터가 `sectionId`를 Tag으로 하여 InfluxDB에 저장된다.
- [ ] 해당 구역의 룰과 이상 상태가 판단된다.
- [ ] `ALERT` 상태만 `EventCreationNode`로 전달된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| InfluxDB 저장 실패 | `sectionId`, 센서 종류, 장치 정보와 함께 오류를 기록한다. |
| 룰 설정 없음 또는 조회 실패 | 이벤트를 생성하지 않고 오류를 기록한다. |
| 상태 저장소 오류 | 해당 장치의 판단을 중단하고 다른 구역 Flow의 처리는 계속한다. |
