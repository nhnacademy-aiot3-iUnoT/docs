# 📝 4.3 환경 룰 판단 관리

## 구현 상태

> `ThresholdFilterNode`, `DoorStateFilterNode`, `AbnormalDecisionNode`의 기본 동작은 구현되었지만, 현재 `NormalizedSensorProcessingFlow`에는 연결되지 않았다.

따라서 아래 기능은 단위 Node 수준으로 구현되어 있으며 실제 RabbitMQ 센서 처리 경로에서는 아직 실행되지 않는다.

## 온도·습도 임계값 검사

`ThresholdFilterNode`는 `temperature`, `humidity`만 처리한다.

| 센서 | 기본 최솟값 | 기본 최댓값 | 이상 지속 시간 |
| --- | ---: | ---: | ---: |
| 온도 | 15℃ | 25℃ | 30분 |
| 습도 | 35% | 65% | 30분 |

- 최솟값 미만은 `BELOW_MIN`, 최댓값 초과는 `ABOVE_MAX`로 판단한다.
- 범위 안의 값은 `NORMAL` 결과를 생성한다.
- 현재 `InMemoryThresholdPolicyRepository`는 저장된 정책을 반환하지 않으므로 항상 기본 정책을 사용한다.
- 구역별 룰 CRUD와 영속 저장은 구현되지 않았다.

## 문열림 검사

`DoorStateFilterNode`는 `door` 센서만 처리한다.

- 값 `1.0`은 `OPEN`, 위반 상태로 판단한다.
- 값 `0.0`은 `CLOSED`, 정상 상태로 판단한다.
- 그 외 값은 지원하지 않는 상태로 기록하고 결과를 전달하지 않는다.

## 이상 상태 판단

`AbnormalDecisionNode`는 룰 결과를 다음 키로 메모리에 관리한다.

`organizationId:storageId:sectionId:deviceEui:sensorType`

| 조건 | 상태 및 출력 |
| --- | --- |
| 정상 결과 | `NORMAL`로 초기화, 알림 대상 출력 없음 |
| 지속 시간 있는 최초 위반 | `PENDING` 저장 |
| 위반 지속 시간 충족 | `ALERT`로 변경하고 결과 출력 |
| 문열림처럼 지속 시간 없는 위반 | 즉시 `ALERT`로 변경하고 결과 출력 |
| `ALERT`가 계속됨 | 30분마다 결과 재출력 |

## 현재 제약

- 세 Node는 `NormalizedSensorProcessingFlow`에 연결되지 않았다.
- 상태는 인스턴스의 `ConcurrentHashMap`에만 존재하므로 재시작 시 초기화된다.
- 여러 인스턴스가 Normalized Queue를 경쟁 소비하면 같은 센서의 연속 데이터가 다른 인스턴스로 분산될 수 있다.
- 분산 상태 저장 또는 센서 키 기반 라우팅 없이 상태 판단을 연결하면 지속 시간 판단이 일관되지 않을 수 있다.
- 미수신 센서 판단은 구현되지 않았다.

## 완료 기준

- [x] 온도·습도 임계값 검사 Node가 구현되었다.
- [x] 문열림 검사 Node가 구현되었다.
- [x] `NORMAL/PENDING/ALERT` 상태 전이와 30분 재출력이 구현되었다.
- [ ] 룰 Node가 Normalized 처리 Flow에 연결된다.
- [ ] 구역별 룰 CRUD와 영속 Repository가 구현된다.
- [ ] 분산 환경에서 상태 일관성이 보장된다.
- [ ] 미수신 센서 판단이 구현된다.
