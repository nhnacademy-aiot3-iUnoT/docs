# 📝 4.3 환경 룰 판단 관리

## 기능 목적

> 위치별 센서 데이터에 온도·습도 임계값, 문 상태 및 데이터 미수신 룰을 적용하여 이상 상태와 정상 복구를 판단한다.


## 사용자 및 권한

- 환경관리 룰엔진 시스템
- 환경 룰 설정 권한을 가진 조직 관리자


## 사전 조건

- 센서 데이터의 위치와 장치가 식별되어 있어야 한다.
- 위치별·센서별 룰 설정이 등록되어 있어야 한다.
- 해당 룰과 알림 사용 여부가 설정되어 있어야 한다.
- 센서별 마지막 수신 시간과 현재 상태를 저장할 수 있어야 한다.


## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 위치 ID | Long | O | 룰 적용 위치 |
| 센서 종류 | String | O | `temperature`, `humidity`, `door` 등 |
| 장치 식별자 | String | O | 장치별 상태 및 미수신 관리 기준 |
| 측정값 | Number | O | 표준화된 센서값 |
| 최소·최대 임계값 | Number | 조건부 | 온도·습도 룰 사용 시 필요 |
| 이상 지속시간 | Duration | 조건부 | 임계값 이상 상태 확정 기준 |
| 미수신 기준시간 | Duration | 조건부 | 센서 통신 장애 판단 기준 |
| 룰·알림 활성화 여부 | Boolean | O | 판단 및 알림 수행 여부 |

## 처리 절차

1. 위치, 센서 종류 및 장치 식별자를 기준으로 적용할 룰을 조회한다.
2. 룰 활성화 여부를 확인하고 센서의 마지막 수신 시간을 갱신한다.
3. 온도·습도는 최소값과 최대값을 비교하고 이상 지속시간을 확인한다.
4. 문 센서는 마지막 문 상태와 새 상태를 비교하여 열림 또는 닫힘 상태 전이를 판단한다.
5. 공통 미수신 감시 스케줄러가 활성 센서의 마지막 수신 시간을 주기적으로 확인한다.
6. 상태를 `NORMAL`, `PENDING`, `ALERT`, `RECOVERED`, `DISABLED` 중 하나로 갱신한다.
7. 신규 이상, 문 상태 변경, 통신 장애 또는 정상 복구가 확정되면 이벤트 생성 단계로 전달한다.

## 업무 규칙

- 온도·습도 값이 임계 범위를 벗어나면 `PENDING`, 설정된 시간 이상 지속되면 `ALERT`로 전이해야 한다.
- 지속시간 전에 정상 범위로 복구되면 이벤트 없이 `NORMAL`로 돌아가야 한다.
- `ALERT` 상태에서 정상 범위로 돌아오면 `RECOVERED`를 거쳐 `NORMAL`로 전이해야 한다.
- 문 상태의 초기값은 `UNKNOWN`이며, 첫 상태 이벤트 수신 후 `OPEN` 또는 `CLOSED`로 갱신해야 한다.
- `UNKNOWN` 자체는 이상으로 판단하지 않아야 한다.
- 문 상태는 마지막 수신 이벤트를 기준으로 유지하고, 같은 상태가 반복되면 중복 알림을 생성하지 않아야 한다.
- 센서 수신 시 `locationId + sensorType + deviceEui` 기준으로 마지막 수신 시간을 갱신해야 한다.
- 마지막 수신 시간에 미수신 기준시간을 더한 값이 현재 시간보다 이전이면 미수신 상태로 판단해야 한다.
- 미수신 상태에서 데이터가 다시 수신되면 통신 복구로 판단해야 한다.
- 동일한 이상 또는 미수신 상태에 대해 이벤트를 반복 생성하지 않아야 한다.
- 룰이 비활성화되면 상태를 `DISABLED`로 관리하고 룰 이벤트를 생성하지 않아야 한다.
- 룰 설정을 조회하지 못한 경우 임의 기본값으로 판단하지 않아야 한다.

## 처리 결과

- 위치별·센서별 현재 환경 상태가 갱신된다.
- 임계값 초과, 문열림·문닫힘, 센서 미수신 및 각 복구 상태가 판별된다.
- 새로 확정된 상태 변화만 이벤트 생성 대상으로 전달된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 룰 설정이 없거나 조회에 실패함 | 해당 룰 판단을 중단하고 오류 로그를 남긴다. |
| 지원하지 않는 센서 종류 | 판단 대상에서 제외하고 경고 로그를 남긴다. |
| 문 상태값을 해석할 수 없음 | 기존 상태를 유지하고 경고 로그를 남긴다. |
| 같은 이상 또는 문 상태가 반복됨 | 상태 정보만 유지하고 중복 이벤트를 생성하지 않는다. |
| 룰이 비활성화됨 | 상태를 `DISABLED`로 관리하고 이벤트와 알림을 생성하지 않는다. |
