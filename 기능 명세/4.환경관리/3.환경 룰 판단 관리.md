# 📝 4.3 위치별 센서 데이터 저장 및 임계값 판단

## 기능 목적

> 위치별 `LocationRuleFlow`로 분배된 센서 데이터를 InfluxDB에 저장하고, 설정된 임계값 이탈이 지속 시간을 초과한 경우만 `AlarmNode`에 알림 대상 데이터를 전달한다.

## 사용자 및 권한

- 환경관리 룰엔진 시스템
- 위치별 `LocationRuleFlow`
- InfluxDB
- `AlarmNode`

## 사전 조건

- 대상 위치의 `LocationRuleFlow-{locationId}`가 실행 중이어야 한다.
- InfluxDB와 위치별·센서별 임계값 설정을 조회할 수 있어야 한다.
- 센서·장치별 임계값 이탈 시작 시각을 관리할 수 있어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `locationId` | Long | O | 위치 Flow와 룰 적용 기준 |
| `applicationName`, `location` | String | O | InfluxDB에 저장할 병원 또는 캠퍼스명과 위치명 |
| `deviceName`, `deviceEui` | String | O | 장치 정보 |
| `sensorType`, `value`, `unit`, `time` | String, Number, String, String | O | 표준 센서 종류, 측정값, 단위, 측정 시각 |
| 임계값 설정 | Object | O | 최소·최대 임계값과 이상 지속 시간 |

## 처리 절차

1. 위치 Flow는 자신의 `locationId`와 수신 데이터의 `locationId`가 일치하는지 검증한다.
2. 측정 시각을 변환하고, 변환할 수 없으면 서버 수신 시각을 사용한다.
3. 위치·장치·센서 정보를 Tag으로, 측정값을 Field로 하여 InfluxDB에 저장한다.
4. 센서 종류에 해당하는 위치별 임계값과 이상 지속 시간을 조회한다.
5. 측정값이 임계값을 벗어나면 임계값 이탈 시작 시각을 기록한다.
6. 이탈 상태가 이상 지속 시간 이상 유지되면 알림 대상 데이터를 생성하여 `AlarmNode`로 전달한다.
7. 측정값이 임계값 범위로 복귀하면 임계값 이탈 시작 시각을 초기화한다.

## 업무 규칙

- 센서 데이터는 임계값 판단 전에 InfluxDB에 저장해야 한다.
- 임계값 이탈 시작 시각은 `locationId + sensorType + deviceEui` 기준으로 관리해야 한다.
- 임계값 이탈이 지속 시간에 도달하지 않으면 `AlarmNode`로 전달하지 않아야 한다.
- 같은 이탈 상태에 대해 알림 대상 데이터를 중복 전달하지 않아야 한다.
- 한 위치 Flow의 저장 또는 판단 오류가 다른 위치 Flow에 영향을 주지 않아야 한다.

## 처리 결과

- [ ] 분배된 센서 데이터가 위치별로 InfluxDB에 저장된다.
- [ ] 임계값을 벗어난 상태의 지속 시간이 판단된다.
- [ ] 설정된 지속 시간을 초과한 데이터만 `AlarmNode`로 전달된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| Flow의 위치 ID와 메시지의 위치 ID가 다름 | 저장·임계값 판단을 수행하지 않고 경고 로그를 남긴다. |
| InfluxDB 저장 실패 | 위치, 센서 종류, 장치 정보와 함께 오류 로그를 남긴다. |
| 임계값 설정 없음 또는 조회 실패 | 알림 대상 데이터를 생성하지 않고 오류를 기록한다. |
