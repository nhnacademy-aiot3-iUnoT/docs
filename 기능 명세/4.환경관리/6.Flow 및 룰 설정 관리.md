# 📝 4.6 Flow 생명주기 및 설정 관리

## 기능 목적

> 세 종류의 Flow를 시작·중지하고, Local Connection의 비동기 처리를 관리하며 외부 수집과 가상 센서의 중복 실행을 방지한다.

## 현재 Flow

| Flow | ID | 생성 기준 | 시작 방식 |
| --- | --- | --- | --- |
| 외부 센서 수집 | `sensor-processing-flow` | 클러스터 전체 1개 | `ExternalIngressCoordinator`가 Redis Lock 획득 후 시작 |
| 가상 센서 | `virtual-sensor-flow-{sectionId}` | 활성 구역별 1개 | `VirtualSensorCoordinator`가 구역 Lock 획득 후 시작 |
| 표준 센서 처리 | `normalized-sensor-processing-flow` | 인스턴스별 1개 | `NormalizedSensorFlowInitializer`가 애플리케이션 초기화 시 시작 |

내부 MQTT 설정, `SectionEnvironmentFlow`, `SectionEnvironmentFlowFactory`, `SectionEnvironmentFlowService`는 현재 소스에서 제거되었다.

## 비동기 Flow 처리

- Flow Node 사이는 `LocalConnection`으로 연결한다.
- `FlowEngine`은 Connection마다 별도의 비동기 소비 작업을 실행한다.
- Flow 시작 전 Node·Port 존재 여부와 순환 연결을 검사한다.
- 동일 Flow ID는 한 인스턴스의 `FlowEngine`에 중복 등록하지 않는다.
- `FlowProcessingCompletion`이 비동기 처리 결과를 RabbitMQ Consumer에 전달한다.
- 검증 또는 저장 중 예외가 발생하면 Connection 작업이 완료 객체를 예외 상태로 변경한다.
- 종료 시 Connection 작업을 먼저 중단한 뒤 Node 자원을 종료한다.

## 설정 반영 범위

- 가상 센서 생성과 활성·비활성 상태 변경은 Redis에 반영된다.
- Coordinator가 Redis 활성 목록을 다음 확인 주기에 읽어 Flow 시작·중지를 조정한다.
- 가상 센서 설정 수정·삭제 API 및 실행 중 갱신은 구현되지 않았다.
- 환경 임계값은 현재 메모리 Repository와 기본값만 사용한다.
- 룰 설정 API, 알림 채널 설정과 Flow 반영은 구현되지 않았다.

## 완료 기준

- [x] 외부 수집 Flow가 클러스터 전체에서 하나만 실행된다.
- [x] 활성 구역별 가상 센서 Flow가 하나만 실행된다.
- [x] 각 인스턴스에서 Normalized 처리 Flow가 자동 실행된다.
- [x] Flow Connection이 비동기로 처리되고 완료·오류가 Consumer에 전달된다.
- [x] 내부 MQTT 기반 Flow가 제거되었다.
- [ ] 룰 Node가 Normalized Flow에 연결된다.
- [ ] 가상 센서·룰·알림 설정 변경이 실행 중 Flow에 반영된다.
