# 📝 4.6 Flow 생명주기 및 설정 관리

## 기능 목적

> 시스템 전체에 하나인 `EnvironmentProcessingFlow`의 생명주기를 관리하고, 위치별 룰·가상 센서 설정 변경을 재생성 없이 실행 중인 Flow에 반영한다.

## 사용자 및 권한

- 환경관리 설정 권한을 가진 조직 관리자
- 환경관리 룰엔진 시스템
- 장소 관리 서비스

## 사전 조건

- 위치 정보와 활성 상태를 조회할 수 있어야 한다.
- 룰 설정과 가상 센서 설정을 저장할 수 있어야 한다.
- `ExternalSensorSubflow`와 단일 `EnvironmentProcessingFlow`를 실행할 수 있어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `locationId` | Long | O | 위치별 룰·가상 센서 설정 관리 기준 |
| `applicationName`, `location` | String | O | 위치 소속과 위치명 |
| `locationStatus` | String | O | 활성, 비활성, 삭제 상태 |
| `ruleConfig` | Object | O | 센서별 임계값, 지속 시간, 미수신, 알림 설정 |
| `virtualSensorConfig` | Object | X | 생성 주기, 센서 종류, 값 범위, 발생 확률 설정 |

## 처리 절차

1. 룰엔진 시작 시 `ExternalSensorSubflow`와 단일 `EnvironmentProcessingFlow`를 생성하고 시작한다.
2. 활성 위치와 저장된 룰·가상 센서 설정을 조회해 설정 저장소를 초기화한다.
3. 가상 센서 설정이 활성화된 위치마다 `VirtualSensorFlow-{locationId}`를 생성하고 시작한다.
4. 위치가 비활성화되거나 삭제되면 해당 위치의 룰을 비활성화하고 가상 센서 Flow만 중지·제거한다.
5. 룰 또는 가상 센서 설정 변경 요청의 권한과 입력값을 검증한다.
6. 검증된 설정을 저장하고, `EnvironmentProcessingFlow`가 이후 수신하는 데이터부터 새 위치별 룰을 조회하도록 반영한다.
7. Flow 생명주기와 설정 변경 이력을 기록한다.

## 업무 규칙

- `EnvironmentProcessingFlow`는 위치 수와 관계없이 시스템 전체에 하나만 생성해야 한다.
- 위치별 `LocationRuleFlow`를 생성·시작·중지·제거하지 않아야 한다.
- 위치가 비활성화되거나 삭제되어도 공통 `EnvironmentProcessingFlow`는 계속 실행해야 한다.
- 서버 재시작 시 공통 Flow를 한 번만 복구하고 위치별 설정을 설정 저장소에서 재로드해야 한다.
- 룰 설정 변경을 위해 실행 중인 `EnvironmentProcessingFlow`를 재생성하지 않아야 한다.
- 가상 센서 설정 변경시 실행 중인 `VirtualSensorFlow`는 생성 주기와 값 생성 조건을 갱신해야 한다.
- 임계값, 시간, 센서 종류 등 설정값은 저장 전 유효성을 검증해야 한다.

## 처리 결과

- [ ] 위치 수와 관계없이 단일 `EnvironmentProcessingFlow`가 실행된다.
- [ ] 서버 재시작 후 공통 Flow와 위치별 룰·가상 센서 설정이 자동 복구된다.
- [ ] 서비스 중단 없이 변경된 룰·가상 센서 설정이 적용된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 공통 Flow 중복 생성 요청 | 추가 생성하지 않고 기존 `EnvironmentProcessingFlow`를 유지한다. |
| 필수 위치 정보 또는 설정 누락 | 설정 변경을 거부하고 오류를 기록한다. |
| 유효하지 않은 임계값·시간·센서 종류 | 설정을 저장하지 않고 검증 오류를 반환한다. |
| 공통 Flow 시작·중지 실패 | Flow ID와 실패 원인을 기록하고 재시작 정책을 수행한다. |
| 서버 재시작 시 공통 Flow 복구 실패 | 센서 처리를 시작하지 않고 복구 실패 원인을 기록한다. |
