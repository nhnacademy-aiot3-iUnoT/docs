# 📝 4.6 Flow 생명주기 및 설정 관리

## 기능 목적

> 위치 상태와 설정에 따라 위치별 `LocationRuleFlow`와 `VirtualSensorFlow`의 생성·시작·중지·제거를 관리하고, 실행 중인 Flow에 룰·가상 센서 설정 변경을 반영한다.

## 사용자 및 권한

- 환경관리 설정 권한을 가진 조직 관리자
- 환경관리 룰엔진 시스템
- 장소 관리 서비스

## 사전 조건

- 위치 정보와 활성 상태를 조회할 수 있어야 한다.
- 룰 설정과 가상 센서 설정을 저장할 수 있어야 한다.
- 공통 `ExternalSensorFlow`와 `InternalMqttSubscriberFlow`가 실행 중이어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `locationId` | Long | O | Flow 생명주기 관리 기준 |
| `applicationName`, `location` | String | O | 위치 소속과 위치명 |
| `locationStatus` | String | O | 활성, 비활성, 삭제 상태 |
| `ruleConfig` | Object | O | 센서별 임계값, 지속 시간, 미수신, 알림 설정 |
| `virtualSensorConfig` | Object | X | 생성 주기, 센서 종류, 값 범위, 발생 확률 설정 |

## 처리 절차

1. 룰엔진 시작 시 활성 위치와 저장된 설정을 조회한다.
2. 활성 위치마다 `LocationRuleFlow-{locationId}`를 생성하고 시작한다.
3. 가상 센서 설정이 활성화된 위치마다 `VirtualSensorFlow-{locationId}`를 생성하고 시작한다.
4. 위치가 비활성화되거나 삭제되면 해당 위치의 Flow를 중지하고 제거한다.
5. 룰 또는 가상 센서 설정 변경 요청의 권한과 입력값을 검증한다.
6. 검증된 설정을 저장하고, 실행 중인 Flow가 이후 수신·생성하는 데이터부터 새 설정을 사용하도록 반영한다.
7. Flow 생명주기와 설정 변경 이력을 기록한다.

## 업무 규칙

- Flow ID에는 변경 가능한 이름이 아닌 `locationId`를 사용해야 한다.
- 같은 `locationId`의 `LocationRuleFlow`와 `VirtualSensorFlow`를 중복 생성하지 않아야 한다.
- 위치별 Flow는 다른 위치의 Flow와 독립적으로 시작, 중지, 제거할 수 있어야 한다.
- 위치가 비활성화되거나 삭제되어도 공통 MQTT Flow는 계속 실행해야 한다.
- 서버 재시작 시 활성 위치와 저장된 설정을 기준으로 Flow를 자동 복구해야 한다.
- 룰 설정 변경을 위해 실행 중인 `LocationRuleFlow`를 재생성하지 않아야 한다.
- 가상 센서 설정 변경시 실행 중인 `VirtualSensorFlow`는 생성 주기와 값 생성 조건을 갱신해야 한다.
- 임계값, 시간, 센서 종류 등 설정값은 저장 전 유효성을 검증해야 한다.

## 처리 결과

- [ ] 위치 상태에 따라 위치별 Flow가 생성, 시작, 중지 또는 제거된다.
- [ ] 서버 재시작 후 활성 위치의 Flow와 설정이 자동 복구된다.
- [ ] 서비스 중단 없이 변경된 룰·가상 센서 설정이 적용된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 동일한 위치 Flow 생성 요청 | 추가 생성하지 않고 기존 Flow를 유지한다. |
| 필수 위치 정보 또는 설정 누락 | Flow 생성 또는 설정 변경을 거부하고 오류를 기록한다. |
| 유효하지 않은 임계값·시간·센서 종류 | 설정을 저장하지 않고 검증 오류를 반환한다. |
| Flow 시작·중지·제거 실패 | `locationId`, Flow ID, 실패 원인을 기록한다. |
| 서버 재시작 시 일부 Flow 복구 실패 | 다른 위치 Flow의 복구는 계속하고 실패 대상을 기록한다. |
