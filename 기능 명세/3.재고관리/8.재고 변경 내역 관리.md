# 📝 8.1 재고 변경 내역 기록

## 기능 목적

> 입고·출고·폐기 작업 시 해당 내역을 기록하여 재고의 변동 이력을 관리한다.

## 사용자 및 권한

- 재고 관리 권한을 가진 사용자


## 사전 조건

- 사용자가 유효한 작업(입고/출고/폐기)을 요청함


## 처리 절차

재고관리 서비스가 입고·출고·폐기 프로세스를 실행 후 해당 내역을 받아와 재고 변동 내역으로 DB에 저장 후 성공 여부 반환

1. 사용자가 입고·출고·폐기서비스를 요청
2. 재고관리 서비스가 해당 프로세스 실행
3. 해당 프로세스 실행 후 변동 내역(history) 저장 프로세스 실행 및 성공 여부 반환
4. 재고 변동 내역 저장이 성공적으로 완료되면 입고·출고·폐기 프로세스 완료, 실패 시 트랜잭션 롤백

## 입력값

| 항목       | 형식       | 필수 여부 | 설명                  |
|----------|----------|:-----:|---------------------|
| 제품명      | String   |   Y   | 대상 제품의 이름           |
| 저장소/보관구역 | String   |   Y   | 재고 위치 정보            |
| 제조번호     | String   |   Y   | 제조번호 (Batch Number) |
| 유통기한     | Date     |   Y   | 제품 유통기한             |
| 변동유형     | Enum     |   Y   | 입고, 출고, 폐기 구분       |
| 처리 전 수량  | Integer  |   Y   | 변경할 수량              |
| 처리 후 수량  | Integer  |   Y   | 변경된 수량              |
| 작업자      | String   |   Y   | 작업 수행자 ID           |
| 사유       | String   |   N   | 작업 수행 사유            |
| 작업시간     | DateTime |   Y   | 작업을 수행한 시간          |

## 규칙 및 요구사항

- 이 작업은 사용자가 아닌 입고·출고·폐기 프로세스가 실행한다.
- 모든 입고·출고·폐기 작업과 내역 기록은 하나의 트랜잭션으로 처리한다.
- 내역 데이터는 생성 후 수정(Update) 및 삭제(Delete)를 금지한다.

## 처리 결과

- 성공 시: 프로세스 완료 및 변동 내역 저장
- 실패 시: Exception 발생 및 전체 작업 취소(Rollback)

## 예외 처리

| 예외 조건 | 처리                       |
| --- |--------------------------|
| 내역 기록 중 DB 장애 발생 | Exception 발생(전체 트랜잭션 롤백) |

# 📝 8.2 재고 변경 내역 조회

## 기능 목적

> 기록한 재고 변동 내역중 조건에 맞는 내역을 정렬하여 보여준다.

## 사용자 및 권한

- 재고 관리 권한을 가진 사용자


## 사전 조건

- 사용자가 검색 조건을 포함한 변경 내역 조회를 요청


## 처리 절차

사용자가 재고 변동 내역을 조회 시 조건에 맞는 변경 내역 DTO 리스트 반환

1. 사용자가 검색조건을 포함하여 변경 내역 조회를 요청
2. 재고관리 서비스는 요청받은 검색 조건을 바탕으로 테이블에서 조건에 부합하는 데이터를 조회
3. 조회된 데이터를 정렬 기준에 맞춰 정렬하여 사용자에게 리스트 형태로 반환
4. 조건에 맞는 내역이 없을경우, 빈리스트 혹은 적절한 메시지 반환

## 입력값

| 항목       | 형식     | 필수 여부 | 설명            |
|----------|--------|:-----:|---------------|
| 제품명      | String |   N   | 대상 제품의 이름     |
| 저장소/보관구역 | String |   N   | 재고 위치 정보      |
| 변동유형     | Enum   |   N   | 입고, 출고, 폐기 구분 |
| 시작 날짜    | Date   |   N   | 조회 기간의 시작점    |
| 마지막 날짜   | Date   |   N   | 조회 기간의 종료점    |
| 정렬기준     | Enum   |   Y   | 최신순(디폴트), 과거순 |

## 규칙 및 요구사항

- 정렬기준은 사용자가 설정하지 않을 경우 프론트에서 기본적으로 최신순을 선택하여 요청
- 입력되지 않은 조건 항목은 검색 필터에서 제외
- 변동 내역 DTO의 리스트 형태로 반환, 내역이 없을 경우 빈리스트 반환

## 처리 결과

- 성공 시: 변동 내역 DTO의 리스트 형태 또는 빈리스트 반환
- 실패 시: 에러 처리된 ApiResponse 반환

## 예외 처리

| 예외 조건            | 처리                   |
|------------------|----------------------|
| 내역 조회 중 DB 장애 발생 | error ApiResponse 반환 |
