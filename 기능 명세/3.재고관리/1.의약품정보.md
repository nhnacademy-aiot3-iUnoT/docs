# 📝 의약품 정보 제공

## 기능 목적

> 이 기능을 제공하는 목적을 작성한다.
사용자가 의약품 입고 시 제품의 기본 정보를 직접 입력하면 오입력, 표기 방식 불일치 및 중복 등록이 발생할 수 있다.
따라서 공공데이터포털에서 제공하는 식품의약품안전처 의약품 API를 통해 의약품 기본 정보를 수집한다.
수집한 정보는 시스템 데이터베이스의 의약품 목록에 저장하고, 이후 의약품 검색과 입고 등록 시 기준정보로 사용한다.

## 최초 데이터 구축

시스템은 최초 구축 시 공공데이터 API에서 제공하는 전체 의약품 정보를 페이지 단위로 수집하여 시스템 데이터베이스에 저장한다.
한 번의 API 호출로 전체 의약품 정보가 반환되지 않으므로, API 응답의 전체 데이터 건수와 페이지당 조회 건수를 기준으로 전체 페이지 수를 계산한 후 
마지막 페이지까지 반복 호출한다.


## 사전 조건

- 공공데이터 포털에서 API 서비스키가 발급되어 있어야 한다.
- 의약품 정보 수집 API가 정상적으로 호출 가능해야 한다.
- 의약품 정보를 저장할 데이터베이스와 테이블이 생성되어 있어야 한다.
- 동일한 최초 수집 작업이 이미 실행 중이지 않아야 한다.


## API 응답의 페이지 정보
```
<numOfRows>10</numOfRows>
<pageNo>1</pageNo>
<totalCount>43017</totalCount>
```

| 응답 항목        | 설명                        |
| ------------ | ------------------------- |
| `numOfRows`  | 현재 요청에서 설정한 페이지당 최대 조회 건수 |
| `pageNo`     | 현재 조회한 페이지 번호             |
| `totalCount` | API에서 조회 가능한 전체 의약품 건수    |

위 응답은 현재 1페이지를 조회했으며, 한 페이지당 최대 10건씩 전체 43,017건의 데이터가 존재한다.

## 처리 절차

1. 시스템은 pageNo=1로 공공데이터 API를 호출한다.
2. API 응답의 처리 결과 코드가 정상인지 확인한다.
3. 응답에서 `totalCount`,`numOfRows`,`pageNo`를 확인한다.
4. `totalCount`와 `numOfRows`를 이용하여 전체 페이지 수를 계산한다.
5. 응답에 포함된 의약품 정보를 내부 저장 형식으로 변환한다.
6. 필수값이 존재하는지 검증한다.
7. 검증을 통과한 데이터를 데이터베이스에 저장한다.
8. `pageNo`를 1씩 증가시키며 다음 페이지를 호출한다.
9. 마지막 페이지까지 동일한 처리를 반복한다.
10. 전체 페이지 처리가 완료되면 수집 작업 결과를 기록한다.

## 페이지별 저장 방식
전체 데이터를 메모리에 한 번에 보관하지 않고, 페이지 단위로 조회하고 저장한다.

```
1페이지 조회
→ 1페이지 데이터 저장
→ 다음 페이지 조회

2페이지 조회
→ 2페이지 데이터 저장
→ 다음 페이지 조회
```

## 데이터 검증

필수값 
다음 값이 없는 데이터는 정상적인 의약품 정보로 저장하지 않는다.
- 품목기준코드
- 제품명
- 업체명

선택값
- 저장방법
- 유효기간
- 포장단위
- 성분 및 함량
- 마약류 구분 


## 데이터 변환 규칙

- 품목기준코드, 제품명 및 업체명은 앞뒤 공백을 제거한 후 저장한다.
- 저장방법, 유효기간 및 성분·함량은 임의로 해석하거나 분리하지 않고 원문을 저장한다.
- API의 날짜 형식은 내부 시스템 날짜 형식으로 변환할 수 있는 경우 변환한다.
- 변환할 수 없는 값은 원문을 유지하고 오류 내용을 기록한다.




## 업무 규칙

- 시스템은 API응답의 `totalCount`를 기준으로 전체 의약품 건수와 수집할 페이지 수를 결정한다.
- 시스템은 `totalCount`와 `numOfRows`를 이용하여 전체 페이지 수를 계산한다.
- 시스템은 `pageNo`를 1부터 마지막 페이지까지 증가시키며 모든 의약품 정보를 순차적으로 수집한다.
- 페이지당 조회 건수는 API 가 허용하는 범위 안에서 가능한 크게 설정하여 호출 횟수를 줄인다.
- 수집한 데이터는 전체를 한 번에 메모리에 보관하지 않고 페이지 단위로 DB에 저장한다.
- 품목기준코드, 제품명, 업체명과 같은 필수값이 누락된 데이터는 저장하지 않는다.
- 저장방법, 성분·함량 정보 등 선택값이 없는 경우 해당 항목은 `null`로 저장할 수 있다.
- 저장방법, 유효기간, 성분·함량 정보처럼 형식이 일정하지 않은 값은 공공데이터 원문 그대로 저장한다.
- 동일한 품목기준코드가 이미 DB에 존재하면 새로운 의약품으로 중복 등록하지 않는다.
- 기존 의약품 정보와 새로 수집한 정보가 다르면 기존 데이터를 갱신한다.
- 수집 도중 API 호출이나 DB 저장에 실패하면 오류 내용을 로그로 기록한다.
- 수집 실패가 발생하더라도 기존에 저장된 의약품 정보는 삭제하지 않는다.
- 최초 수집이 완료된 이후 의약품 검색과 입고 등록에서는 공공데이터 API가 아니라 내부 DB의 의약품 정보를 사용한다.
- 공공데이터 API가 일시적으로 중단되더라도 기존 DB에 저장된 의약품 정보는 계속 조회하고 입고 등록에 사용할 수 있어야 한다.
- API 서비스키는 소스코드에 직접 작성하지 않고 환경변수 또는 외부 설정 파일로 관리한다. 



## 처리 결과

- 공공데이터 API의 전체 의약품 정보가 시스템 DB에 저장된다.
- 저장된 의약품은 제품명, 품목기준코드로 검색할 수 있다.
- 입고 등록시 공공데이터 API를 다시 호출하지 않고 내부 DB의 의약품 정보를 사용한다.
- 동일한 의약품 데이터를 다시 수집해도 중복 의약품이 생성되지 않는다.
- 기존 의약품의 정보가 변경된 경우 변경된 내용이 DB에 반영된다.
- 필수값이 누락되거나 저장에 실패한 데이터는 저장 대상에서 제외된다.
- API 호출 또는 DB 저장 중 오류가 발생하면 오류 내용이 로그에 기록된다.
- 일부 페이지 수집에 실패하더라도 이전에 정상 저장된 의약품 정보는 유지된다.

## 로그 기록 규칙

- API 서비스키, 데이터베이스 비밀번호, 인증 토큰 등 민감정보는 로그에 기록하지 않는다.
- 길이가 큰 API 원본 응답 전체는 로그에 기록하지 않는다.
- 오류 발생 시 원인을 확인할 수 있도록 페이지 번호와 오류 메시지를 기록한다.
- 선택값 누락은 오류로 처리하지 않으며, 필요한 경우 페이지별 집계 정보로 기록한다.
- 동일한 형식의 로그 메세지를 사용하여 페이지 번호와 품목기준코드로 검색할 수 있도록 한다.
