# 📝 11. 수량 조정


## 기능 목적
> 사용자가 입고 또는 출고 수량을 잘못 입력하거나, 시스템에 기록된 재고 수량과 창고에서 확인한 실제 재고 수량이 다른 경우 현재 재고 수량을 실제 수량에 맞게 정정할 수 있도록 한다.


## 사용자 및 권한

- 사용자는 현재 소속된 조직의 해당 부서의 저장소 재고만 정정할 수 있다.
- 재고 관리 권한이 없는 사용자는 수량 정정 기능을 사용할 수 없다.

## 사전 조건

- 정정 대상 재고가 존재해야 한다.
- 정정 대상 저장소가 사용자의 부서에 할당되어 있어야 한다. 
- 저장소 및 보관 구역이 사용가능한 상태여야 한다.
- 사용자가 창고에서 실제 재고 수량을 확인해야 한다.


## 기본 처리 원칙

확정된 기존 입고,출고,폐기 변동 내역은 수정하거나 삭제하지 않는다. 
수량 정정 시 사용자는 창고에서 확인한 실제 재고 수량을 입력한다.
시스템은 현재 시스템 수량과 실제 확인 수량의 차이를 자동으로 계산한다.

`조정 수량 = 실제 확인 수량 - 현재 시스템 수량`

- 조정 수량이 양수이면 재고 증가 정정으로 처리한다.
- 조정 수량이 음수이면 재고 감소 정정으로 처리한다.
- 조정 수량이 0이면 정정을 처리하지 않는다.


정정 완료 후 현재 재고 수량은 실제 확인 수량과 동일해야 한다.



## 재고 감소 정정

현재 시스템 수량: 70개
실제 확인 수량: 50개 
=> 조정 수량: -20개

## 재고 증가 정정

현재 시스템 수량: 70개
실제 확인 수량: 90개
=> 조정 수량: = 20개


## 처리 예시


### 입고 수량을 적게 입력한 경우
실제로 120개 입고 되었으나 100개로 입력한 경우:

| 변동 유형 | 변동 수량 | 처리 전 수량 | 처리 후 수량 |
| ----- | ----: | ------: | ------: |
| 입고    |  +100 |       0 |     100 |
| 수량 정정 |   +20 |     100 |     120 |


### 현재 재고를 감소 정정하는 경우

시스템 수량이 3,899개이지만 실제 확인 수량이 2,578개인 경우:

| 항목          |      수량 |
| ----------- | ------: |
| 현재 시스템 수량   |  3,899개 |
| 실제 확인 수량    |  2,578개 |
| 자동 계산 조정 수량 | -1,321개 |
| 정정 후 수량     |  2,578개 |


재고 변동 내역 목록:

| 변동 유형 |  변동 수량 | 처리 전 수량 | 처리 후 수량 |
| ----- | -----: | ------: | ------: |
| 수량 정정 | -1,321 |   3,899 |   2,578 |


## 기존 입출고 이후 정정하는 경우

| 변동 유형 | 변동 수량 | 처리 전 수량 | 처리 후 수량 |
| ----- | ----: | ------: | ------: |
| 입고    |  +100 |       0 |     100 |
| 출고    |   -30 |     100 |      70 |
| 수량 정정 |   -20 |      70 |      50 |

기존 입고 및 출고 내역은 그대로 유지하고, 수량 정정 내역만 새로 생성한다. 




## 입력값

| 항목        | 필수 여부 | 입력 방식    | 설명                                  |
| --------- | ----- | -------- |-------------------------------------|
| 재고 ID     | 필수    | 시스템 전달   | 정정할 개별 재고 의약품ID                     |
| 현재 시스템 수량 | 필수    | 읽기 전용 표시 | 정정 화면 조회 당시 시스템에 기록된 수량             |
| 실제 확인 수량  | 필수    | 사용자 입력   | 사용자가 창고에서 직접 확인한 실제 재고 수량 or 변경할 수량 |
| 조정 수량     | 필수    | 자동 계산    | 실제 확인 수량과 현재 시스템 수량의 차이             |
| 정정 후 수량   | 필수    | 자동 표시    | 정정 완료 후 적용될 재고 수량                   |
| 정정 사유     | 필수    | 사용자 선택   | 수량 차이가 발생한 원인                       |
| 상세 메모     | 선택    | 사용자 입력   | 정정 사유에 대한 추가 설명                     |


- 0 이상의 정수만 입력할 수 있다.
- 공백 또는 음수는 입력할 수 없다.
- 현재 시스템 수량과 동일한 값은 입력할 수 없다. 


## 동시 재고 변동 처리

사용자가 수량 정정 화면을 조회한 이후 정정을 완료하기 전까지 다른 사용자가 동일 재고에 대해 입고·출고·폐기·수량 정정을 처리할 수 있다. 
따라서 서버는 정정 요청 처리 시 현재 DB 수량과 정정 화면 조회 당시의 시스템 수량을 비교한다. 

### 현재 DB 수량과 조회 당시 수량이 동일한 경우 

조회 당시 시스템 수량: 3,899개
현재 DB 수량: 3,899개
→ 수량 정정 진행

서버는 다음과 같이 조정 수량을 다시 계산한다.

2,578 - 3,899 = -1,321

재고 수량을 2,578개로 변경하고 수량 정정 변동 내역을 생성한다.


### 현재 DB 수량과 조회 당시 수량이 다른 경우

조회 당시 시스템 수량: 3,899개
현재 DB 수량: 3,799개 
→ 다른 재고 변동 발생 
→ 수량 정정 중단 

다음 메시지를 제공한다.

정정 화면을 조회한 이후 다른 재고 변동이 발생했습니다. 현재 재고와 실제 수량을 다시 확인해 주세요.

변경된 현재 DB 수량을 기준으로 자동 정정하지 않는다.
화면 조회 이후 출고나 폐기가 발생했다면 사용자가 확인한 실제 수량도 이미 변경되었을 수 있기 때문이다.




## 동시성 제어

서버는 정정 대상 재고를 쓰기 잠금으로 조회한다.

```java
@Lock(LockModeType.PESSIMISTIC_WRITE)
@Query("""
    select i
    from MedicineInventory i
    where i.id = :inventoryId
""")
Optional<MedicineInventory> findByIdForUpdate(Long inventoryId);

```

다음 작업은 하나의 DB 트랜잭션으로 처리한다.

재고 행 쓰기 잠금
-> 현재 DB 수량 검증 -> 조정 수량 계산 -> 재고 수량 변경 -> 수량 정정 변동 내역 저장 -> 재고 상태 및 알림 재계산 -> 트랜잭션 커밋

재고 변경 또는 변동 내역 저장 중 하나라도 실패하면 전체 작업을 롤백한다.

## 재고 상태 및 알림 처리

수량 저정 완료 후 다음 항목을 다시 계산한다.

- 현재 재고 수량
- 출고 가능 수량
- 재고 부족 여부
- 재고 부족 알림 생성 여부
- 기존 재고 부족 알림 해제 여부
- 전체 재고 조회 화면의 재고 현황

### 재고 감소 정정
정정 후 출고 가능 수량이 최소 재고 기준 이하가 되면 재고 부족 알림을 생성한다.

### 재고 증가 정정
정정 후 출고 가능 수량이 최소 재고 기준을 초과하면 기존 재고 부족 알림을 해제한다.

수량 정정은 다음 상태를 자동으로 변경하지 않는다. 

- 환경 검토 상태
- 폐기 상태


## 처리 절차

1. 수량 정정 화면 조회
2. 정정 대상 재고 정보와 현재 시스템 수량 표시
3. 사용자가 창고의 실제 재고 수량 확인
4. 실제 확인 수량, 정정 사유 및 상세 메모 입력 
5. 시스템이 예상 조정 수량과 정정 후 수량 자동 표시
6. 사용자가 수량 정정 요청
7. 사용자 조직, 부서 및 재고 관리 권한 확인
8. 정정 대상 재고를 쓰기 잠금으로 조회
9. 현재 DB 수량과 화면 조회 당시 수량 비교
10. 실제 확인 수량 및 정정 사유 검증
11. 서버에서 조정 수량 재계산
12. 현재 재고 수량을 실제 확인 수량으로 변경
13. 수량 정정 변동 내역 생성
14. 출고 가능 수량 및 재고 부족 알림 재계산
15. 수량 정정 완료


### 동시 재고 변동이 발생한 경우

현재 DB 수량과 화면 조회 당시 수량이 다르면 정정을 처리하지 않는다.

현재 DB 수량 ≠ 화면 조회 당시 수량
1. 다른 입고·출고·폐기 또는 수량 정정이 발생한 것으로 판단
2. 수량 정정 중단
3. 사용자에게 현재 재고와 실제 수량 재확인 안내

안내 메시지:
정정 화면을 조회한 이후 다른 재고 변동이 발생했습니다. 현재 재고와 실제 수량을 다시 확인해 주세요.

## 규칙 및 요구사항

- 사용자는 재고 관리 권한이 있는 경우에만 수량을 정정할 수 있다.
- 사용자는 자신이 접근할 수 있는 조직 및 저장소의 재고만 정정할 수 있다.
- 수량 정정은 제조번호, 유통기한, 저장소 및 보관 구역으로 구분된 개별 재고를 대상으로 한다.
- 사용자는 창고에서 확인한 실제 재고 수량을 입력한다.
- 실제 확인 수량은 0 이상의 정수만 입력할 수 있다.
- 현재 시스템 수량과 실제 확인 수량이 같으면 정정할 수 없다.
- 시스템은 현재 수량과 실제 확인 수량의 차이를 자동 계산한다.
- 정정 완료 시 현재 재고 수량을 실제 확인 수량으로 변경한다.
- 기존 입고·출고·폐기 내역은 수정하거나 삭제하지 않고, 새로운 수량 정정 내역을 생성한다. 
- 정정 내역에는 조정 수량, 처리 전 수량, 처리 후 수량, 정정 사유, 처리자 및 처리 일시를 기록한다.
- 정정 화면 조회 이후 동일 재고의 수량이 변경된 경우 정정을 중단하고 재확인을 요청한다.
- 재고 수량 변경과 정정 내역 저장은 하나의 트랜잭션으로 처리한다.
- 수량 정정 완료 후 출고 가능 수량과 재고 부족 알림을 다시 계산한다. 



## 처리 결과

- 현재 재고 수량이 사용자가 입력한 실제 확인 수량으로 변경된다.
- 기존 입고·출고·폐기 내역은 변경되지 않는다.
- 조정 수량, 처리 전 수량, 처리 후 수량이 수량 정정 내역으로 새로 저장된다.
- 정정 사유, 상세 메모, 처리자 및 처리 일시가 기록된다.
- 정정된 수량을 기준으로 출고 가능 수량과 재고 부족 여부가 다시 계산된다.
- 정정 화면 조회 이후 다른 재고 변동(입고,출고)이 발생한 경우 수량 정정은 처리되지 않는다.

| 현재 수량과 실제 수량이 동일  | 현재 수량과 실제 확인 수량이 동일합니다.                                   |

| 조회 이후 다른 재고 변동 발생 | 정정 화면을 조회한 이후 다른 재고 변동이 발생했습니다. 현재 재고와 실제 수량을 다시 확인해 주세요. |
