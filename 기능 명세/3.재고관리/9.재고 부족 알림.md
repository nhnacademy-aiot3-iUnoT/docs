# 📝 9.1 재고 부족 알림 임계값 설정(생성)

## 기능 목적

> 사용자가 재고 부족 알림을 위한 임계값 설정(생성) 할 수 있도록 한다.

## 사용자 및 권한

- 재고 관리 권한을 가진 사용자

## 사전 조건

- 사용자가 의약품의 최소 개수 설정을 생성한다.


## 처리 절차

사용자가 재고 부족 알림을 위한 임계값을 설정하면 값을 받아와 최소 재고 품목 DB에 저장

1. 사용자가 의약품 최소 개수 설정(생성)
2. 최소 재고 품목 생성 및 DB저장
3. 사용자에게 최소 재고 품목 DTO를 포함한 ApiResponse반환
4. 실패 시 error ApiResponse반환

## 입력값

| 항목   | 형식      | 필수 여부 | 설명        |
|------|---------|:-----:|-----------|
| 제품명  | String  |   Y   | 대상 제품의 이름 |
| 저장소  | String  |   Y   | 재고 위치 정보  |
| 최소수량 | Integer |   Y   | 재고 최소 수량  |

## 업무 규칙

- 최소 수량이 유효한 값인지 검증한다(마이너스 방지)

## 처리 결과

- 성공 시: 최소 재고 품목 저장
- 실패 시: error Api Response 반환

## 예외 처리

| 예외 조건         | 처리                       |
|---------------|--------------------------|
| 저장 중 DB 장애 발생 | error Api Response 반환 |


# 📝 9.2 재고 부족 알림 임계값 설정(변경)

## 기능 목적

> 사용자가 재고 부족 알림을 위한 임계값 설정(변경) 할 수 있도록 한다.

## 사용자 및 권한

- 재고 관리 권한을 가진 사용자

## 사전 조건

- 사용자가 의약품의 최소 개수 설정을 변경한다.


## 처리 절차

사용자가 설정한 최소 재고 품목 옆의 변경칸을 누르고 값을 입력하면 값을 받아와 그 품목의 최소 수량을 업데이트한다.

1. 사용자가 의약품 최소 재고 품목 옆의 변경칸을 누르고 값을 입력
2. 해당 품목의 아이디로 품목의 조회 및 업데이트
3. 사용자에게 최소 재고 품목 DTO를 포함한 ApiResponse반환
4. 실패 시 error ApiResponse반환

## 입력값

| 항목         | 형식      | 필수 여부 | 설명           |
|------------|---------|:-----:|--------------|
| 변경할 품목 아이디 | Long    |   Y   | 최소 재고 품목의 키값 |
| 최소수량       | Integer |   Y   | 업데이트 할 최소 수량 |

## 업무 규칙

- 해당 품목의 아이디로 조회 후 널 체크(존재하지않는 품목 변경 시 오류 방지)
- 최소 수량이 유효한 값인지 체크(마이너스 방지)

## 처리 결과

- 성공 시: 최소 재고 품목 업데이트
- 실패 시: error Api Response 반환

## 예외 처리

| 예외 조건              | 처리                    |
|--------------------|-----------------------|
| 조회 및 저장 중 DB 장애 발생 | error Api Response 반환 |

# 📝 9.3 재고 부족 알림 임계값 설정(삭제)

## 기능 목적

> 사용자가 재고 부족 알림을 위한 임계값 설정(삭제) 할 수 있도록 한다.

## 사용자 및 권한

- 재고 관리 권한을 가진 사용자

## 사전 조건

- 사용자가 의약품의 최소 개수 설정을 삭제한다.


## 처리 절차

사용자가 설정한 최소 재고 품목 옆의 삭제칸을 누르면 값을 받아와 그 품목을 삭제한다.

1. 사용자가 의약품 최소 재고 품목 옆의 삭제칸 누른 후 확인 버튼 클릭
2. 해당 품목의 아이디가 존재하는지 확인 후 삭제
3. 사용자에게 성공 여부 포함한 ApiResponse반환
4. 실패 시 error ApiResponse반환

## 입력값

| 항목         | 형식      | 필수 여부 | 설명           |
|------------|---------|:-----:|--------------|
| 삭제할 품목 아이디 | Long    |   Y   | 최소 재고 품목의 키값 |

## 업무 규칙

- 해당 품목의 아이디가 존재하는지 체크 후 삭제
- 해당 품목이 존재하지 않을 시 이미 삭제된 품목임을 포함한 ApiResponse 반환

## 처리 결과

- 성공 시: 최소 재고 품목 삭제
- 실패 시: error Api Response 반환

## 예외 처리

| 예외 조건             | 처리                             |
|-------------------|--------------------------------|
| 삭제 중 DB 장애 발생     | error Api Response 반환          |
| 존재하지 않는 품목(동시 삭제) | 이미 삭제된 품목임을 포함한 ApiResponse 반환 |

# 📝 9.4 재고 부족 알림 임계값 설정(조회)

## 기능 목적

> 사용자가 현재 설정된 임계값을 직접 확인하여 재고 운영 정책을 관리하고 최신화 할 수 있도록 지원한다.

## 사용자 및 권한

- 재고 관리 권한을 가진 사용자

## 사전 조건

- 사용자가 의약품의 최소 개수 설정페이지에 진입함

## 처리 절차

1. 사용자가 최소 재고 품목 설정창에 들어왔을 때 조회 요청을 받음
2. 최소 재고 품목 페이징 조회
3. 사용자에게 최소 재고 품목 DTO 리스트를 포함한 ApiResponse반환
4. 실패 시 error ApiResponse반환

## 입력값

| 항목  | 형식      | 필수 여부 | 설명        |
|-----|---------|:-----:|-----------|
| 저장소 | String  |   N   | 재고 위치 정보  |
| 페이지 | Integer |   Y   | 조회할 페이지   |
| 사이즈 | Integer |   Y   | 페이지당 항목 수 |

## 업무 규칙

- 저장소 미입력시 전체 저장소 조회

## 처리 결과

- 성공 시: 최소 재고 품목 리스트 반환
- 실패 시: error Api Response 반환

## 예외 처리

| 예외 조건             | 처리                            |

# 📝 9.5 재고 부족 알림 생성

## 기능 목적

> 최소 재고 품목에 설정해둔 재고의 개수가 최소 수량보다 적을 시에 사용자 알려 재고를 확인하고 대처할 수 있도록 한다.

## 사용자 및 권한

- 재고 관리 권한을 가진 사용자

## 사전 조건

- 사용자가 출고·폐기 작업 수행

## 처리 절차

출고·폐기 작업 수행 후 재고 부족 알림 프로세스(비동기) 해당 의약품 정보를 넘기면 최소 재고 품목에 설정된 의약품인지 확인 후 최소 수량 보다 낮을 시 알림 생성

1. 사용자가 출고·폐기 작업 수행
2. 재고 부족 알림 프로세스 실행(비동기)
3. 최소 재고 품목에 해당 의약품이 존재하는지 확인
4. 해당 저장소의 의약품 개수 조회 및 최소 수량 비교
5. 최수 수량보다 적을 시 알림 생성 및 DB 저장

## 입력값

| 항목  | 형식      | 필수 여부 | 설명         |
|-----|---------|:-----:|------------|
| 제품명 | String  |   Y   | 대상 제품의 이름  |
| 저장소 | String  |   Y   | 재고 위치 정보   |

## 업무 규칙

- 최소 재고 품목에 해당 의약품이 존재하지 않을 시 즉시 프로세스 종료

## 처리 결과

- 성공 시: 조건에 부합 시 알림 생성

# 📝 9.6 재고 부족 알림(간단 구현 버전)

## 기능 목적

> 읽지 않은 알림이 존재 시 알림창에 표시하여 사용자가 알림을 확인 할 수 있도록 한다.

## 사용자 및 권한

- 재고 관리 권한을 가진 사용자

## 사전 조건

- 사용자가 웹페이지 이용(이동 또는 새로고침)

## 처리 절차

사용자가 웹 사용 시 읽지 않은 알림 내역 조회 후 알림 표시

1. 사용자가 웹 페이지 이동 또는 새로고침 시 알림 내역 조회 요청을 받음
2. 아직 읽지 않은 내역의 개수(캐싱 가능)를 포함하여 Api Response 반환
3. 웹 상단의 알림창 옆에 읽지 않은 알림 내역의 개수를 표시

## 입력값

없음

## 업무 규칙

- 알림 내역 중 읽음 필드가 false 인 내역을 조회하여 개수 반환

## 처리 결과

- 성공 시: 읽지 않은 알림 개수 표시
- 실패 시: error Api Response 반환

## 예외 처리

# 📝 9.7 알림 내역 조회

## 기능 목적

> 사용자가 모든 알림에 대한 내역을 확인하고 관리 할 수 있도록 한다.

## 사용자 및 권한

- 재고 관리 권한을 가진 사용자

## 사전 조건

- 사용자가 알림 내역 페이지로 진입

## 처리 절차

1. 사용자가 알림 내역 페이지로 진입했을때 조회 요청을 받음
2. 알림 내역 페이징 조회
3. 사용자에게 알림 내역 DTO 리스트를 포함한 ApiResponse 반환

## 입력값

| 항목    | 형식      | 필수 여부 | 설명            |
|-------|---------|:-----:|---------------|
| 읽음 상태 | boolean |   Y   | 조회할 알림의 읽음 상태 |
| 페이지   | Integer |   Y   | 조회할 페이지       |
| 사이즈   | Integer |   Y   | 페이지당 항목 수     |

## 업무 규칙

- 알림 내역이 없을 시 빈리스트를 반환
- 기본적으로 읽음 상태는 false(읽지 않은 알림)로 받는다 가정

## 처리 결과

- 성공 시: 알림 내역 DTO 또는 빈리스트 반환
- 실패 시: error ApiResponse 반환 

## 예외 처리

| 예외 조건             | 처리                            |
|-------------------|-------------------------------|
| 조회 중 DB 장애 발생     | error Api Response 반환         |
