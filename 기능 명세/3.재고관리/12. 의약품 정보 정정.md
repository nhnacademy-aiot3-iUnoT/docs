# 📝 12. 의약품 재고 정보 정정

## 기능 목적

> 사용자가 의약품 입고 등록 과정에서 제조번호 또는 유통기한을 잘못 입력한 경우 해당 재고 정보를 정정할 수 있도록 한다.



## 사용자 및 권한

- 사용자는 자신이 소속된 부서에 할당된 저장소의 재고만 정정할 수 있다.
- 사용자에게 의약품 재고 관리 권한이 있어야 한다.
- 다른 조직 또는 다른 부서에 속한 재고는 조회하거나 정정할 수 없다.


## 사전 조건

- 정정 대상 재고가 존재해야 한다.
- 정정 대상 재고가 폐기 완료 상태가 아니어야 한다.
- 정정 대상 재고에 정정 가능한 수량이 존재해야 한다.
- 정정 대상 재고의 현재 수량이 1개 이상이어야 한다.



## 화면 표시 정보

| 항목      | 표시 여부 | 설명              |
| ------- | ----- | --------------- |
| 재고 ID   | 표시    | 정정 대상 개별 재고 식별자 |
| 현재 의약품  | 표시    | 읽기 전용           |
| 현재 제조번호 | 표시    | 읽기 전용           |
| 현재 유통기한 | 표시    | 읽기 전용           |
| 현재 수량   | 표시    | 읽기 전용           |
| 저장소     | 표시    | 읽기 전용           |
| 보관 구역   | 표시    | 읽기 전용           |




## 입력값

| 항목       | 필수 여부 | 설명                       |
| -------- | ----- | ------------------------ |
| 정정할 제조번호 | 필수    | 올바른 제조번호                 |
| 정정할 유통기한 | 필수    | 올바른 유통기한                 |
| 정정 사유    | 필수    | 제조번호 입력 오류, 유통기한 입력 오류 등 |
| 메모       | 선택    | 추가 설명                    |





## 입력값 검증

### 제조번호

- 제조번호는 필수값
- 입력값의 앞뒤 공백을 제거한다.
- 공백만 입력할 수 없다.
- 시스템에서 정한 최대 길이를 초과할 수 없다.

### 유통기한

- 유통기한은 필수값
- 올바른 날짜 형식
- 현재 날짜 이전의 날짜를 입력한 경우 만료 재고로 처리
- 유통기한 변경 후 정상, 임박 또는 만료 상태를 다시 계산한다.

### 정정 사유

- 정정 사유는 필수값
- 공백만 입력할 수 없다.
- 시스템에서 정한 최대 길이 초과 불가

### 변경 여부

- 제조번호, 유통기한 또는 메모 중 하나 이상이 기존 값과 달라야 한다.
- 모든 입력값이 기존 값과 같은 경우 정정 요청을 처리하지 않는다.


## 동일 재고 판단 기준

정정 후 다음 값이 모두 같은 기존 재고가 있으면 동일 재고로 판단한다.

- 조직
- 의약품
- 저장소
- 보관 구역
- 제조번호
- 유통기한

```mysql
UNIQUE (
organization_id,
medicine_id,
storage_id,
storage_area_id,
lot_number,
expiration_date
)
```
제조번호와 유통기한이 같더라도 저장소 또는 보관 구역이 다르면 별도의 재고로 유지한다.


## 처리 절차

1. 사용자가 재고 상세 화면에서 `정보 정정` 버튼을 선택한다.
2. 시스템은 사용자의 조직 소속과 재고 관리 권한을 확인한다.
3. 시스템은 정정 대상 재고가 사용자의 관리 범위에 포함되는지 확인한다.
4. 시스템은 현재 재고 정보를 정정 화면에 표시한다.
5. 사용자는 제조번호, 유통기한, 메모 및 정정 사유를 입력한다.
6. 사용자가 `정정하기` 버튼을 선택한다.
7. 시스템은 입력값을 검증한다.
8. 시스템은 정정 대상 재고에 잠금을 설정한다.
9. 시스템은 변경 후 정보를 기준으로 동일 재고가 존재하는지 확인한다.
10. 동일 재고 존재 여부에 따라 정정 처리 방식을 결정한다.
11. 시스템은 변경 전·후 정보와 정정 사유를 이력으로 저장한다.
12. 유통기한 상태, 출고 가능 수량 및 관련 알림을 다시 계산한다.
13. 정정 결과를 사용자에게 표시한다.


## 정정 후 동일 재고가 존재하지 않는 경우

정정하려는 제조번호와 유통기한을 가진 동일 재고가 존재하지 않으면 기존 재고 정보를 직접 수정한다.

### 처리 내용

- 정정 대상 재고의 제조번호, 유통기한을 변경한다.
- 메모를 입력한 경우 변경한다.
- 재고 수량은 유지한다.
- 저장소와 보관 구역은 유지한다.
- 변경 전·후 정보와 정정 사유를 기록한다.

### 처리 예시

변경 전
의약품 A / 냉장구역 / LOT-001 / 2027-12-31 / 70개

변경 후
의약품 A / 냉장구역 / LOT-002 / 2028-06-30 / 70개

### 처리 결과

정정 후 동일 재고 없음
→ 제조번호·유통기한 직접 수정
→ 수량 유지


## 정정 후 동일 재고가 존재하는 경우

정정하려는 제조번호와 유통기한을 가진 동일 재고가 같은 저장소와 보관 구역에 이미 존재하면 기존 재고에 수량을 합산한다.

경고 문구

사용자에게 다음 경고를 표시한다.
> 동일한 제조번호와 유통기한을 가진 재고가 현재 위치에 이미 존재합니다. 정정을 진행하면 선택한 재고의 수량이 기존 재고에 합산됩니다. 

사용자가 확인한 경우에만 합산을 진행한다.
사용자가 취소하면 정정 처리를 중단한다.

처리 예시
```
정정 대상 재고 
의약품 A / 냉장구역 / LOT-001 / 2027-12-31 / 70개

기존 동일 재고 
의약품 A / 냉장구역 / LOT-002 / 2028-06-30 / 30개
```

정정 대상 재고의 제조번호와 유통기한을 다음과 같이 변경한다.

```
LOT-001 / 2027-12-31
→ LOT-002 / 2028-06-30
```

정정 후 두 재고의 식별값이 모두 같아지므로 다음과 같이 합산한다.

```
정정 대상 재고: 70개 → 0개
기존 동일 재고: 30개 → 100개
```



### 처리 내용

- 정정 대상 재고와 합산 대상 재고를 잠근다(정정 처리하는 동안 다른 사용자가 그 두 재고의 수량을 바꾸지 못하게 막음)
- 정정 대상 재고의 현재 수량을 확인한다.
- 해당 수량을 기존 동일 재고에 합산한다.
- 정정 대상 재고의 수량을 0으로 변경한다.
- 정정 대상 재고를 소진 상태로 처리한다.
- 두 재고의 변경 이력을 생성한다.
- 두 이력은 동일한 `correction_id`로 연결한다.
- 변경 전·후 제조번호, 유통기한 및 정정 사유를 기록한다. 


### 처리 결과

정정 후 동일 재고 존재
```
-> 합산 예정 경고 표시
-> 사용자 확인
-> 기존 동일 재고로 수량 합산
```

## 재고 변동 이력

동일 재고 합산이 발생한 경우 두 개의 재고 변동 이력을 생성한다.

| 대상       | 처리 유형                 | 변경 수량 | 변경 전 수량 | 변경 후 수량 |
| -------- | --------------------- | ----: | ------: | ------: |
| 정정 대상 재고 | `INFO_CORRECTION_OUT` |   -70 |      70 |       0 |
| 기존 동일 재고 | `INFO_CORRECTION_IN`  |   +70 |      30 |     100 |


외부에서 실제 의약품이 입고된 것이 아니므로 일반 입고 유형인 INBOUND로 기록하지 않는다.

## 정정 이력

모든 정보 정정은 별도의 정정 이력을 남긴다.

### 저장 정보

- 정정 ID
- 정정 대상 재고 ID
- 합산 대상 재고 ID
- 정정 전 제조번호
- 정정 후 제조번호
- 정정 전 유통기한
- 정정 후 유통기한
- 정정 전 메모
- 정정 후 메모
- 정정 전 수량
- 정정 후 수량
- 합산 여부
- 이동된 수량
- 정정 사유
- 추가 설명
- 처리자
- 처리 일시
- 연관된 재고 변동 ID

생성된 정정 이력은 수정하거나 삭제할 수 없다.


## 동시성 처리

재고 정보 정정은 재고 수량과 정보를 안전하게 변경하기 위해 비관적 쓰기 잠금을 사용한다.
정정 요청이 들어오면 시스템은 정정 대상 재고를 잠금 상태로 조회한다.

```mysql
SELECT * 
FROM medicine_inventory 
WHERE inventory_id = ?
FOR UPDATE;
```

잠금을 획득한 후 데이터베이스에 저장된 최신 제조번호, 유통기한 및 수량을 기준으로 정정 처리를 진행한다.

### 정정 후 동일 재고가 존재하지 않는 경우

정정 대상 재고만 잠근 상태에서 다음 작업을 처리한다.

- 제조번호 및 유통기한 수정
- 메모 수정
- 정정 이력 저장
- 유통기한 상태 및 관련 알림 재계산

처리가 완료되어 트랜잭션이 종료되면 잠금은 자동으로 해제된다.

### 정정 후 동일 재고가 존재하는 경우

정정 대상 재고와 합산 대상 재고를 모두 잠근다.

```mysql
SELECT * 
FROM medicine_inventory 
WHERE inventory_id IN (?, ?) 
ORDER BY inventory_id 
FOR UPDATE;

```

두 재고를 잠근 후 최신 수량을 다시 조회하여 다음 작업을 처리한다.

- 정정 대상 재고의 최신 수량 확인
- 합산 대상 재고의 최신 수량 확인
- 정정 대상 재고 수량을 합산 대상 재고에 추가
- 정정 대상 재고 수량을 0으로 변경
- 재고변동내역 및 정정 이력 저장


잠금은 항상 inventory_id 오름차순과 같이 일정한 순서로 획득하여 서로 다른 요청이 반대 순서로 재고를 잠그면서 발생할 수 있는 교착 상태를 줄인다.
다른 요청이 해당 재고를 먼저 변경하고 있는 경우 현재 요청은 기존 트랜잭션이 종료될 때까지 대기한다. 
잠금이 해제되면 시스템은 최신 재고 정보를 기준으로 정정 또는 합산을 처리한다.

잠금 대기 시간이 설정된 제한을 초과하면 정정 처리를 중단하고 다음과 같이 안내한다.
> 다른 사용자가 해당 재고를 처리하고 있습니다. 잠시 후 다시 시도해 주세요.

- 재고 수정, 수량 합산, 재고변동내역 생성 및 정정 이력 저장은 하나의 트랜잭션으로 처리한다. 
- 처리 과정에서 오류가 발생하면 모든 변경 사항을 롤백하고 잠금을 해제한다.
- 잠금이 유지되는 동안 외부 API 호출, 알림 발송 등 시간이 오래 걸릴 수 있는 작업은 수행하지 않는다. 
- 알림 발송과 같은 부가 작업은 재고 정정 트랜잭션이 완료된 이후 처리한다.



## 트랜잭션 처리

사용자의 조직 소속, 부서 접근 범위 및 재고 관리 권한을 먼저 확인한다.

권한 검증이 완료되면 다음 처리를 하나의 데이터베이스 트랜잭션으로 수행한다.

- 정정 대상 재고 잠금 및 최신 정보 조회
- 변경 후 동일 재고 조회
- 동일 재고가 존재하는 경우 합산 대상 재고 잠금
- 제조번호 및 유통기한 수정 또는 재고 수량 합산
- 재고변동내역 생성
- 정보 정정 이력 생성
- 유통기한 상태 재계산
- 관련 알림 생성 또는 해제

처리 중 오류가 발생하면 재고 변경과 이력 생성을 모두 롤백한다.




## 에러 처리

| 상황                 | 처리                |
| ------------------ | ----------------- |
| 권한이 없는 사용자         | 정정 요청 거부          |
| 다른 조직의 재고          | 정정 요청 거부          |
| 다른 부서 저장소의 재고      | 정정 요청 거부          |
| 존재하지 않는 재고         | 정정 요청 거부          |
| 폐기 완료 재고           | 정정 요청 거부          |
| 정정 가능한 수량이 없는 재고   | 정정 요청 거부          |
| 변경된 값이 없음          | 정정 요청 거부          |
| 제조번호가 공백           | 입력 오류 안내          |
| 유통기한 형식 오류         | 입력 오류 안내          |
| 동일 재고 존재 후 사용자 취소  | 정정 처리 중단          |
| 잠금 대기 시간 초과        | 잠시 후 다시 시도하도록 안내  |
| 동일 재고 생성 중 중복 키 충돌 | 전체 작업 롤백 후 재시도 안내 |
| 처리 중 오류 발생         | 전체 작업 롤백          |
