# [ 계정 복구 전체 사전 조건 ]

- 비인증 요청의 응답은 계정 존재 여부와 상태를 노출하지 않도록 동일하게 표현한다.
- 인증 코드·토큰은 용도별로 분리하고 다른 복구 기능에 재사용하지 않는다.
- 원문 토큰과 인증 코드는 저장하지 않고 해시값, 만료 일시, 사용 여부만 저장한다.
- 발급 횟수, 입력 실패 횟수, IP·계정별 요청 빈도를 제한한다.
- 새 코드를 발급하면 같은 용도의 기존 코드·토큰을 무효화한다.
- 성공·실패 이력에는 비밀번호, 코드, 토큰 원문을 남기지 않는다.

# 📝 1.3.1 비밀번호 재설정 요청

## 기능 목적

> 비밀번호를 잊은 회원에게 등록 이메일로 재설정 링크 또는 인증 코드를 보낸다.

## 사용자 및 권한

- 비인증 사용자

## 사전 조건

- 가입 이메일에 해당하는 계정이 존재해야 한다.
- 대상 계정이 `WITHDRAWN` 상태가 아니어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `email` | String | O | 가입 시 등록한 이메일 |
| `method` | Enum | O | `LINK` 또는 `CODE` |

## 처리 절차

1. 입력 형식을 검증하고 이메일에 해당하는 계정을 조회한다.
2. 대상이 복구 가능한 상태인지 확인한다.
3. `LINK`이면 암호학적으로 안전한 일회용 토큰을, `CODE`이면 6자리 일회용 코드를 생성한다.
4. 해시값, 용도, 만료 일시, 사용 여부를 저장한다.
5. 등록 이메일로 링크 또는 코드를 발송한다.
6. 계정 존재 여부와 관계없이 동일한 접수 응답을 반환한다.

## 업무 규칙

| 방식 | 기본 유효시간 | 전달 내용 |
| --- | --- | --- |
| `LINK` | 15분 | HTTPS 재설정 주소와 일회용 토큰 |
| `CODE` | 5분 | 6자리 일회용 코드 |

- 재설정 링크는 허용된 서비스 도메인만 사용하며 토큰을 서버 로그나 분석 도구에 남기지 않는다.
- 메일에는 비밀번호나 민감한 계정 정보를 포함하지 않는다.
- `ACTIVE`, `LOCKED`, `INACTIVE` 계정은 비밀번호를 재설정할 수 있으나 상태는 그대로 유지한다.
- `WITHDRAWN` 계정에는 링크나 코드를 발송하지 않는다.

## 처리 결과

- [ ] 등록 이메일로 재설정 링크 또는 인증 코드가 발송된다.
- [ ] 계정 존재 여부와 관계없이 동일한 접수 응답을 반환한다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 입력 형식 오류 | 입력값 오류를 반환한다. |
| 계정 또는 등록 이메일 불일치 | 일반화된 접수 결과를 반환하고 발송하지 않는다. |
| 요청 횟수 초과 | 일정 시간 요청을 제한한다. |
| 이메일 발송 실패 | 내부 오류를 기록하고 재시도 정책을 적용한다. |

# 📝 1.3.2 비밀번호 재설정 코드 확인

## 기능 목적

> 이메일 인증 코드를 확인하고 비밀번호 변경 전용 토큰을 발급한다.

## 사용자 및 권한

- 비인증 사용자

## 사전 조건

- `CODE` 방식으로 발급한 유효한 인증 코드가 있어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `email` | String | O | 가입 시 등록한 이메일 |
| `verificationCode` | String | O | 이메일 인증 코드 |

## 처리 절차

1. 코드의 일치 여부, 용도, 만료, 사용 여부, 실패 횟수를 확인한다.
2. 코드를 사용 완료 처리한다.
3. 비밀번호 변경 전용 `passwordResetToken`을 발급한다.

## 업무 규칙

- 코드 자체를 비밀번호 변경 권한으로 사용하지 않는다.
- 재설정 토큰의 기본 유효시간은 10분이다.
- 재설정 토큰은 한 번만 사용할 수 있다.

## 처리 결과

- [ ] 비밀번호 변경 전용 일회용 토큰이 발급된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 코드 불일치·만료·사용 완료 | 인증 코드 오류를 반환한다. |
| 실패 횟수 초과 | 일정 시간 코드 확인을 제한한다. |

# 📝 1.3.3 새 비밀번호 설정

## 기능 목적

> 유효한 재설정 토큰으로 새 비밀번호를 설정한다.

## 사용자 및 권한

- 유효한 재설정 토큰을 가진 사용자

## 사전 조건

- 재설정 토큰이 유효하고 사용되지 않은 상태여야 한다.
- 대상 계정이 `WITHDRAWN` 상태가 아니어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `passwordResetToken` | String | O | 링크 토큰 또는 코드 확인 후 발급된 토큰 |
| `newPassword` | String | O | 6~64자, 비밀번호 정책 준수 |

## 처리 절차

1. 토큰의 서명 또는 해시, 용도, 만료, 사용 여부를 확인한다.
2. 대상 계정이 `WITHDRAWN`이 아닌지 확인한다.
3. 새 비밀번호가 기존 비밀번호와 다른지 확인한다.
4. 새 비밀번호를 단방향 해시해 저장한다.
5. 토큰을 사용 완료 처리하고 해당 계정의 다른 재설정 토큰을 모두 무효화한다.
6. 기존 Refresh Token을 모두 폐기하고 계정 소유자에게 변경 완료 메일을 보낸다.

## 업무 규칙

- 비밀번호 변경과 토큰 사용 완료 처리는 하나의 트랜잭션으로 처리한다.
- 비밀번호 재설정으로 `LOCKED` 또는 `INACTIVE` 상태가 해제되지 않는다.

## 처리 결과

- [ ] 새 비밀번호가 저장된다.
- [ ] 재설정 토큰과 기존 Refresh Token이 폐기된다.
- [ ] 등록 이메일로 변경 완료 알림이 발송된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 토큰 불일치·만료·사용 완료 | 재설정 토큰 오류를 반환한다. |
| 비밀번호 정책 위반 | 입력값 오류를 반환한다. |
| 기존 비밀번호와 동일 | 동일 비밀번호 오류를 반환한다. |
| 처리 중 오류 발생 | 비밀번호 변경과 토큰 처리를 모두 롤백한다. |

# 📝 1.3.4 비활성 계정 재활성화

## 기능 목적

> 계정 소유자가 등록 이메일 인증 후 `INACTIVE` 계정을 `ACTIVE`로 변경한다.

## 사용자 및 권한

- 이메일 인증을 완료한 계정 소유자

## 사전 조건

- 대상 계정이 `INACTIVE` 상태여야 한다.
- 가입 시 등록한 이메일을 수신할 수 있어야 한다.

## 입력값

| 단계 | 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | --- | :---: | --- |
| 코드 요청 | `email` | String | O | 가입 시 등록한 이메일 |
| 재활성화 | `email`, `verificationCode` | String | O | 가입 이메일과 일회용 코드 |

## 처리 절차

1. 코드 요청 시 계정과 이메일을 확인하고 재활성화 전용 코드를 발송한다.
2. 확인 시 코드의 일치 여부, 용도, 만료, 사용 여부를 검증한다.
3. 계정이 `INACTIVE`인지 다시 확인한다.
4. 상태를 `ACTIVE`로 변경하고 코드 사용 완료 및 수정 일시를 기록한다.

## 업무 규칙

- `INACTIVE` 계정만 이 기능으로 재활성화한다.
- `LOCKED` 계정의 잠금은 해제하지 않는다.
- `WITHDRAWN` 계정은 재활성화할 수 없다.
- 요청 응답으로 계정 존재 여부나 상태를 노출하지 않는다.
- 관리자 재활성화는 [2. 회원 권한.md](./2.%20회원%20권한.md)의 상태 변경 정책을 따른다.

## 처리 결과

- [ ] 계정 상태가 `ACTIVE`로 변경된다.
- [ ] 인증 코드가 사용 완료 처리된다.
- [ ] 수정 일시가 갱신된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 계정 또는 이메일 불일치 | 코드 요청 시 일반화된 결과를 반환한다. |
| 인증 코드 불일치·만료·사용 완료 | 인증 코드 오류를 반환한다. |
| 계정이 `INACTIVE` 상태가 아님 | 상태 변경을 거부한다. |
| 실패 횟수 초과 | 일정 시간 코드 확인을 제한한다. |
