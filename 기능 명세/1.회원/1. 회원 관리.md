# 📝 1.1.1 회원가입

## 기능 목적

비인증 사용자가 이름, 이메일, 비밀번호를 등록해 계정을 생성한다.

## 사용자 및 권한

- 비인증 사용자

## 사전 조건

- 사용할 이메일이 등록되어 있지 않아야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `name` | String | O | 최대 100자 |
| `email` | String | O | 올바른 이메일 형식, 최대 254자, 중복 불가 |
| `password` | String | O | 6~64자, 서비스의 비밀번호 정책 준수 |

## 처리 절차

1. 입력 형식을 검증한다.
2. 이메일의 중복 여부를 확인한다.
3. 외부 식별용 UUID를 생성한다.
4. 비밀번호를 단방향 해시한 뒤 계정을 저장한다.
5. 권한을 `USER`, 상태를 `ACTIVE`로 설정한다.
6. 생성 일시와 수정 일시를 기록한다.

## 업무 규칙

- 이메일은 계정 로그인과 본인 확인에 사용하며 UUID나 DB 내부 `id`와 구분한다.
- UUID는 외부 계정 식별자와 JWT Subject로 사용하며 생성 후 변경하지 않는다.
- 이메일은 로그인, 비밀번호 재설정, 비활성 계정 재활성화에 사용한다.
- 비밀번호 원문은 저장하거나 로그에 남기지 않는다.
- 일반 회원가입 요청으로 `ADMIN` 권한을 생성할 수 없다.
- 사전 중복 확인 여부와 관계없이 저장 직전에 중복을 다시 확인한다.
- DB에도 이메일 Unique 제약조건을 적용한다.

## 처리 결과

- [ ] `USER` 권한과 `ACTIVE` 상태를 가진 계정이 생성된다.
- [ ] 비밀번호를 제외한 계정 생성 결과를 반환한다.

## 예외 처리

| 조건 | 처리 |
| --- | --- |
| 입력값이 정책을 만족하지 않음 | 입력값 오류를 반환한다. |
| 이메일이 이미 사용 중임 | 이메일 중복 오류를 반환한다. |
| 저장 중 Unique 제약조건 위반 발생 | 해당 항목의 중복 오류를 반환한다. |

# 📝 1.1.2 이메일 중복 확인

## 기능 목적

> 회원가입 전에 계정 생성 전체 정보가 아닌 이메일만 입력해 사용 가능 여부를 확인한다.

## 사용자 및 권한

- 비인증 사용자
- `USER`
- `ADMIN`

## 사전 조건

- 확인할 이메일이 이메일 형식을 만족해야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `email` | String | O | 공백 불가, 올바른 이메일 형식, 최대 254자 |

## 처리 절차

1. 이메일 입력 형식을 검증한다.
2. 동일한 이메일을 가진 계정이 있는지 확인한다.
3. 사용 가능 여부만 반환한다.

## 업무 규칙

- 중복 확인은 값을 예약하지 않으며 회원가입 성공을 보장하지 않는다.
- 이름, 비밀번호 등 다른 계정 생성 정보는 입력받지 않는다.
- 다른 계정 정보는 반환하지 않는다.
- 탈퇴 시 제거된 이메일의 재사용 허용 여부는 별도 보존 정책을 따른다.

## 처리 결과

| 결과 | 설명 |
| --- | --- |
| 사용 가능 | 동일한 이메일이 존재하지 않는다. |
| 사용 불가 | 동일한 이메일이 존재한다. |

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 이메일이 없거나 형식이 올바르지 않음 | 입력값 오류를 반환한다. |

# 📝 1.1.3 내 계정 조회

## 기능 목적

> 인증된 사용자가 자신의 계정 정보를 조회한다.

## 사용자 및 권한

인증된 `USER`, `ADMIN`

## 사전 조건

- 인증 정보가 유효해야 한다.
- JWT Subject에 해당하는 계정이 존재해야 한다.

## 입력값

- 별도 계정 식별자를 입력받지 않고 JWT Subject(UUID)로 본인을 식별한다.

## 처리 절차

1. 인증 정보를 검증한다.
2. JWT Subject(UUID)로 본인 계정을 조회한다.
3. 허용된 계정 정보만 반환한다.

## 업무 규칙

- DB 내부 `id`, 비밀번호, 비밀번호 해시는 반환하지 않는다.
- 요청에서 다른 사용자의 UUID를 받지 않는다.

## 처리 결과

- [ ] UUID, 이름, 이메일, 권한, 계정 상태, 생성 일시, 수정 일시, 탈퇴 일시를 반환한다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 인증 정보가 유효하지 않음 | 인증 오류를 반환한다. |
| 계정이 존재하지 않음 | 계정 조회 오류를 반환한다. |

# 📝 1.1.4 내 계정 수정

## 기능 목적

> 인증된 사용자가 자신의 이름 또는 비밀번호를 변경한다.

## 사용자 및 권한

- `USER`: 자신의 계정만 수정할 수 있다.
- `ADMIN`: 자신의 계정만 수정할 수 있다.

## 사전 조건

- 인증된 `USER`, `ADMIN`이 자신의 `ACTIVE` 계정만 수정할 수 있다.
- 이름 또는 새 비밀번호 중 하나 이상을 입력해야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `name` | String | X | 입력 시 1~100자 |
| `password` | String | X | 입력 시 6~64자, 변경할 새 비밀번호 |

## 처리 절차

1. JWT Subject로 본인 계정을 조회하고 상태를 확인한다.
2. 변경할 입력값을 검증한다.
3. 비밀번호 변경 시 새 비밀번호가 현재 비밀번호와 다른지 확인한다.
4. 새 비밀번호를 단방향 해시한다.
5. 변경값을 저장하고 수정 일시를 갱신한다.

## 업무 규칙

- 이메일, UUID, 권한, 상태는 이 기능으로 변경하지 않는다.
- `ADMIN`도 다른 회원의 이름이나 비밀번호를 직접 변경할 수 없다.
- 입력한 비밀번호는 저장하거나 로그에 남기지 않는다.
- 비밀번호 변경 후 기존 세션의 유지 여부는 인증 토큰 정책을 따른다.

## 처리 결과

- [ ] 요청한 이름 또는 비밀번호가 변경된다.
- [ ] 수정 일시가 갱신된다.

## 예외 처리

| 조건 | 처리 |
| --- | --- |
| 인증이 유효하지 않음 | 인증 오류를 반환한다. |
| 계정이 없거나 `ACTIVE`가 아님 | 계정 수정을 거부한다. |
| 변경할 값이 없음 | 입력값 오류를 반환한다. |
| 새 비밀번호가 현재 비밀번호와 같음 | 동일 비밀번호 오류를 반환한다. |
| 저장 실패 | 전체 변경을 롤백한다. |

# 📝 1.1.5 계정 탈퇴

## 기능 목적

> 계정 소유자가 본인 확인 후 계정을 탈퇴하고 개인정보를 제거한다.

## 사용자 및 권한

- `USER`: 자신의 계정을 탈퇴할 수 있다.
- `ADMIN`: 자신의 계정을 탈퇴할 수 있다.

## 사전 조건

- 계정 소유자가 본인 확인 후 자신의 계정을 탈퇴한다.
- `ACTIVE`, `LOCKED`, `INACTIVE` 계정은 탈퇴할 수 있다.
- `WITHDRAWN` 계정은 다시 탈퇴하거나 복구할 수 없다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `password` | String | O | 공백 불가, 6~64자, 현재 비밀번호를 통한 본인 확인 |

`LOCKED` 또는 `INACTIVE` 상태로 비밀번호 인증이 불가능하면 별도의 본인 확인 수단을 사용한다. 임의의 UUID로 다른 계정을 탈퇴시킬 수 없어야 한다.

## 처리 절차

1. 대상 계정과 요청자의 소유 관계를 확인한다.
2. 비밀번호 또는 별도 수단으로 본인을 확인한다.
3. 상태를 `WITHDRAWN`으로 변경한다.
4. 이름, 이메일, 비밀번호 등 개인정보를 제거하거나 복구 불가능하게 처리한다.
5. Refresh Token을 모두 폐기하고 Access Token 차단 정책을 적용한다.
6. 탈퇴 일시와 수정 일시를 기록한다.

## 업무 규칙

- 상태 변경, 개인정보 제거, 토큰 폐기는 가능한 범위에서 하나의 트랜잭션으로 처리한다.
- 이력 연결을 위해 DB 내부 `id`와 UUID는 유지할 수 있다.
- 탈퇴한 계정의 로그인과 재활성화를 허용하지 않는다.
- 이메일의 재사용 시점은 개인정보 보존 및 부정 가입 방지 정책을 따른다.
- Access Token의 즉시 차단은 블랙리스트, 계정별 토큰 버전, 보호 자원 요청 시 상태 확인 중 정한 정책을 사용한다.

## 처리 결과

- [ ] 계정 상태가 `WITHDRAWN`으로 변경된다.
- [ ] 개인정보와 인증 토큰이 정책에 따라 처리된다.
- [ ] 탈퇴 일시와 수정 일시가 기록된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 계정이 존재하지 않음 | 계정 조회 오류를 반환한다. |
| 요청자가 계정 소유자가 아님 | 권한 없음을 반환한다. |
| 본인 확인 실패 | 본인 확인 오류를 반환한다. |
| 이미 `WITHDRAWN` 상태임 | 중복 탈퇴를 거부한다. |
| 처리 중 오류 발생 | 상태 변경과 개인정보 제거를 롤백한다. |
