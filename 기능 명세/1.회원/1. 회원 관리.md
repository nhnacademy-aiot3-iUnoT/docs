# 📝 1.1 계정 생성

## 기능 목적

> 이름, 이메일, 비밀번호를 입력받아 신규 계정을 생성한다.


## 사용자 및 권한

* 비인증 사용자


## 사전 조건

* 동일한 이메일을 사용하는 계정이 없어야 한다.


## 입력값

| 항목         | 형식  | 필수 여부 | 설명            |
| ---------- | --- | :---: | ------------- |
| `name`     | 문자열 |   O   | 최대 16자        |
| `email`    | 이메일 |   O   | 최대 32자, 중복 불가 |
| `password` | 문자열 |   O   | 6자 이상 64자 이하  |


## 처리 절차

1. 입력값과 이메일 중복 여부를 검증한다.
2. UUID를 생성하고 비밀번호를 해싱한다.
3. 계정을 `ACTIVE` 상태로 저장한다.


## 업무 규칙

* UUID는 외부 식별자와 JWT Subject로 사용하며 변경할 수 없다.
* 비밀번호는 평문으로 저장하지 않는다.
* 생성 시 `createdAt`, `updatedAt`을 기록한다.

## 처리 결과

* `ACTIVE` 상태의 신규 계정이 생성된다.


## 예외 처리

| 예외 조건                 | 처리               |
| --------------------- | ---------------- |
| 입력값이 제약사항을 만족하지 않는 경우 | 입력값 오류를 반환한다.    |
| 이메일이 중복된 경우           | 이메일 중복 오류를 반환한다. |

# 📝 1.2 계정 정보 조회

## 기능 목적

> 인증된 사용자가 자신의 계정 정보를 조회한다.


## 사용자 및 권한

* 인증된 사용자


## 사전 조건

* 사용자 식별 정보에 해당하는 계정이 존재해야 한다.


## 입력값

| 항목        | 형식   | 필수 여부 | 설명                       |
| --------- | ---- | :---: | ------------------------ |
| 사용자 식별 정보 | UUID |   O   | JWT Subject로 전달되는 외부 식별자 |


## 처리 절차

1. UUID로 계정을 조회한다.
2. 조회된 계정 정보를 반환한다.


## 업무 규칙

* DB 내부 식별자인 `id`는 외부에 사용하지 않는다.
* 탈퇴 계정은 이름, 이메일, 비밀번호 정보를 보유하지 않는다.


## 처리 결과

* 사용자 계정 정보가 반환된다.


## 예외 처리

| 예외 조건          | 처리              |
| -------------- | --------------- |
| 계정이 존재하지 않는 경우 | 계정 조회 오류를 반환한다. |

# 📝 1.3 계정 정보 수정

## 기능 목적

> 사용자의 이름, 이메일 또는 비밀번호를 변경한다.


## 사용자 및 권한

* 인증된 사용자


## 사전 조건

* 계정 상태가 `ACTIVE`여야 한다.


## 입력값

| 항목         | 형식  |  필수 여부 | 설명            |
| ---------- | --- | :----: | ------------- |
| `name`     | 문자열 | 변경 시 O | 최대 16자        |
| `email`    | 이메일 | 변경 시 O | 최대 32자, 중복 불가 |
| `password` | 문자열 | 변경 시 O | 6자 이상 64자 이하  |


## 처리 절차

1. 계정 상태와 입력값을 검증한다.
2. 변경된 정보를 반영한다.
3. 비밀번호 변경 시 해싱하여 저장한다.
4. `updatedAt`을 갱신한다.


## 업무 규칙

* `ACTIVE` 상태의 계정만 수정할 수 있다.
* UUID와 `createdAt`은 변경할 수 없다.


## 처리 결과

* 계정 정보와 수정 일시가 갱신된다.


## 예외 처리

| 예외 조건                  | 처리               |
| ---------------------- | ---------------- |
| 계정이 존재하지 않는 경우         | 계정 수정 오류를 반환한다.  |
| 계정 상태가 `ACTIVE`가 아닌 경우 | 수정을 거부한다.        |
| 입력값이 제약사항을 만족하지 않는 경우  | 입력값 오류를 반환한다.    |
| 이메일이 중복된 경우            | 이메일 중복 오류를 반환한다. |

# 📝 1.4 계정 잠금 및 잠금 해제

## 기능 목적

> 계정의 로그인을 차단하거나 잠금을 해제한다.


## 사용자 및 권한

* 계정 상태 변경 권한을 가진 사용자 또는 시스템


## 사전 조건

* 대상 계정이 존재해야 한다.


## 입력값

| 항목       | 형식         | 필수 여부 | 설명        |
| -------- | ---------- | :---: | --------- |
| 계정 식별 정보 | UUID       |   O   | 대상 계정 식별자 |
| 변경 동작    | 잠금 / 잠금 해제 |   O   | 수행할 상태 변경 |


## 처리 절차

1. 계정의 현재 상태를 확인한다.
2. 잠금 시 `ACTIVE`를 `LOCKED`로 변경한다.
3. 잠금 해제 시 `LOCKED`를 `ACTIVE`로 변경한다.
4. `updatedAt`을 갱신한다.

## 업무 규칙

* `ACTIVE` 계정만 잠글 수 있다.
* `LOCKED` 계정만 잠금을 해제할 수 있다.
* `LOCKED` 계정은 로그인할 수 없다.


## 처리 결과

* 계정 상태와 수정 일시가 갱신된다.


## 예외 처리

| 예외 조건                   | 처리              |
| ----------------------- | --------------- |
| 허용되지 않은 상태에서 변경을 요청한 경우 | 상태 변경을 거부한다.    |
| 계정이 존재하지 않는 경우          | 계정 조회 오류를 반환한다. |

# 📝 1.5 계정 비활성화 및 재활성화

## 기능 목적

> 계정을 비활성화하거나 다시 활성화한다.


## 사용자 및 권한

* 계정 상태 변경 권한을 가진 사용자 또는 시스템


## 사전 조건

* 대상 계정이 존재해야 한다.


## 입력값

| 항목       | 형식          | 필수 여부 | 설명        |
| -------- | ----------- | :---: | --------- |
| 계정 식별 정보 | UUID        |   O   | 대상 계정 식별자 |
| 변경 동작    | 비활성화 / 재활성화 |   O   | 수행할 상태 변경 |


## 처리 절차

1. 계정의 현재 상태를 확인한다.
2. 비활성화 시 `ACTIVE`를 `INACTIVE`로 변경한다.
3. 재활성화 시 `INACTIVE`를 `ACTIVE`로 변경한다.
4. `updatedAt`을 갱신한다.


## 업무 규칙

* `ACTIVE` 계정만 비활성화할 수 있다.
* `INACTIVE` 계정만 재활성화할 수 있다.
* 정의되지 않은 상태 전이는 허용하지 않는다.


## 처리 결과

* 계정 상태와 수정 일시가 갱신된다.


## 예외 처리

| 예외 조건                   | 처리              |
| ----------------------- | --------------- |
| 허용되지 않은 상태에서 변경을 요청한 경우 | 상태 변경을 거부한다.    |
| 계정이 존재하지 않는 경우          | 계정 조회 오류를 반환한다. |

# 📝 1.6 계정 탈퇴

## 기능 목적

> 계정을 탈퇴 상태로 변경하고 개인정보를 제거한다.

## 사용자 및 권한

* 인증된 사용자


## 사전 조건

* 계정이 존재하며 `WITHDRAWN` 상태가 아니어야 한다.

## 입력값

| 항목        | 형식   | 필수 여부 | 설명           |
| --------- | ---- | :---: | ------------ |
| 사용자 식별 정보 | UUID |   O   | 탈퇴 대상 계정 식별자 |


## 처리 절차

1. 계정 상태를 `WITHDRAWN`으로 변경한다.
2. 이름, 이메일, 비밀번호 정보를 제거한다.
3. `withdrawnAt`과 `updatedAt`을 기록한다.

## 업무 규칙

* `ACTIVE`, `LOCKED`, `INACTIVE` 계정은 탈퇴할 수 있다.
* `WITHDRAWN`은 복구할 수 없는 최종 상태이다.
* 계정 식별을 위해 `id`와 UUID는 유지한다.

## 처리 결과

* 계정이 탈퇴 처리되고 개인정보가 제거된다.


## 예외 처리

| 예외 조건          | 처리              |
| -------------- | --------------- |
| 계정이 존재하지 않는 경우 | 계정 조회 오류를 반환한다. |
| 이미 탈퇴한 계정인 경우  | 중복 탈퇴 요청을 거부한다. |
