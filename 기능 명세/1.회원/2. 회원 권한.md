# 👤 1.2 회원 권한과 관리자 기능

> [회원 전체 흐름](./0.회원%20전체%20흐름.md)의 소스 확인 기준을 따른다. Account의 계정 권한과 Inventory의 조직 역할은 별개다.

---

# 👤 1.2.1 회원 권한 정의

## 권한 정의

| 권한 | 현재 허용 기능 |
| --- | --- |
| `USER` | 본인 정보 조회·이름 수정·비밀번호 변경·탈퇴, 비활성 계정 재활성화 |
| `ADMIN` | 본인 기능, 전체 회원 조회·상세 조회, 관리자 생성, 대상 회원 이름 수정·비밀번호 재설정·상태 변경·비밀번호 확인을 통한 탈퇴 |

## 업무 규칙

- 일반 초대 가입은 `USER`, 관리자 생성 API는 `ADMIN`으로 생성한다.
- 관리자 API는 JWT `ROLE_ADMIN` 확인에 더해 DB의 요청자 계정이 `ADMIN`이고 `ACTIVE`인지 다시 검사한다.
- 관리자는 대상 회원의 이름과 비밀번호를 실제로 변경할 수 있다. 이메일이나 기존 계정의 권한을 변경하는 API는 없다.
- 계정 `ADMIN`을 조직 `OWNER`·`BOSS`와 같은 역할로 취급하지 않는다.

# 👤 1.2.2 계정 상태 정의

## 상태 정의

| 상태 | 의미 | Account 로그인·토큰 갱신 |
| --- | --- | --- |
| `ACTIVE` | 정상 계정 | 가능 |
| `LOCKED` | 잠금 상태 | 거부 |
| `INACTIVE` | 비활성 상태 | 가능. Front에서 재활성화 화면으로 안내 |
| `WITHDRAWN` | 탈퇴 상태 | 거부. 이메일·비밀번호 해시가 제거됨 |

## 상태 전이

| 동작 | 현재 상태 → 결과 | 수행 경로 |
| --- | --- | --- |
| `LOCK` | `ACTIVE` → `LOCKED` | 활성 관리자 API |
| `UNLOCK` | `LOCKED` → `ACTIVE` | 활성 관리자 API |
| `DEACTIVATE` | `ACTIVE` → `INACTIVE` | 활성 관리자 API |
| `REACTIVATE` | `INACTIVE` → `ACTIVE` | 활성 관리자 API 또는 본인의 이메일 링크 인증 |
| 탈퇴 | `ACTIVE`·`LOCKED`·`INACTIVE` → `WITHDRAWN` | 본인·관리자 탈퇴 API 또는 내부 삭제 API의 조건 충족 시 |

## 업무 규칙

- 표와 다른 상태 변경은 `409 A006`이다.
- `WITHDRAWN`을 되돌리는 전이는 없다.
- 자동 휴면·자동 잠금 스케줄러나 상태 변경 감사 이력 저장은 확인한 Account 코드에서 구현 근거를 찾지 못했다.

# 📝 1.2.3 관리자 회원 조회

## 기능 목적

> 관리자가 전체 회원 목록 또는 특정 회원의 정보를 조회한다.

## 사용자 및 권한

- JWT `ROLE_ADMIN` 권한이 있고, DB의 요청자 계정이 `ADMIN`·`ACTIVE`인 관리자.

## 사전 조건

- 상세 조회는 대상 UUID에 해당하는 계정이 존재해야 한다.
- 목록·상세 조회에는 탈퇴 계정도 포함한다.

## 입력값

API: 목록 `GET /api/accounts/admin`, 상세 `GET /api/accounts/admin/{uuid}`

DTO: 없음. 목록 조회는 Path·Query·Body 입력이 없고 상세 조회는 Path의 UUID를 사용한다.

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `uuid` | UUID, Path | O (상세) | 상세 조회할 대상 계정 UUID |

## 처리 절차

1. 관리자 자격을 확인한다.
2. 목록 요청이면 전체 회원 목록을, 상세 요청이면 대상 UUID의 계정을 조회한다.

## 업무 규칙

- Account 목록 API는 전체 목록을 반환하며 페이지·검색 조건을 받지 않는다.
- Front `/admin/users`가 이 목록에 이름·이메일 검색, 권한·상태 필터, 정렬, 페이지 나누기를 적용한다. Front 페이지 크기는 10·20·50 중 선택한다.
- 탈퇴 계정의 외부 응답에서는 이름·이메일을 null로 가린다. 비밀번호 해시와 내부 ID는 노출하지 않는다.

## 처리 결과

| 구분 | 처리 결과 |
| --- | --- |
| 목록 | 전체 계정 목록을 `200 OK`, `ApiResponse<List<AccountResponse>>`로 반환한다. |
| 상세 | 대상 계정 정보를 `200 OK`, `ApiResponse<AccountResponse>`로 반환한다. |

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 요청자 또는 상세 조회 대상 계정 없음 | `404 A001` |
| 관리자 자격 미충족 | `403 AU006` |

# 📝 1.2.4 관리자 상태 변경

## 기능 목적

> 관리자가 허용된 상태 전이에 따라 대상 회원의 상태를 변경한다.

## 사용자 및 권한

- JWT `ROLE_ADMIN` 권한이 있고, DB의 요청자 계정이 `ADMIN`·`ACTIVE`인 관리자.

## 사전 조건

- 대상 계정이 존재하고 요청한 상태 전이가 허용되어야 한다.

## 입력값

API: `PUT /api/accounts/admin/{uuid}/status`

DTO: `ChangeAccountStatusRequest`

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `uuid` | UUID, Path | O | 변경할 대상 계정 |
| `action` | AccountStatusAction, Body | O | `LOCK`, `UNLOCK`, `DEACTIVATE`, `REACTIVATE` |
| `reason` | String, Body | O | 공백 불가. DTO에 길이 제한은 없음 |

## 처리 절차

1. 요청자의 활성 관리자 자격을 확인한다.
2. 대상 계정과 상태 전이를 확인한다.
3. 계정 상태를 갱신한다.

## 업무 규칙

- `reason`은 입력 검증만 수행하며 현재 서비스에서 저장·감사 로그 기록에 사용하지 않는다.
- 자기 계정 상태 변경을 별도로 막는 조건은 없다.
- 역할 변경이나 모든 인증 토큰 폐기는 이 처리에 포함되지 않는다.

## 처리 결과

- 요청한 동작에 따라 대상 계정의 상태가 변경된다.
- Account는 `200 OK`, `ApiResponse<AccountResponse>`를 반환한다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 입력 오류 | `400 G001` |
| 요청자 또는 대상 계정 없음 | `404 A001` |
| 관리자 자격 미충족 | `403 AU006` |
| 허용되지 않은 상태 전이 | `409 A006`. 계정 상태 정의의 전이 규칙을 따른다. |

# 📝 1.2.5 관리자 계정 생성

## 기능 목적

> 관리자가 새로운 관리자 계정을 생성한다.

## 사용자 및 권한

- JWT `ROLE_ADMIN` 권한이 있고, DB의 요청자 계정이 `ADMIN`·`ACTIVE`인 관리자.

## 사전 조건

- 새 계정에 사용할 이메일이 기존 계정과 중복되지 않아야 한다.

## 입력값

API: `POST /api/accounts/admin`

DTO: `CreateAdminAccountRequest`

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `name` | String | O | 공백 불가, 최대 100자 |
| `email` | String | O | 공백 불가·이메일 형식·최대 254자 |
| `password` | String | O | 공백 불가·6~64자 |

## 처리 절차

1. 관리자 자격과 입력값을 확인한다.
2. 이메일 정규화·BCrypt·이메일 고유 제약을 적용한다.
3. `ADMIN`, `ACTIVE` 계정을 만든다.

## 업무 규칙

- 초대 토큰을 요구하지 않는다.

## 처리 결과

- `ADMIN`, `ACTIVE` 계정이 생성된다.
- Account는 `200 OK`, `ApiResponse<AccountResponse>`를 반환한다. 일반 회원가입은 `201 Created`를 반환한다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 입력 오류 | `400 G001` |
| 요청자 계정 없음 | `404 A001` |
| 이메일 중복 | `409 A002` |
| 관리자 자격 미충족 | `403 AU006` |

# 📝 1.2.6 관리자에 의한 이름 수정

## 기능 목적

> 관리자가 대상 회원의 이름을 수정한다.

## 사용자 및 권한

- JWT `ROLE_ADMIN` 권한이 있고, DB의 요청자 계정이 `ADMIN`·`ACTIVE`인 관리자.

## 사전 조건

- 대상 계정이 `ACTIVE`여야 한다.

## 입력값

API: `PUT /api/accounts/admin/{uuid}`

DTO: `UpdateAccountNameRequest`

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `uuid` | UUID, Path | O | 대상 계정 UUID |
| `name` | String, Body | O | 공백 불가·1~100자 |

## 처리 절차

2. 대상 계정과 `ACTIVE` 상태를 확인한다.

## 업무 규칙

## 처리 결과

| 관리자 자격 미충족 | `403 AU006` |
| 변경 불가 상태 | `409 A006` |

# 📝 1.2.7 관리자 비밀번호 재설정

## 기능 목적

> 관리자가 대상 회원의 비밀번호를 재설정한다.

## 사용자 및 권한

- JWT `ROLE_ADMIN` 권한이 있고, DB의 요청자 계정이 `ADMIN`·`ACTIVE`인 관리자.

## 사전 조건

- 대상 계정이 `ACTIVE`여야 한다.

## 입력값

API: `PUT /api/accounts/admin/{uuid}/pwd`

DTO: `AdminResetPasswordRequest`

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `uuid` | UUID, Path | O | 대상 계정 UUID |
| `password` | String, Body | O | 공백 불가·6~64자 |

## 처리 절차

1. 요청자의 활성 관리자 자격을 확인한다.
2. 대상 계정의 존재 여부와 `ACTIVE` 상태를 확인한다.
3. 새 비밀번호의 BCrypt 해시를 저장한다.

## 업무 규칙

- 관리자 재설정은 대상의 현재 비밀번호를 요구하지 않고 동일 비밀번호 여부도 비교하지 않는다.
- 전체 Refresh Token 폐기나 변경 알림 메일 발송은 연결되어 있지 않다.

## 처리 결과

- 대상 계정에 새 비밀번호의 BCrypt 해시가 저장된다.
- Account는 `200 OK`, `ApiResponse<AccountResponse>`를 반환한다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 입력 오류 | `400 G001` |
| 요청자 또는 대상 계정 없음 | `404 A001` |
| 관리자 자격 미충족 | `403 AU006` |
| 대상 계정이 `ACTIVE`가 아님 | `409 A006` |

# 📝 1.2.8 관리자 회원 탈퇴

## 기능 목적

> 관리자가 대상 계정의 현재 비밀번호를 확인하고 탈퇴 처리한다.

## 사용자 및 권한

- JWT `ROLE_ADMIN` 권한이 있고, DB의 요청자 계정이 `ADMIN`·`ACTIVE`인 관리자.

## 사전 조건

- **대상 계정의 현재 비밀번호**가 필요하다.

## 입력값

API: `DELETE /api/accounts/admin/{uuid}`

DTO: `WithdrawAccountRequest`

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `uuid` | UUID, Path | O | 대상 계정 UUID |
| `password` | String, Body | O | 대상 계정의 현재 비밀번호, 공백 불가·6~64자 |

## 처리 절차

1. 요청자의 활성 관리자 자격을 확인한다.
2. 대상 계정을 조회하고 대상 계정의 현재 비밀번호를 검증한다.
3. Inventory 조직 탈퇴를 처리한다.
4. Account 탈퇴를 처리한다.

## 업무 규칙

- 현재 구현은 본인 탈퇴와 같은 서비스 메서드를 사용한다. 관리자 자신의 비밀번호나 비밀번호 없는 강제 탈퇴 요청이 아니다.
- Front `AdminUserController`에는 이 탈퇴 동작의 화면 라우트가 없다.

## 처리 결과

- 대상 계정이 `WITHDRAWN`으로 변경되고 이메일·비밀번호 해시가 제거된다.
- Account는 `200 OK`, `ApiResponse<Void>`를 반환한다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 입력 오류 | `400 G001` |
| 요청자 또는 대상 계정 없음 | `404 A001` |
| 관리자 자격 미충족 | `403 AU006` |
| 대상 계정의 현재 비밀번호 불일치 | `400 A008` |
| Inventory 조직 탈퇴 실패 | `502 G004`. Account 탈퇴로 진행하지 않는다. |
| 이미 `WITHDRAWN`인 계정 | 엔티티는 `409 A006`으로 거부한다. 현재 비밀번호를 먼저 검증하므로 외부 API에서 이 오류가 항상 먼저 반환되는 것은 아니다. |
