# 👤 2.1 계정 권한 정의

| 권한 | 설명 |
| --- | --- |
| `USER` | 자신의 계정 정보를 조회·수정하고 계정 탈퇴를 수행할 수 있다. 이메일 인증을 통해 자신의 비활성 계정을 재활성화할 수 있다. |
| `ADMIN` | 자신의 계정에 대한 `USER` 권한을 가지며, 다른 계정 조회와 계정 잠금·잠금 해제·비활성화 등의 상태 관리 기능을 수행할 수 있다. |

## 권한 규칙

* 일반 회원가입으로 생성되는 계정에는 `USER` 권한을 부여한다.
* 회원가입 요청에서 계정 권한을 직접 입력받지 않는다.
* `ADMIN` 권한은 별도의 관리자 권한 부여 절차를 통해서만 부여한다.
* `USER`는 자신의 계정을 직접 잠그거나 잠금 해제할 수 없다.
* `USER`는 자신의 계정을 직접 비활성화할 수 없다.
* `USER`는 이메일 인증을 통해 자신의 `INACTIVE` 계정을 재활성화할 수 있다.
* `ADMIN`이라도 다른 사용자의 이름이나 비밀번호를 직접 변경할 수 없다.
* 계정 잠금·잠금 해제·비활성화는 `ADMIN` 또는 시스템만 수행할 수 있다.
* 시스템에 의한 자동 잠금 및 비활성화 처리는 계정 권한과 별개로 수행할 수 있다.

# 📝 2.2 관리자 계정 정보 조회

## 기능 목적

> 관리자가 지정한 계정의 정보를 조회한다.

## 사용자 및 권한

* `ADMIN`

## 사전 조건

* 요청 관리자의 인증 정보가 유효해야 한다.
* 대상 계정이 존재해야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 계정 식별 정보 | UUID | O | 조회할 대상 계정의 외부 식별자 |

## 처리 절차

1. 요청 사용자의 인증 정보와 `ADMIN` 권한을 확인한다.
2. 전달받은 UUID로 대상 계정을 조회한다.
3. 조회된 계정 정보를 반환한다.

## 업무 규칙

* DB 내부 식별자인 `id`는 외부에 노출하지 않는다.
* 비밀번호와 비밀번호 해시값은 반환하지 않는다.
* `WITHDRAWN` 계정의 이름, 이메일, 비밀번호는 제거된 상태로 조회된다.
* 관리자의 계정 조회 내역을 감사 로그로 기록할 수 있다.

## 처리 결과

* 다음 계정 정보가 반환된다.
  * UUID
  * 이름
  * 이메일
  * 권한
  * 계정 상태
  * 생성 일시
  * 수정 일시
  * 탈퇴 일시

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 인증 정보가 유효하지 않은 경우 | 인증 오류를 반환한다. |
| 관리자 권한이 없는 경우 | 접근 권한 오류를 반환한다. |
| 대상 계정이 존재하지 않는 경우 | 계정 조회 오류를 반환한다. |

# 📝 2.3 계정 잠금

## 기능 목적

> 대상 계정의 로그인을 차단하기 위해 계정 상태를 `LOCKED`로 변경한다.

## 사용자 및 권한

* `ADMIN`
* 시스템

## 사전 조건

* 대상 계정이 존재해야 한다.
* 대상 계정이 `ACTIVE` 상태여야 한다.
* 요청 주체가 계정 상태 변경 권한을 가져야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 계정 식별 정보 | UUID | O | 잠금 대상 계정 식별자 |

## 처리 절차

1. 요청 주체의 권한을 확인한다.
2. 대상 계정을 조회한다.
3. 대상 계정이 `ACTIVE` 상태인지 확인한다.
4. 계정 상태를 `LOCKED`로 변경한다.
5. `updatedAt`을 갱신한다.
6. 상태 변경 주체, 변경 전후 상태 및 변경 사유를 기록한다.

## 업무 규칙

* `ACTIVE` 계정만 잠글 수 있다.
* `USER`는 자신의 계정을 직접 잠글 수 없다.
* `INACTIVE` 또는 `WITHDRAWN` 계정은 잠글 수 없다.
* 계정 잠금은 계정 권한을 변경하지 않는다.
* `LOCKED` 계정은 로그인할 수 없다.
* 관리자 또는 시스템에 의한 상태 변경 이력을 기록해야 한다.
* 관리자가 자신의 계정을 잠그는 행위의 허용 여부는 별도 운영 정책을 따른다.

## 처리 결과

* 계정 상태가 `LOCKED`로 변경된다.
* `updatedAt`과 상태 변경 이력이 기록된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 계정이 존재하지 않는 경우 | 계정 조회 오류를 반환한다. |
| 상태 변경 권한이 없는 경우 | 접근 권한 오류를 반환한다. |
| 대상 계정이 `ACTIVE` 상태가 아닌 경우 | 상태 변경을 거부한다. |
| 상태 변경 저장 중 오류가 발생한 경우 | 변경 내용을 롤백하고 오류를 반환한다. |

# 📝 2.6 관리자 계정 재활성화

## 기능 목적

> 관리자가 운영 정책에 따라 비활성 계정을 다시 활성화한다.

## 사용자 및 권한

* `ADMIN`

## 사전 조건

* 대상 계정이 존재해야 한다.
* 대상 계정이 `INACTIVE` 상태여야 한다.
* 관리자 재활성화 정책을 충족해야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |

3. 대상 계정이 `INACTIVE` 상태인지 확인한다.

5. 계정 상태를 `ACTIVE`로 변경한다.

* `LOCKED` 계정은 재활성화 기능으로 잠금을 해제할 수 없다.
* `WITHDRAWN` 계정은 재활성화할 수 없다.
* 관리자 재활성화 작업 이력을 반드시 기록한다.
* 계정 소유자의 이메일 인증을 통한 재활성화는 `회원관리.md`를 따른다.

## 처리 결과

* 계정 상태가 `ACTIVE`로 변경된다.
* `updatedAt`과 상태 변경 이력이 기록된다.

# 📌 2.7 계정 상태 전이

| 현재 상태 | 변경 상태 | 수행 주체 | 조건 |
| --- | --- | --- | --- |
| `ACTIVE` | `LOCKED` | `ADMIN`, 시스템 | 계정 잠금 |
| `LOCKED` | `ACTIVE` | `ADMIN`, 시스템 | 계정 잠금 해제 |
| `ACTIVE` | `INACTIVE` | `ADMIN`, 시스템 | 비활성화 또는 휴면 처리 |
| `INACTIVE` | `ACTIVE` | 계정 소유자 | 이메일 인증 완료 |
| `INACTIVE` | `ACTIVE` | `ADMIN` | 관리자 재활성화 정책 충족 |
| `ACTIVE` | `WITHDRAWN` | 계정 소유자 | 본인 확인 후 계정 탈퇴 |
| `LOCKED` | `WITHDRAWN` | 계정 소유자 | 별도 본인 확인 후 계정 탈퇴 |
| `INACTIVE` | `WITHDRAWN` | 계정 소유자 | 별도 본인 확인 후 계정 탈퇴 |

## 상태별 의미

| 상태 | 설명 |
| --- | --- |
| `ACTIVE` | 로그인과 일반 계정 기능을 사용할 수 있는 정상 상태 |
| `LOCKED` | 관리자 또는 시스템에 의해 로그인이 차단된 상태 |
| `INACTIVE` | 장기 미사용 등의 사유로 로그인이 제한된 비활성 상태 |
| `WITHDRAWN` | 개인정보가 제거되었으며 복구할 수 없는 최종 상태 |

## 상태 전이 규칙

* `USER`는 자신의 계정을 `LOCKED` 또는 `INACTIVE` 상태로 직접 변경할 수 없다.
* `USER`는 자신의 `LOCKED` 상태를 직접 해제할 수 없다.
* 계정 잠금·잠금 해제·비활성화는 `ADMIN` 또는 시스템만 수행한다.
* 계정 소유자는 이메일 인증을 통해 자신의 `INACTIVE` 계정을 `ACTIVE`로 재활성화할 수 있다.
* `ACTIVE`, `LOCKED`, `INACTIVE` 계정은 본인 확인 후 탈퇴할 수 있다.
* 탈퇴를 위해 `LOCKED` 또는 `INACTIVE` 계정을 먼저 `ACTIVE`로 변경할 필요는 없다.
* `WITHDRAWN` 상태에서는 다른 상태로 전이할 수 없다.
* 표에 정의되지 않은 상태 전이는 허용하지 않는다.
