# 👤 1.2.1 회원 권한 정의

| 권한 | 허용 범위 |
| --- | --- |
| `USER` | 자신의 계정 조회·수정·탈퇴, 본인 인증을 통한 계정 복구 |
| `ADMIN` | `USER` 권한의 기능과 다른 계정 조회, 잠금·잠금 해제·비활성화·재활성화 |

## 업무 규칙

- 일반 회원가입은 `USER`만 부여한다.
- `ADMIN`은 별도 관리자 권한 부여 절차로만 부여한다.
- `USER`는 자신의 계정을 직접 잠그거나 비활성화할 수 없다.
- `ADMIN`도 다른 회원의 이름, 이메일, 비밀번호를 직접 변경할 수 없다.
- 시스템은 보안·휴면 정책에 따라 계정 상태를 자동 변경할 수 있다.

# 📌 1.2.2 계정 상태 정의

| 상태 | 의미 | 로그인 |
| --- | --- | :---: |
| `ACTIVE` | 정상 사용 가능 | 가능 |
| `LOCKED` | 보안 또는 운영 사유로 잠김 | 불가 |
| `INACTIVE` | 장기 미사용 등으로 비활성화됨 | 불가 |
| `WITHDRAWN` | 개인정보가 제거된 최종 상태 | 불가 |

## 상태 전이

| 현재 | 변경 | 수행 주체 | 조건 |
| --- | --- | --- | --- |
| `ACTIVE` | `LOCKED` | `ADMIN`, 시스템 | 잠금 사유 발생 |
| `LOCKED` | `ACTIVE` | `ADMIN`, 시스템 | 잠금 해제 조건 충족 |
| `ACTIVE` | `INACTIVE` | `ADMIN`, 시스템 | 비활성화 또는 휴면 조건 충족 |
| `INACTIVE` | `ACTIVE` | 계정 소유자 | 이메일 인증 완료 |
| `INACTIVE` | `ACTIVE` | `ADMIN` | 관리자 재활성화 정책 충족 |
| `ACTIVE`, `LOCKED`, `INACTIVE` | `WITHDRAWN` | 계정 소유자 | 본인 확인 완료 |

- 표에 없는 전이는 허용하지 않는다.
- `WITHDRAWN`은 다른 상태로 변경할 수 없다.
- 비밀번호 재설정은 계정 상태를 바꾸지 않는다.
- `LOCKED` 계정은 비밀번호 재설정이나 비활성 계정 재활성화로 잠금을 해제할 수 없다.

# 📝 1.2.3 관리자 계정 조회

## 기능 목적

> 관리자가 지정한 계정의 정보를 조회한다.

## 사용자 및 권한

- 사용자: 인증된 `ADMIN`

## 사전 조건

- 인증 정보와 관리자 권한이 유효해야 한다.
- 대상 계정이 존재해야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| 계정 식별 정보 | UUID | O | 대상 계정의 외부 식별자 |

## 처리 절차

1. 관리자 인증과 권한을 확인한다.
2. UUID로 대상 계정을 조회한다.
3. 허용된 계정 정보를 반환한다.

## 업무 규칙

- DB 내부 `id`와 비밀번호 정보는 반환하지 않는다.
- `WITHDRAWN` 계정의 제거된 개인정보는 반환하지 않는다.
- 조회 이력은 감사 로그 정책에 따라 기록한다.

## 처리 결과

- [ ] UUID, 이름, 이메일, 권한, 상태, 생성·수정·탈퇴 일시를 반환한다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 인증 실패 | 인증 오류를 반환한다. |
| 관리자 권한 없음 | 권한 없음을 반환한다. |
| 대상 계정 없음 | 계정 조회 오류를 반환한다. |

# 📝 1.2.4 관리자 계정 상태 변경

## 기능 목적

> 관리자가 계정을 잠금·잠금 해제·비활성화·재활성화한다.

## 사용자 및 권한

인증된 `ADMIN` 또는 허용된 시스템 작업

## 사전 조건

- 대상 계정이 존재해야 한다.
- 요청 주체가 상태 변경 권한을 가져야 한다.
- 현재 상태에서 요청한 상태로 전이할 수 있어야 한다.

## 입력값

| 항목 | 형식 | 필수 여부 | 설명 |
| --- | --- | :---: | --- |
| `accountUuid` | UUID | O | 대상 계정의 외부 식별자 |
| `action` | Enum | O | `LOCK`, `UNLOCK`, `DEACTIVATE`, `REACTIVATE` |
| `reason` | String | O | 상태 변경 사유 |

## 동작 조건

| 동작 | 허용 전이 |
| --- | --- |
| `LOCK` | `ACTIVE` → `LOCKED` |
| `UNLOCK` | `LOCKED` → `ACTIVE` |
| `DEACTIVATE` | `ACTIVE` → `INACTIVE` |
| `REACTIVATE` | `INACTIVE` → `ACTIVE` |

## 처리 절차

1. 요청 주체의 인증과 권한을 확인한다.
2. 대상 계정과 현재 상태를 조회한다.
3. 요청한 상태 전이가 허용되는지 확인한다.
4. 상태와 수정 일시를 변경한다.
5. 요청 주체, 변경 전·후 상태, 사유, 처리 일시를 감사 이력에 기록한다.

## 업무 규칙

- 상태 변경은 계정 권한을 변경하지 않는다.
- 관리자가 자기 계정을 변경할 수 있는지는 별도 운영 정책을 따른다.

## 처리 결과

- [ ] 요청한 계정 상태로 변경된다.
- [ ] 수정 일시와 감사 이력이 기록된다.

## 예외 처리

| 예외 조건 | 처리 |
| --- | --- |
| 대상 계정 없음 | 계정 조회 오류를 반환한다. |
| 상태 변경 권한 없음 | 권한 없음을 반환한다. |
| 허용되지 않은 상태 전이 | 상태 변경을 거부한다. |
| 저장 또는 이력 기록 실패 | 상태 변경을 롤백한다. |
